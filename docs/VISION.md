# Lectern 의 방향

Lectern 은 Markdown 파일을 중심으로 사람과 AI가 함께 리서치하는 로컬 통합 작업 환경(Integrated Research Work Environment)을 지향한다.

- 정한 날: 2026-11-05
- 장기 지향점: 마름모형 리서치 방법을 구조화한다. **지금 구현하지 않는다.**
- 지금의 중심: Claude Code·Claude 가 프로젝트 폴더에 만든 문서와 자료를 사람이 읽고, 살피고, 그 자리에서 고치는 것.
- 근거 문서: 사용자가 쓴 'AI 활용 리서치의 검증 체계' (2026-11-02). 원자재 시장동향 분석과 장단기 예측을 사례로 삼았다. 그 문서의 8단계 그림이 위아래로 좁고 가운데가 넓어 마름모 모양이다.

## 마름모형 리서치 방법

좁게 정의하고, 넓게 쌓고, 정확하게 깎는다. 핵심 주장은 AI 리서치의 품질이 모델 성능보다 "무엇을 어떻게 검증하는가"의 설계에서 결정된다는 것이다.

```text
              [  1 주제선정  ]                 사람 주도
           [     2 핵심질문     ]              문제 정의·평가 기준을 사람이 확정
        [         3 기획         ]             AI 는 질문 후보 확장·변수 점검 보조
     [            4 조사            ]          넓고 빠르게 (쌓기)
  [               5 분석               ]       경량·로컬 모델로 수집·요약·태깅, 계산은 코드로
     [            6 합성            ]          정확하게 (깎기)
        [         7 종합         ]             고성능 모델로 합성·작성
           [  8 최종결과물  ]                  사람 검토를 이 구간에 집중
```

| 단계 | 구간 | 우선하는 것 | 검증 질문 | 검증 수단 |
|---|---|---|---|---|
| 1~3 주제선정·핵심질문·기획 | 사람 주도 | 문제 정의 | 평가 기준을 착수 전에 정했는가 | 정량 목표, 정성 루브릭, 골든셋 |
| 4 조사 | 쌓기 | 범위와 속도 | 요약이 원문과 일치하는가 | 표본 대조, 오류율 측정 |
| 5 분석 | 쌓기 | 범위와 속도 | 수치가 계산 결과인가 | 코드 재계산, 단위·기준 점검 |
| 6 합성 | 깎기 | 정확성 | 주장마다 근거가 있는가 | 주장-근거 표 |
| 7 종합 | 깎기 | 정확성 | 서술과 전망치가 같은 방향인가 | 정합성 점검, 반대 시나리오 |
| 8 최종결과물 | 깎기 | 정확성 | 이 방식이 실제로 더 나은가 | 재현 테스트, 회고 기록 |

방법을 받치는 규칙:

- 평가 기준을 프롬프트보다 먼저 정한다.
- 수치는 AI 의 문장이 아니라 코드 실행 결과여야 한다.
- 사실, 해석, 가정을 구분해 표기한다.
- AI 는 가설에 동조하기 쉬우므로 반증과 반대 시나리오를 별도 작업으로 시킨다.
- 전망이 빗나간 원인을 유형별로 기록하고, 반복되는 오류를 AI 작업 지침으로 올린다. 보고서가 쌓일수록 방법이 나아지는 순환이다.
- 사람 검토는 결론에 영향이 큰 깎기 구간에 모은다.

## 지금 Lectern 과의 관계

이 표는 구현 계획이 아니라 현재 위치를 적은 것이다.

| 단계 | 이미 있는 것 | 비어 있는 것 |
|---|---|---|
| 1~3 | 새 문서, 터미널의 Claude Code | 평가 기준을 먼저 적는 틀 (템플릿은 미룸) |
| 4 조사 | '자료' 목록, 전체 검색, 모아 보기, 담기, CSV·엑셀 보기 | 요약과 원문의 표본 대조 |
| 5 분석 | 자료 요약 줄, 계산 열, 빠른 차트 | 본문의 숫자와 자료의 대조 |
| 6 합성 | 담기·보내기, 한 줄 편집, 줄 구조 편집 | 주장-근거 표 |
| 7 종합 | 하이라이트를 Claude 로 보내기 | 서술과 전망의 방향 대조, 반대 시나리오 작업 (문서 점검·책갈피는 미룸) |
| 8 최종결과물 | 발표, 인쇄, 바뀐 곳 강조 | 회고 기록, 재현 테스트 |

## 판단 기준

- 새 기능을 고를 때 어느 단계·구간을 돕는지 적는다. 어디에도 닿지 않으면 다시 생각한다.
- Markdown 파일이 원본이다. 리서치의 결과와 기록은 프로젝트 폴더의 파일로 남아 Claude Code 가 그대로 읽을 수 있어야 한다.
- AI 는 터미널의 Claude Code 로 연결한다. 앱이 스스로 외부에 요청하지 않는 원칙은 그대로다.
- Lectern 은 구조·연결·검증 근거를 보여 준다. 판단은 사람이, 계산은 코드가, 초안은 AI 가 한다.
- 단계를 강제하지 않는다. 방법은 길잡이이고, 사용자가 건너뛰어도 앱은 동작한다.

## 아직 정하지 않은 것

- 리서치의 진행 상태(단계, 평가 기준, 회고)를 어디에 둘지. 프로젝트 폴더의 md 가 먼저 후보다.
- 단계·구간을 화면에 어떻게 보일지.
- 모델을 구간별로 나눠 쓰는 일을 Lectern 이 도울지. 지금은 터미널의 도구에 맡긴다.
