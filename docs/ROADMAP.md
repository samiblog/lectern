### 정할 것
1. **어떤 html을 '문서'로 볼지.** 프로젝트에는 앱 소스(`web/index.html` 같은)와 Claude가 만든 보고서 html이 섞여 있다. 후보: 설정한 폴더(`docs/`, `reports/` 등)만 / `<meta name="generator">` 등 표식이 있는 것만 / 전부 보이되 개요에서 구분.
2. **스크립트와 외부 리소스.** Claude가 만든 html 보고서는 Chart.js 같은 라이브러리를 CDN에서 불러오는 경우가 많다. 로컬 전용 원칙(외부 요청 금지)과 부딪친다. 후보: (a) 스크립트 끄고 정적 내용만 / (b) 스크립트는 허용하되 CSP로 외부 요청 차단(그러면 CDN 차트는 안 그려짐) / (c) 문서마다 사용자가 '외부 리소스 허용'을 고름.
3. **스타일.** html은 자기 스타일 그대로 보여 줄지(권장), Lectern 테마를 입힐지.

### 구현 메모
- 렌더링: `<iframe sandbox>` 로 격리하고 `allow-same-origin` 은 주지 않는다 (문서 스크립트가 `/api/*` 를 부르지 못하게). `/doc/*.html` 응답에 CSP 헤더로 2번 결정을 적용한다.
- 스캔·개요: `scanner.MD_EXT`·`is_md()` 를 형식 표(`DOC_TYPES = {'.md': 'markdown', '.html': 'html', ...}`)와 `doc_kind()` 로 바꾼다. JS의 `isMd()` 도 같이. `/doc/` 경로와 API 이름은 이미 형식 중립이다.
- 제목·요약(`docinfo.py`): `<title>` → 첫 `<h1>`, 요약은 `<meta name="description">` → 첫 `<p>`. 표준 라이브러리 `html.parser` 로 충분하다.
- 목차·찾기: cross-origin iframe 안은 읽을 수 없다. 목차는 서버가 제목을 뽑아 주고, 찾기는 iframe에 넣은 작은 스크립트와 `postMessage` 로 하거나 html에서는 끈다.
- 문서 안 링크: iframe 안에서 다른 문서 링크를 누르면 뷰어가 이동하도록 `postMessage` 로 알린다. `allow-top-navigation` 은 주지 않는다.
- 자동 새로고침: iframe을 다시 불러오고, 같은 출처가 아니므로 스크롤 위치는 `postMessage` 로 주고받는다.
- `doc.js` 는 md 렌더러로 두고, `htmldoc.js` 를 따로 만든다. `nav.js` 가 `S.fileMap` 의 형식을 보고 고른다.
