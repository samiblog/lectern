# 설계 결정 기록

결정마다 무엇을 골랐고 왜 그랬는지 남긴다. 결정을 바꿀 때는 항목을 지우지 말고 "변경" 줄을 덧붙인다.
새 결정은 맨 아래에 번호를 이어서 쓴다.

---

## D1. 용도: Claude가 만든 프로젝트 문서를 보기만 한다

- **결정**: 편집 기능, DRM·클라우드 드라이브(OneDrive 등) 대응, cp949 인코딩 대응을 넣지 않는다. 프로젝트 폴더와 그 하위만 본다.
- **이유**: 사용자는 Claude Code / Claude가 쓴 리서치·계획·설계 문서를 일목요연하게 읽으려고 한다. Claude가 쓰는 파일은 UTF-8이고 로컬 프로젝트 폴더에 있다.
- **영향**: 요구가 바뀌지 않는 한 위 기능은 다시 넣지 않는다.
- **변경 (v0.10.0, D38)**: 오른쪽 터미널을 넣는다. Lectern 자신은 여전히 파일을 만들거나 고치지 않고 아무것도 실행하지 않는다 — 터미널에서 사용자가 친 명령이 하는 일은 사용자가 한 것이다.

## D2. Python + pywebview(WebView2) + 순수 JS

- **결정**: 창은 pywebview, 렌더링은 웹 기술. C#/WebView2, Tauri, Electron은 쓰지 않는다.
- **이유**: 사용자가 Python·JS에 익숙하고 사내망에서 Rust·.NET 개발 환경을 갖추기 어렵다. Electron은 무겁다. pywebview는 Windows에서 Edge WebView2(Chromium)를 써서 최신 CSS·JS 기능을 그대로 쓸 수 있다.
- **대가**: 배포본이 수십 MB(PyInstaller). 실행 파일 첫 기동이 Python 앱보다 약간 느리다.

## D3. 자체 HTTP 서버(werkzeug)를 띄우고 창에 URL을 넘긴다

- **결정**: `create_window(url=<WSGI 앱>)` 대신 `werkzeug.serving.make_server('127.0.0.1', port, app, threaded=True)` 를 스레드로 돌리고 `http://127.0.0.1:<포트>/` 를 창에 연다.
- **이유**: 창 모드와 브라우저 개발 모드(`--browser`)가 완전히 같은 서버를 쓴다. 바인딩 주소·스레딩·포트를 직접 통제한다.
- **처음 제안과 다름**: 초기 구상은 pywebview에 Flask 앱을 직접 넘기는 방식이었다.

## D4. 네이티브 기능만 js_api, 나머지는 HTTP API

- **결정**: `js_api` 에는 폴더 선택 대화상자와 창 제목만 둔다.
- **이유**: 브라우저 모드에서 UI 전체를 확인·자동 테스트(playwright)할 수 있다. 문서 상대경로(`./img/a.png`)를 브라우저의 URL 해석에 그대로 맡길 수 있다.

## D5. Markdown은 프런트엔드(markdown-it)에서 렌더링

- **결정**: 서버는 원문만 주고, 변환·후처리는 JS가 한다.
- **이유**: 테마 전환·다시 그리기가 즉시 되고, Mermaid·KaTeX·highlight.js 같은 웹 라이브러리를 그대로 쓴다. 서버는 파일 전달과 경로 검사만 맡아 단순해진다.

## D6. 외부 라이브러리는 web/vendor 에 번들, 빌드 단계 없음

- **결정**: npm 패키지에서 배포용 파일만 복사해 저장소에 넣는다 (`tools/update_vendor.py`). 번들러·트랜스파일러 없이 ES modules로 쓴다.
- **이유**: 사내망 PC에서 npm이 필요 없다. 실행 중 외부 요청이 없다. 빌드 도구가 없어 Claude Code가 고치고 바로 확인하기 쉽다.
- **버전**: `web/vendor/VERSIONS.json`. 올릴 때는 `tools/ui_smoke.py` 를 다시 돌린다.

## D7. 레이아웃은 왼쪽 트리 하나

- **결정**: 처음 구상한 3종(왼쪽 트리 / 상단+왼쪽 / 탭)과 자동 추천을 버리고 접을 수 있는 왼쪽 트리 하나로 간다. 열린 문서 탭 대신 뒤로/앞으로 기록.
- **이유**: Claude 프로젝트 폴더는 트리 하나로 충분하다. 레이아웃 3종은 만드는 비용에 비해 '보기'에 기여가 작다. 대신 폴더 개요 화면과 최근 변경으로 한눈에 보기를 해결한다.
- **변경 (v0.7.0, 사용자 요청)**: 프로젝트(폴더) 탭을 더했다 (D34). 탭은 볼 폴더를 바꾸는 것이고, 사이드바는 여전히 왼쪽 트리 하나다. 열린 문서 탭은 여전히 하지 않는다.

## D8. 폴더 개요 화면이 첫 화면

- **결정**: 폴더를 누르거나 프로젝트를 열면 개요(최근 변경 레일, 하위 폴더, 문서별 제목·요약·수정 시각)를 보여 준다.
- **이유**: 문서를 하나씩 열지 않고 무엇이 있는지, 무엇이 방금 바뀌었는지 파악하는 것이 이 도구의 핵심 가치다.
- **보류**: 마지막에 본 문서로 시작하는 옵션은 ROADMAP에 있다.
- **변경 (v0.3.0)**: 설정 `restore_last`(기본 켜짐 — 사용자가 고름)면 폴더를 열 때 마지막에 보던 문서·스크롤 위치로 시작한다. 그 문서가 없어졌거나 설정을 끄면 개요 (ROADMAP 2-4).

## D9. 변경 반영은 1초 폴링 (`/api/changes?since=seq`)

- **결정**: 서버는 watchdog 이벤트를 순번 붙여 기록하고, 프런트가 1초마다 새 기록만 가져간다.
- **이유**: `window.state` 푸시(pywebview)는 브라우저 모드에서 동작하지 않는다. SSE는 서버 스레드를 오래 잡는다. 로컬 1초 폴링은 비용이 거의 없고 두 모드에서 똑같이 동작한다. 창이 가려지면(`document.hidden`) 쉰다.
- **대체**: watchdog가 없으면 서버가 2초 간격 스캔 비교로 같은 기록을 만든다.

## D10. 자동 새로고침 때 화면 밖에서 먼저 그린다

- **결정**: 문서를 `.lec-stage`(화면 밖, visibility:hidden)에 그린 뒤 한 번에 바꿔 끼우고 스크롤을 복원한다.
- **이유**: Claude가 문서를 쓰는 동안 여러 번 다시 그려도 깜박임·스크롤 튐이 없어야 한다. Mermaid는 DOM에 붙어 있어야 크기를 잴 수 있어 분리된 노드에서는 그릴 수 없다.

## D11. 코드 파일 링크는 실행하지 않는다

- **결정**: 이미지·PDF·오피스 등 안전한 형식만 기본 앱으로 열고, 코드·스크립트·그 밖의 파일은 편집기(`code -g 파일:줄`)로, 편집기가 없으면 탐색기에서 선택만 한다.
- **이유**: Windows에서 `.py`·`.js`·`.bat`·`.ps1` 의 기본 동작은 실행이다. 문서 링크를 누르다가 스크립트가 실행되면 안 된다. 뷰어 안에 코드 보기 화면은 만들지 않는다 (D7과 같은 이유).
- `code.cmd` 는 배치 파일이라 `&` 같은 문자가 명령으로 해석될 수 있어, 그런 문자가 든 경로는 탐색기로 보낸다.
- **변경 (v0.15.0, 사용자 요청 2026-10-23)**: 뷰어 안에 코드 읽기 화면을 넣었다 (D43). 여전히 실행하지 않는다 — 글자로만 보이고, 편집기로 여는 길(두 번 누르기·우클릭·화면 위 버튼)은 그대로다.

## D12. 수식의 `$` 는 pandoc 규칙

- **결정**: 여는 `$` 뒤와 닫는 `$` 앞에 공백이 없어야 하고, 닫는 `$` 바로 뒤가 숫자가 아니어야 하며, 첫 번째 닫는 후보만 본다.
- **이유**: 원자재 리서치 문서에는 `$105/t`, `$95~$110` 같은 달러 표기가 많다. 일반적인 `$…$` 규칙은 이것을 수식으로 망가뜨린다.
- **보완**: 전체 끄기는 설정 `math: false`.
- **`\[…\]` 도 (2026-10-18)**: 마크다운에서 `\[` 는 대괄호를 글자로 쓰는 표기다. Claude 가 옮긴 문서의 `\[판독 불확실\]`·`\[원문 그대로\]` 31곳이 수식 글꼴로 가운데 놓였다. 그래서 `\[…\]` 는 줄을 통째로 차지할 때만(앞뒤에 같은 줄의 글이 없을 때) 수식으로 본다 — markdown-it-texmath 의 `\[` 규칙과 같다. 줄을 통째로 차지하는 `\[참고\]` 도 있을 수 있어, `\(…\)`·`\[…\]` 안에 한글·한자가 있는데 TeX 명령(`\frac` 등)이 없으면 수식이 아니다. `\text{매출}` 처럼 명령이 있으면 수식.

## D13. Ctrl+F 찾기는 직접 구현 (CSS Custom Highlight API)

- **결정**: `find.js` 가 텍스트 노드를 훑어 Range를 만들고 `CSS.highlights` 로 표시한다.
- **이유**: pywebview는 디버그가 아닐 때 `AreBrowserAcceleratorKeysEnabled=False` 로 WebView2의 기본 찾기를 끈다 (pywebview 6.2 `edgechromium.py` 확인). Highlight API는 DOM을 바꾸지 않아 다시 그리기와 충돌하지 않는다.
- **한계**: 여러 텍스트 노드에 걸친 검색어(예: 굵은 글씨 경계)는 찾지 못한다.

- **변경 (v0.3.0)**: 텍스트 노드마다 따로 찾던 것을, 같은 블록(문단·칸·제목 등) 안의 글자를 이어 붙여 찾도록 바꿨다. `**굵게**텍스트`·`` `코드` `` 처럼 서식이 섞인 글자도 찾는다. 블록 사이에는 줄바꿈을 넣어 문단을 넘어 찾지 않는다. html 문서(iframe)도 같은 방법이다.

## D14. CSP를 걸지 않는다

- **결정**: `index.html` 에 Content-Security-Policy를 두지 않는다.
- **이유**: pywebview가 js_api 결과를 돌려줄 때 `eval` 계열을 쓸 수 있어 `unsafe-eval` 없는 CSP와 충돌할 위험이 있다. 대신 DOMPurify 정화, 로컬 바인딩, 토큰, Host 검사로 막는다.
- **재검토 조건**: 창 모드에서 CSP를 걸고 js_api·Mermaid가 모두 동작하는지 확인되면 추가한다.
- **변경 (v0.1.3)**: 스크립트·스타일 지시어를 뺀 CSP는 eval 문제와 부딪치지 않으므로 건다. 이미지·연결·글꼴 출처만 제한한다 (D20). `script-src` 는 여전히 두지 않는다.
- **변경 (v0.10.0, D38)**: 셸을 다루는 터미널 API 가 생겨, 문서에 끼어든 스크립트가 앱 출처에서 돌 때의 피해가 커졌다. `script-src 'self' 'unsafe-eval'` 을 둔다 — 앱 자신의 파일만 돌고 인라인 스크립트·이벤트 속성은 브라우저가 막는다. pywebview 가 넣는 스크립트(토큰·js_api)는 호스트가 `ExecuteScript` 로 넣어 페이지 CSP 를 받지 않고, js_api 결과를 돌려줄 때 eval 을 쓸 수 있어 `'unsafe-eval'` 은 남긴다. `ui_smoke` 전체(수식·Mermaid 포함)가 그대로 통과하고, 창 모드에서 js_api·토큰이 동작하며 CSP 위반 기록이 없다.

## D15. DOMPurify `SANITIZE_DOM: false`

- **결정**: DOM clobbering 보호를 끈다.
- **이유**: 기본값이면 `id="title"`, `id="images"` 처럼 `document` 속성과 이름이 같은 제목 앵커가 지워져 목차·앵커 링크가 깨진다. 문서는 사용자 자신의 로컬 파일이고, 앱 코드는 문서 영역 밖에서 `document.<이름>` 전역 참조를 쓰지 않으며 앱 id는 `lec-` 접두사를 쓴다.
- **재검토 필요 (v0.1.3 검토)**: 위 이유의 일부가 사실과 다르다. 앱은 `document.querySelector`·`createElement`·`body`·`title` 을 쓰고, 문서 속 `<img name="querySelector">` 가 이것을 가린다 (화면이 멈춤). 제목 id(`<h2 id="title">`)는 `document` 속성을 가리지 않으므로, `SANITIZE_DOM` 을 끈 채 `img` 의 `name` 만 지우는 방안을 검토한다. ROADMAP '알려진 문제' 참고.
- **변경 (v0.1.3)**: 위 방안대로 한다. `SANITIZE_DOM: false` 는 그대로 두고, 정화 훅이 `img` 의 `name` 을 지운다. `document` 의 이름을 가릴 수 있는 요소 가운데 DOMPurify가 허용하는 것은 `img` 뿐이다 (`form` 은 금지, `embed`·`object`·`iframe` 은 DOMPurify가 막음). `window.<id>` 는 진짜 전역을 가리지 못하므로, 늦게 불러오는 전역(mermaid)만 조심한다 (CLAUDE.md 함정).

- **변경 (v0.3.0)**: `ALLOWED_URI_REGEXP` 에 `file:` 과 드라이브 경로(`c:/`, `c:%5C`)를 더했다. 기본값은 이런 주소의 `href`·`src` 를 지워 프로젝트 안 절대경로 그림·링크(ROADMAP 2-2)를 쓸 수 없었다. 이런 주소는 모두 `resolveRef` 가 프로젝트 안이면 상대경로로 바꾸고 밖이면 막는다.

## D16. 제목 앵커는 GitHub 규칙

- **결정**: slug = 소문자, 글자·숫자·`_`·공백·`-` 외 제거, 공백 → `-`. 한글은 유지.
- **이유**: Claude가 문서에 쓰는 목차 링크(`[개요](#1-개요)`)가 GitHub 규칙을 따른다.

## D17. 로컬 서버는 Host 헤더를 검사한다

- **결정**: `Host` 가 `127.0.0.1`·`localhost` 가 아닌 요청은 403.
- **이유**: 토큰이 없는 `/doc/*` 를 DNS 리바인딩으로 읽어 가는 것을 막는다.

## D18. 이름은 Lectern (렉턴)

- **결정**: 프로젝트·실행 파일·패키지 이름을 'MD Viewer'에서 **Lectern** 으로 바꾼다 (v0.1.1). 코드 이름 `lectern`, 실행 파일 `Lectern.exe`, 설정 폴더 `%APPDATA%\Lectern`, 앱 DOM 접두사 `lec-`.
- **이유**: 나중에 HTML 문서도 볼 예정이라 형식(md)이 이름에 들어가면 안 된다. 목적은 프로젝트 문서를 '기계가 아닌 사람이' 일목요연하게 보는 것이다. 독서대(lectern)는 사람이 문서를 펼쳐 놓고 읽는 받침대라 형식과 무관하게 이 목적을 담는다. 짧은 영문이라 터미널에서 `lectern .` 으로 치기 쉽다.
- **검토한 다른 이름**: 열람실(Readroom), 일람(Illam), Glance(같은 이름이 흔함). Docent(도슨트)는 뜻이 가장 잘 맞았지만 AI 에이전트 기록 분석 도구(Transluce Docent)가 이미 쓰고 있어 뺐다.
- **영향**: 새 코드·문서에 'md 전용'을 전제로 한 이름을 새로 만들지 않는다. 기존 `is_md`·`MD_EXT` 같은 이름은 HTML을 붙일 때(ROADMAP 4단계) 형식 표로 바꾼다.
- **변경 (v0.3.0~)**: 형식 표 `DOC_TYPES`·`doc_kind()` 로 바꿨고, 쓰이지 않던 `is_md`·`MD_EXT` 는 지웠다 (점검 후).

## D19. 문서 속 외부 이미지는 보여 준다 (설정으로 끌 수 있음)

- **결정**: 문서에 들어 있는 `http(s)` 이미지를 불러와 표시한다 (v0.1.2). 설정 `external_images`(기본 `true`)로 끌 수 있다. referrer를 보내지 않고, 오류·15초 초과면 원래 주소로 가는 링크로 바꾼다.
- **변경**: v0.1.1까지는 로컬 전용 원칙에 따라 외부 이미지를 링크로만 보여 주었다. 사용자가 외부 이미지를 보기를 원해서 바꿨다.
- **유지하는 것**: 앱 자체의 외부 요청 금지(CDN·웹폰트 등), 프로젝트 밖 로컬 경로 차단, `srcset`·`poster`·CSS `url()` 제거. 외부 요청이 허용되는 길은 `<img>` 하나뿐이고 `tools/ui_smoke.py` 가 이를 확인한다.
- **감수하는 것**: 이미지 주소의 서버는 그 그림을 요청한 사실(IP, 시각)을 안다. 사내망에서 막힌 주소는 링크로 바뀐다.
- **HTML(ROADMAP 4단계)과의 관계**: 이 결정은 Markdown 속 이미지에 대한 것이다. HTML 문서의 스크립트·CDN 허용 여부는 4단계에서 따로 정한다.
- **변경 (v0.1.3)**: v0.1.2에서는 `<img>` 가 아닌 길 — 표의 `background`, SVG `image`·`feImage` 의 href, SVG `fill`·`mask`·`clip-path`·`marker` 의 `url()`, style 의 `image-set()` — 로 외부 그림을 불렀고, 설정을 꺼도 막히지 않았다. 정화 훅에서 이 길을 지우고 CSP로 한 번 더 막는다 (D20). 이제 외부 요청이 나가는 길은 정말 `<img>` 하나다.

## D20. 앱 페이지에 이미지·연결 출처만 제한하는 CSP를 건다

- **결정**: `GET /` 응답에 `img-src 'self' data: blob:`(설정 `external_images` 가 켜져 있으면 `http: https:` 추가), `media-src 'self'`, `font-src 'self' data:`, `connect-src 'self'`, `object-src 'none'`, `frame-src 'none'`, `base-uri 'none'`, `form-action 'none'` 을 붙이고, `Referrer-Policy: no-referrer` 를 함께 보낸다 (`server.py` `content_security_policy`).
- **이유**: 문서 HTML은 앱과 같은 출처에서 그려진다. DOMPurify 허용 목록은 넓어서 정화 훅만으로는 그림을 부르는 길을 다 막았다고 장담하기 어렵다 (v0.1.2에서 10가지가 새었다). 브라우저가 출처를 막으면 훅이 놓친 길도 막힌다.
- **두지 않는 것**: `default-src`·`script-src`·`style-src`. pywebview가 eval 계열을 쓸 수 있고 (D14), KaTeX·Mermaid는 인라인 스타일을 쓴다.
- **변경 (v0.10.0)**: `script-src 'self' 'unsafe-eval'` 을 더한다 (D14 변경, D38). `default-src`·`style-src` 는 여전히 두지 않는다.
- **영향**: 설정 `external_images` 를 바꾸면 페이지를 다시 불러와야 CSP가 바뀐다 (설정 창을 만들 때 저장 후 다시 불러오기). ROADMAP 4단계에서 HTML 문서를 `<iframe>` 으로 보일 때는 `frame-src 'self'` 로 바꾼다.
- **`/doc/*`**: 응답에 `Content-Security-Policy: sandbox` 와 `X-Content-Type-Options: nosniff` 를 붙인다. 프로젝트 안의 html·svg 는 앱과 같은 출처로 내려가므로, 창이 그 주소로 바로 이동하는 일이 생겨도 스크립트가 앱 출처(토큰·`/api/*`)에 닿지 못하게 한다. `<img>`·`fetch` 로 쓰는 데는 영향이 없다. 4단계의 HTML 문서 iframe은 이 헤더를 그대로 두고 필요한 것만 `sandbox` 값에 더한다.

## D21. 설정 파일을 읽지 못하면 그 실행 동안 저장하지 않는다

- **결정**: `config.json` 이 있는데 읽지 못하면(JSON 문법 오류, 맨 바깥이 객체가 아님, 읽기 오류) 기본 설정으로 실행하되 저장하지 않는다. 이유와 위치(몇 행 몇 열)를 화면 알림(`/api/state` 의 `config_error`)과 stderr로 알린다. UTF-8 BOM은 오류로 보지 않는다.
- **이유**: README는 `editor`·`exclude_dirs` 를 손으로 고치라고 안내한다. Windows 경로의 역슬래시를 하나만 쓰거나(`"C:\Tools"`), 마지막 쉼표를 남기거나, 메모장·PowerShell 5.1이 BOM을 붙이면 파싱에 실패한다. v0.1.2는 이때 기본값으로 시작한 뒤 폴더를 여는 순간 파일을 덮어써서 사용자가 고친 내용이 조용히 사라졌다.
- **고르지 않은 방안**: 깨진 파일을 `config.json.broken` 으로 옮기고 새로 쓰기. 디스크에 `config.json` 외의 파일을 만들어 보기 전용 원칙(디스크에 쓰는 것은 설정 파일 하나)과 어긋난다.
- **대가**: 파일을 고칠 때까지 최근 폴더·테마·창 크기가 저장되지 않는다.
- **변경 (v0.3.0)**: 설정 창에 '설정 파일 열기'가 생기고 마지막 위치를 자주 기록하게 되어, 앱이 실행 중에 사용자가 파일을 고치는 일이 흔해졌다. 그래서 읽거나 저장하기 전에 파일이 밖에서 바뀌었는지 보고 다시 읽는다. 고친 값은 바로 반영되고 덮어써지지 않는다. 고친 파일이 깨져 있으면 그때부터 저장을 멈추고, 파일이 고쳐지면 다시 저장한다 ('그 실행 동안' → '고쳐질 때까지').

## D22. Python 의존성은 정확한 버전으로 고정한다

- **결정**: `requirements.txt`·`requirements-dev.txt` 의 직접 의존성을 `==` 로 고정한다 (v0.1.3: pywebview 6.2.1, flask 3.1.3, watchdog 6.0.0, pytest 9.1.1, pyinstaller 6.22.3, playwright 1.63.0). 두 파일 첫 줄에 `# -*- coding: utf-8 -*-` 를 둔다.
- **이유**: 사내망 PC에는 인터넷 PC에서 받은 wheel을 옮겨 설치한다. `>=` 이면 받는 날마다 다른 버전이 들어와, 확인하지 않은 판(예: pywebview 7)이 섞일 수 있다. pywebview는 판마다 API가 바뀌어 왔다 (`FileDialog`·창 크기의 DPI 처리 등).
- **coding 선언**: pip 24 이하는 요구사항 파일을 시스템 로캘로 읽는다. 한국어 Windows(cp949)에서 한글 주석이 있으면 `UnicodeDecodeError` 로 설치가 실패한다 (v0.1.2의 `requirements-dev.txt` 가 그랬다). 이 줄이 있으면 pip 24·26 모두 UTF-8로 읽는다.
- **고정하지 않는 것**: 간접 의존성(werkzeug, pythonnet 등). 직접 의존성이 허용하는 범위에서 wheel을 받는 날 정해지고, 사내 설치는 그 wheel 폴더를 그대로 쓰므로 재현된다.
- **올릴 때**: pytest, `tools/ui_smoke.py`, `build.bat`, `docs/TESTING.md` 수동 점검을 다시 하고 이 항목에 판을 적는다.

## D23. 제목을 눌러 절을 접는다 — DOM은 그대로, 상태는 메모리에만

- **결정**: 문서의 최상위 제목을 누르면 다음 같은 수준 이상의 제목 전까지 접고, 다시 누르면 편다 (v0.1.4, `fold.js`). 왼쪽 여백의 화살표와 제목 뒤 '…' 로 접힌 것을 보여 준다.
- **구현**: markdown-it 이 만든 평평한 DOM에 클래스만 붙이고 숨길 블록을 `display:none` 으로 바꾼다. 절마다 `<section>` 으로 감싸는 방법은 고르지 않았다 — `.md-body > :first-child`·`h2 + ul` 같은 CSS, 찾기의 텍스트 노드, 목차·앵커가 모두 영향을 받는다.
- **상태 저장**: 문서 경로별로 이번 실행 동안만 메모리에 둔다. 자동 새로고침 때 Claude가 문서를 고쳐도 접어 둔 절이 펴지지 않게 하려는 것이 주목적이다. `config.json` 에 쓰지 않는다 — 문서마다 쌓이는 값이고, 다음 실행에서 펼친 문서로 시작하는 편이 덜 헷갈린다.
- **접지 않는 것**: H1이 하나뿐인 문서의 H1(문서 제목. 접으면 문서 전체가 사라진다), 내용이 없는 제목, 인용·목록·HTML 블록(`<div>` 등) 안에 든 제목, 각주.
- **누름 판정**: 제목 속 링크, Shift+클릭 등으로 글자를 고른 누름은 접지 않는다. 두 번 눌러 낱말을 고르면 첫 번째 누름에서 접혔다가 바로 펴진다 (제목 글자를 복사할 수 있도록 감수한 깜박임).
- **숨은 곳으로 가기**: 목차·앵커 링크·찾기 결과가 접힌 절 안이면 감싼 절을 편다. 찾기의 건수에는 접힌 절 안의 결과도 들어간다.

## D24. 본문 우클릭 메뉴는 복사와 위치 짚기만 한다

- **결정**: 문서 본문을 우클릭하면 그 블록을 테두리로 표시하고 복사 메뉴를 띄운다 (v0.1.5, `docmenu.js`). 텍스트·Markdown 원문·절 원문·절 링크·표(탭 글 + HTML)·그림(PNG) 복사, Claude용 위치 복사. 여백은 문서 메뉴(경로 복사, 편집기·탐색기로 열기, 모두 접기·펴기).
- **이유**: Lectern은 사람이 읽고 Claude에게 다시 말하는 도구다. 읽다가 '이 부분'을 Claude Code 프롬프트로 정확히 옮기거나, 표·그림을 보고서·메일로 옮기는 일이 잦다. pywebview는 기본 우클릭 메뉴를 끄므로(디버그 모드 제외) 직접 만든다.
- **원문 줄 범위**: markdown-it 토큰의 `map` 을 렌더링 때 `data-lines` 로 달아 둔다. 렌더링한 DOM에서 원문을 거꾸로 짐작하지 않는다.
- **Claude용 위치 형식**: `@docs/a.md 40~52행` (제목은 뒤에 `('결론' 절)`). Claude Code 문서에는 CLI에서 손으로 친 `@파일#L40-52` 같은 범위 표기가 없고 (IDE 연동이 넣는 예시만 `@app.ts#5-10`·`@src/auth.ts#L1-99` 로 서로 다름), 범위를 경로의 일부로 읽으면 파일이 붙지 않을 수 있다. 그래서 파일은 `@경로` 로 통째로 붙이고 범위는 글로 적는다. 범위 표기가 문서화되면 바꾼다.
- **넣지 않는 것**: 편집·삭제, 파일로 저장(CSV·PNG 내보내기 — 디스크에 쓰는 것은 설정 파일 하나, D1), 번역·요약 같은 외부 서비스, 인터넷 그림의 그림 복사(다른 출처 그림은 브라우저가 캔버스로 읽지 못하게 막는다 — 주소 복사만).
- **2차 (v0.3.0, ROADMAP 2-8)**: 편집기에서 이 줄 열기, Mermaid 그림 복사, 수식 LaTeX 복사, 링크 주소 복사, 같은 수준 제목만 접기, 메타데이터 원문 복사.

## D25. 설치 파일은 Inno Setup, 현재 사용자 설치

- **결정**: `build.bat` 이 Inno Setup 6(`installer\lectern.iss`)으로 `dist\Lectern-버전-setup.exe` 를 만든다 (v0.2.0). 관리자 권한 없이 현재 사용자에게 설치(`%LOCALAPPDATA%\Programs\Lectern`). 시작 메뉴 바로가기, 선택 작업으로 탐색기 폴더 우클릭 'Lectern으로 열기'(기본 선택)와 바탕화면 바로가기.
- **이유**: 사용자가 정했다. 사내 PC는 관리자 권한이 없는 경우가 많다. Python이 없는 PC에서는 `tools/context_menu.py` 로 우클릭 메뉴를 등록할 수 없었는데, 설치 파일이 같은 레지스트리 키를 넣고 제거 때 지운다.
- **고르지 않은 것**: MSI(WiX) — 배포 관리 도구가 요구할 때만 의미가 있고 만들기 번거롭다. MSIX — 코드 서명이 반드시 필요하다. 모든 사용자 설치 — 관리자 권한이 필요하다.
- **설정**: 제거해도 `%APPDATA%\Lectern\config.json` 은 지우지 않는다 (다시 설치하면 최근 폴더·스타일을 이어 쓴다). 설치 파일은 설정을 만들거나 고치지 않는다.
- **WebView2**: 설치 파일에 넣지 않는다 (오프라인 설치 파일만 약 170MB). 없으면 설치 중에 알리고 설치는 계속한다.
- **감수하는 것**: 코드 서명이 없어 'Windows의 PC 보호' 경고가 뜬다. 빌드 PC에 Inno Setup이 있어야 한다 (`winget install JRSoftware.InnoSetup`). 없으면 `build.bat` 은 exe까지만 만든다.
- **함께 한 것**: 앱 아이콘(`assets/lectern.svg` → `tools/make_icon.py` → `lectern.ico`)과 exe 버전 정보.

## D26. 문서 스타일 12종, PC 글꼴만

- **결정**: 문서 보기 스타일을 3종에서 12종으로 늘린다 (v0.2.0). 웹에서 많이 쓰는 문서 보기 모양을 참고했다 — GitHub(github-markdown-css 색), 노션풍(Notion 글자색 #37352f), 종이·세피아(Pocket·Firefox 읽기 보기의 #f4ecd8/#5b4636), 논문(Tufte CSS·LaTeX.css — 미색 바탕, 가운데 제목, booktabs 표), 신문(Typora Newsprint), 고대비(Firefox 읽기 보기의 대비 모드), Nord(공식 16색), Solarized 다크, 밤 종이(전자책 밤 모드). 남의 CSS를 복사하지 않고 `base.css` 변수 체계로 새로 만들었다.
- **글꼴**: PC에 있는 글꼴만 쓴다 (사용자가 정함). 웹 글꼴은 로컬 전용 원칙(D19 외 외부 요청 금지)에 어긋나고, 글꼴을 앱에 넣으면 설치 파일이 10~20MB 커진다. 글꼴 목록 끝을 Windows 기본 글꼴로 두어 어느 PC에서나 한글이 보이게 한다 (모양은 PC마다 다를 수 있다).
- **지키는 것**: 모든 스타일에서 본문·흐린 글자·링크의 대비 4.5:1 이상(WCAG AA), 제목 색은 본문과 조금 다르게, 표 머리행은 본문 행과 구분 (v0.1.4 사용자 요청). `ui_smoke.py` 가 스타일마다 확인한다.
- **기본값**: 고른 스타일은 설정에 저장되어 다음 실행의 기본이 된다. 처음 실행은 '자동'(Windows 다크 모드면 다크, 아니면 기본).
- **변경 (v0.4.0)**: 24종으로 늘렸다 (D30).

## D27. HTML 문서는 스크립트 없는 같은 출처 iframe 으로 본다

- **결정**: `.html`·`.htm` 를 문서로 보인다 (v0.3.0). 사용자가 정한 것 — 문서를 보는 위주로 한정해 스크립트는 돌리지 않는다. 앱 소스·빌드 폴더(`src`·`public`·`static`·`templates`·`web`·`www`·`frontend`·`out`, 설정 `html_exclude_dirs` 로 더함) 안의 html 은 문서로 보지 않는다 (md 는 그대로). 인터넷에서 불러오는 것은 그림만 `external_images` 를 따르고 CSS·글꼴·스크립트는 막는다. 문서에 CSS가 있으면 그대로, 없으면 Lectern 스타일을 입힌다.
- **보이는 방법**: `<iframe sandbox="allow-same-origin allow-modals">` 에 `/doc/<경로>` 를 띄운다 (`allow-modals` 는 v0.3.0 인쇄에서 더함 — 앱이 그 문서의 `print()` 를 부른다). 서버는 html 응답에 `sandbox allow-same-origin allow-modals; default-src 'none'; img-src 'self' data: [http: https:]; style-src 'self' 'unsafe-inline'; font-src 'self' data:; media-src 'self'; base-uri 'self'; form-action 'none'` 을 붙인다. `allow-scripts` 가 없으므로 문서의 `<script>`·인라인 이벤트(`onclick`)는 돌지 않는다.
- **같은 출처를 고른 이유**: 처음 구상(ROADMAP 4단계 구현 메모)은 출처를 다르게 하고 `postMessage` 로 목차·찾기·링크를 주고받는 것이었다. 그러려면 iframe 안에서 작은 스크립트가 돌아야 한다. 스크립트를 아예 끄면 같은 출처여도 문서가 앱(`/api/*`, 토큰)에 닿을 길이 없고, 앱(부모)이 iframe 안을 직접 읽어 목차·찾기(CSS Highlight)·링크·우클릭 메뉴·바뀐 부분 강조를 md 와 같은 코드로 다룰 수 있다. 부모가 붙인 이벤트·ResizeObserver·하이라이트가 스크립트 없는 iframe 에서도 동작하는 것을 Chromium 에서 확인했다.
- **높이**: iframe 을 문서 높이에 맞추고 `#lec-content` 가 스크롤한다 — 스크롤 위치 유지·마지막 위치·목차의 현재 위치가 md 와 같게 동작한다. `100vh` 를 쓰는 문서가 끝없이 커지지 않도록 같은 만큼 계속 커지면 멈춘다.
- **앱 CSP**: `/` 의 `frame-src` 를 `'none'` 에서 `'self'` 로 바꿨다 (D20 에 적어 둔 대로). 문서가 `<meta http-equiv="refresh">` 로 iframe 을 바깥 주소로 보내려 해도 이 규칙이 막는다.
- **인쇄 (v0.3.0)**: 앱이 html 문서 자체를 인쇄하려면 iframe 의 `print()` 를 불러야 하고, 그러려면 sandbox 에 `allow-modals` 가 있어야 한다. iframe 속성과 서버 CSP 에 함께 넣었다. 스크립트가 없으므로 문서가 이 권한을 쓸 길은 없다.
- **읽을 수 있는 바탕 (v0.3.1)**: iframe 의 '다크 선호(prefers-color-scheme)'는 Lectern 스타일이 아니라 Windows 설정을 따르고, 색 모드(color-scheme)가 앱과 다르면 Chromium 이 iframe 바탕을 흰색으로 칠한다. 그래서 (1) 다크 스타일에서 스타일 없는 html 이 흰 바탕에 밝은 글자, (2) 바탕을 칠하지 않고 밝은 글자만 정한 문서(어두운 바탕을 가정한 보고서, Windows 다크 모드에서 켜지는 문서의 다크 디자인)가 흰 바탕에 밝은 글자가 되어 읽을 수 없었다 (사용자 보고). 이제 스타일 없는 문서는 쪽 바탕과 색 모드를 앱 스타일로 칠하고, 스타일 있는 문서가 쪽 바탕을 칠하지 않으면 그 위에 바로 놓인 글자의 밝기(글자 수로)를 보고 어두운/밝은 바탕을 깐다 — 앱 스타일과 밝기가 같으면 그 스타일의 바탕색. 쪽 바탕을 칠하는 문서는 건드리지 않는다. 처음에 둔 '스타일 있는 문서는 흰 바탕'은 없앴다.
- **감수하는 것**: 스크립트로 그리는 차트(Chart.js 등)·인터넷 CSS를 쓰는 보고서는 다르게 보인다. html 은 원문 줄과 화면을 이을 수 없어 원문 복사·Claude용 위치·전체 검색 결과의 줄 이동이 없다 (검색어 첫 결과로 간다). 제목 접기도 없다.

## D28. 앱 UI 색은 문서 스타일에서 만든다

- **결정**: 툴바·사이드바·목차·상태줄·메뉴·설정 창의 색(`--ui-*`)을 고정된 밝음/어두움 두 벌 대신 지금 문서 스타일의 `--md-*`(바탕, 글자, 흐린 글자, 테두리, 링크, 제목)에서 `color-mix()` 로 만든다 (v0.3.1, `app.css`). 사용자가 '문서 스타일과 애플리케이션 스타일을 같게' 요청했다.
- **이유**: 스타일 12종마다 UI 색을 따로 정하는 대신 한 규칙으로 맞추면 새 스타일도 `--md-*` 만 정하면 UI 가 따라온다. 종이 스타일은 세피아 사이드바, Nord 는 Nord 사이드바가 된다.
- **규칙**: 툴바·사이드바 = 본문 바탕에 글자색 5%(어두운 스타일은 검정 16%로 본문보다 조금 어둡게), 팝업 = 본문 바탕, 고른 행 = 링크색 16~20%, 강조 = 링크색. 찾기·변경 표시(호박색)와 오류 색은 스타일과 상관없이 밝음/어두움만 나눈다.
- **지키는 것**: `ui_smoke.py` 가 스타일마다 사이드바 글자·상태줄의 흐린 글자·고른 행의 대비 4.5:1 이상과, 사이드바 색이 스타일마다 다른지 본다. 어두운 스타일의 고른 행은 제목 색(Nord 청록 등)이 모자라 본문 글자를 밝게 해서 쓴다.

## D29. 전체 점검에서 나온 보안 수정 (v0.3.2)

사용자가 '모든 기능을 전체적으로 점검'하도록 요청했고, 보안·서버, 화면, 문서-코드 일치를 나눠 검토한 뒤 재현되는 것만 고쳤다 (2026-10-11).
- **프로그램을 현재 폴더에서 찾지 않는다**: Windows 는 `code`·`explorer` 같은 이름을 PATH 보다 현재 폴더에서 먼저 찾는다 (`shutil.which` 도 같다). `run.bat .`·탐색기 우클릭(`%V`)으로 띄우면 현재 폴더가 열린 프로젝트라서, 내려받은 프로젝트에 든 `code.cmd` 가 코드 링크 한 번에 실행될 수 있었다 (`shutil.which('code')` 가 `.\code.CMD` 를 돌려줌을 확인). 그래서 `app.py` 는 폴더 인자를 푼 뒤 앱 폴더로 `chdir` 하고, `osutil` 은 `NoDefaultCurrentDirectoryInExePath=1` 로 편집기를 찾고 탐색기를 `%SystemRoot%\explorer.exe` 로 띄우며, 설정 `editor` 는 절대경로만 받는다.
- **경로는 글자로 먼저 거른다**: `resolve_inside` 가 `(root / rel).resolve()` 를 먼저 했는데, `rel` 이 `\\서버\공유\x`(주소의 `%5C%5C`)면 `root` 가 버려지고 Windows 가 그 서버에 SMB 로 접속해 로그인 정보(NTLM 해시)를 건넨다. 문서 속 `<img src="/doc/%5C%5C서버…">` 하나로 일어나고, 인터넷 그림을 꺼도 막히지 않았다. 이제 `normpath` 로 root 안인지 본 뒤에만 `resolve()` 한다.
- **설정 값의 형식**: 손으로 고치는 파일이라 JSON 은 맞아도 형식이 틀릴 수 있다 (`"exclude_dirs": "data"` 는 글자 하나하나가 폴더 이름이 되고, `5` 면 폴더 열기·트리가 500). `value_ok` 로 `DEFAULTS` 와 같은 형식인지 보고, 틀린 값만 기본값으로 돌며 알리고 저장을 멈춘다 (D21 과 같은 원칙 — 손으로 쓴 값을 덮어쓰지 않는다).
- **그 밖에 고친 것**: 브라우저 모드의 폼 POST(`/api/open-config` 가 본문 없이 설정 파일을 열었다)를 415 로, 망가진 html 하나가 트리 전체를 500 으로 만들던 것, 공백이 많은 제목 줄에서 정규식이 수 초씩 멈추던 것(ReDoS), html 문서 속 인터넷 그림의 Referer.
- **그대로 둔 것**: `/doc/a.md::$DATA`·`a.md.` 처럼 Windows 가 같은 파일로 여는 이름도 200 이다. 숨김·밖 경로는 이 방법으로도 404 이고, 보기 전용이라 해가 없다.

## D30. 스타일 24종, 목록 묶는 방식 3가지

- **결정**: 스타일을 12종에서 24종으로 늘리고, 선택 목록의 묶음을 밝은/어두운 2가지에서 세 방식 중 고르게 한다 (v0.4.0). 사용자가 '스타일을 더 많이, 묶음은 3~4개로' 요청했고, 제안한 세 방식(용도별·분위기별·밝기별)을 '모두 고를 수 있게' 정했다. 개수는 추천안(12종 추가)으로 했다.
- **새 스타일**: 업무용 사내 문서(맑은 고딕, 파란 머리행 — Word 기본 색)·컨설팅(남색·청록), 읽기용 책(명조, 문단 들여쓰기)·잡지(굵은 고딕 제목, 뽑은 인용)·원고(고정폭, iA Writer 풍), 개발용 문서 사이트(Read the Docs·MkDocs 의 알림 상자)·Solarized 라이트·Gruvbox 라이트, 어두운 GitHub 다크·Dracula·One Dark·먹(완전 검정, OLED). 남의 CSS 를 복사하지 않고 `base.css` 변수로 새로 만들었고, 팔레트 색이 대비 4.5:1 에 못 미치면(Solarized 본문·링크, Dracula 주석 등) 조금 짙게·밝게 바꿨다.
- **묶는 방식**: 용도별(업무·보고 / 읽기·출판 / 개발·기술 / 어두운) — 기본, 분위기별(깔끔한 / 따뜻한·종이 / 색이 있는 / 어두운), 밝기별(밝은 / 종이·책 / 어두운). 설정 `theme_groups`, 설정 창의 '스타일 목록 묶기'에서 고른다. 툴바의 `<select>` 는 그대로 두고 `<optgroup>` 만 바꾼다 — 목록 안에 방식 전환을 넣으면 고르는 동작과 섞인다. 목록 옆에 바로 위·아래 스타일로 바꾸는 ∧·∨ 버튼을 둔다 (사용자 요청 — 24종을 차례로 견주어 보게). 끝에서 처음으로 돌아가지 않고 멈춘다.
- **지키는 것**: 어두운 스타일은 어느 방식에서나 '어두운' 묶음 하나에 모은다 (밝기가 가장 큰 차이라서). 밝은 스타일은 세 방식의 묶음을 모두 정해야 목록에 나온다 (`theme.js` 의 `light(...)`). `ui_smoke.py` 가 세 방식 모두 24종을 한 번씩 보이는지 본다.

## D31. 글자 크기 버튼과 장 하이라이트

- **글자 크기 (사용자 요청)**: 툴바의 − 100% + 로 문서 본문만 키운다. Ctrl+휠(창 전체 확대)과 달리 앱 UI 는 그대로이고, 단 폭도 같은 배율로 넓혀 한 줄의 글자 수를 지킨다. 그림·다이어그램은 키우지 않는다 (흐려지고 넓은 표가 넘친다). 단계는 0.8~2 의 9단계, 값은 설정 `font_scale` 에 남겨 다음 실행에도 쓴다. html 문서는 스타일 없는 것은 같은 변수, 스타일 있는 것은 문서 전체 `zoom` 으로 (그 문서의 글자 크기를 알 수 없어서).
- **장 하이라이트 (사용자 요청)**: '한 장만 지금 모양 그대로, 다른 부분은 글자·선·그림이 바탕색에 가까워져 잘 안 보이게, 키보드 위·아래·PageUp·PageDown 으로 앞뒤 장'. 바탕색에 가깝게 하는 방법으로 블록 `opacity` 를 쓴다 — 바탕이 같으므로 글자·선·그림·다이어그램이 모두 같은 비율로 바탕색 쪽으로 간다. 색을 하나하나 바꾸면 스타일 24종과 코드·표·그림마다 규칙이 필요하다.
- **장의 단위**: 문서의 맨 위 수준 절. Claude 가 쓰는 문서는 보통 `# 제목` 하나와 `##` 절이라, H1 이 하나뿐이면 제목으로 보고 H2 절을 장으로 본다. 제목 앞의 머리말도 한 장으로 쳐 첫 장으로 돌아갈 수 있게 한다. 장의 범위는 그 장 제목을 눌러 접을 때 숨는 범위와 같게 했다 (사용자가 확인을 요청 — 처음에는 H1 하나가 맨 앞에 있을 때만 제목으로 봐서 접기와 규칙이 달랐고, 메타데이터 표가 따로 한 장이 되던 것을 고쳤다).
- **버튼**: 하이라이트 버튼 옆에 앞뒤 장 ∧·∨ (사용자 요청, 스타일 목록 옆 버튼과 같은 모양). 하이라이트 중에만 눌린다.
- **키**: 사용자가 정한 대로 ↑·↓·PageUp·PageDown 은 장 하이라이트 중에는 스크롤 대신 앞뒤 장이다. 긴 장 안에서는 마우스 휠·스페이스로 스크롤한다. 입력칸·열린 팝업·메뉴에서는 원래 동작.
- **그 밖**: 흐린 장을 누르면 그 장으로(첫 누름은 링크·접기로 쓰지 않는다), 목차·찾기·검색 결과로 가면 그 장으로 따라간다. md 문서만 — html 은 구조가 문서마다 달라 장을 나눌 수 없다.

## D32. math·latex·tex 코드 블록을 수식으로

- **결정 (사용자 요청)**: ```` ```math ````·```` ```latex ````·```` ```tex ```` 코드 블록을 KaTeX 로 그린다. KaTeX 가 못 읽으면(오류) 코드 블록 그대로 둔다. 설정 `math: false` 면 모두 코드.
- **이유**: Claude 가 추출·정리한 문서는 식을 `$$` 대신 ```` ```latex ```` 블록에 쓰는 일이 많아, 원문 그대로 보였다. GitHub·GitLab 은 ```` ```math ```` 를 수식으로 그린다.
- **코드로 남기는 것**: LaTeX 문서 원문 예시는 `\documentclass`·`\section`·`\item`·`\cite`·`\label` 같은, KaTeX 에 없는 명령에서 걸리므로 코드로 남는다. 그래서 '읽을 수 있으면 수식'으로 정했다. 빨간 오류 글자로 그리지 않는 것도 같은 이유다 — 원문이 그대로 보이는 편이 읽기 쉽다.
- **세부**: 빈 줄로 나뉜 식은 따로 그린다 (TeX 도 수식 안의 빈 줄은 오류다). 블록 안에 또 쓴 `$$…$$`·`\[…\]` 는 벗긴다. 'LaTeX 복사'는 벗긴 TeX 를 준다.

## D33. 창 나누기 — 문서를 최대 3개 나란히

- **결정 (사용자 요청, 2026-10-18)**: '문서를 최대 3개까지, 창의 가로 길이는 같게 나눠, 하나면 100%, 선택된 창에 따라 오른쪽 목차도'. 문서 화면을 최대 3칸으로 나누고, 칸마다 화면·스크롤·뒤로/앞으로 기록이 따로다. 선택된 칸 하나를 목차·찾기·장 하이라이트·상태줄·트리 강조·툴바가 따른다 (v0.6.0).
- **여는 방법 (사용자가 고름)**: Ctrl+클릭(트리·최근 변경·개요·문서 속 링크·검색 결과, Ctrl+P 는 Ctrl+Enter)과 우클릭 '오른쪽 창에 열기'. 툴바 버튼·끌어다 놓기는 고르지 않았다. 새 칸은 선택된 칸 바로 오른쪽에.
- **3칸일 때 (사용자가 고름)**: 선택된 칸에 열고 '창은 3개까지' 알린다 (Alt+← 로 되돌릴 수 있다).
- **다음 실행 (사용자가 고름)**: 열어 둔 창들과 스크롤 위치, 선택된 창을 되살린다. `projects` 기록에 `panes`·`active` 를 더하고 `doc` 은 선택된 창의 문서로 남겨, 옛 기록도 그대로 읽는다.
- **구현**: 선택된 칸의 본문·스크롤 상자에 `#lec-view`·`#lec-content` id 를 옮겨 단다. 선택된 칸만 다루는 모듈(찾기·우클릭 메뉴·검색 결과 등)과 화면 점검 100여 곳이 그대로 동작하고, 모든 칸을 다루는 렌더러·자동 새로고침은 칸 객체를 받는다. 칸마다 iframe·창 객체를 두는 방법은 쓰지 않았다 — 같은 앱 문서 안이라 스타일·글꼴·라이브러리를 한 번만 불러온다.
- **지키는 것**: 나눠 볼 때는 목차가 없는 문서여도 목차 칸을 남긴다 (칸을 고를 때마다 모든 칸 폭이 바뀌면 읽던 줄이 흔들린다). 장 하이라이트는 다른 칸을 고르면 끈다 (칸마다 켜 두면 ↑·↓ 가 어느 칸을 움직이는지 헷갈린다). 인쇄는 선택된 칸의 문서만.
- **변경 (v0.7.0, 사용자 요청 2026-10-23)**: 창 나누기를 걷었다 — '한 프로젝트에서 한 문서만 읽는 것으로 복귀하고, 탭은 여러 프로젝트를 열도록'. 칸 구조(칸마다 화면·기록·렌더링 순번, 선택된 칸에 id 를 옮겨 다는 방식)는 프로젝트 탭의 문서 화면으로 그대로 쓴다 (D34). Ctrl+클릭·'오른쪽 창에 열기'·'이 창 닫기'·칸 머리줄·Ctrl+1·2·3(창 고르기)은 없어졌고, 위치 기록의 `panes`·`active` 는 읽지 않는다 (`doc` 은 그때 선택된 창의 문서라 그대로 쓴다).

## D34. 프로젝트 탭 — 폴더마다 탭 하나, 창은 하나

- **결정 (사용자 요청, 2026-10-23)**: '다시 한 프로젝트에서 한 문서만 읽는 것으로 복귀하고, 탭은 여러 프로젝트를 열 수 있도록. 탭을 누르면 왼쪽의 문서 목록도 같이 변경' (v0.7.0). 창 나누기(D33)를 걷고 폴더마다 탭을 둔다. 탭마다 트리·사이드바 상태·문서 화면·뒤로/앞으로 기록이 따로다.
- **사용자가 추천대로 고른 것**: 탭 막대는 툴바 아래 전체 폭 (툴바의 폴더 이름·폴더 열기·최근 폴더를 옮김). 폴더 열기(Ctrl+O·최근 폴더·시작 화면)는 늘 새 탭, 이미 열린 폴더면 그 탭으로. 탐색기 우클릭·`run.bat 폴더` 로 또 실행하면 떠 있는 창에 탭으로 더한다 (창은 하나). 탭은 10개까지 (최근 폴더 수와 같게).
- **서버가 여러 폴더를 함께 연다**: 탭마다 `Project`(감시·변경 기록·스캔 캐시). 탭을 고를 때 서버의 폴더를 바꿔 끼우는 방법은 쓰지 않았다 — 숨은 탭의 변경을 놓치고, 숨은 탭의 그림·html 문서 요청이 엉뚱한 폴더로 가고, 바꿀 때마다 감시를 다시 시작해야 한다. 주소에는 프로젝트 id 를 넣는다 (`/doc/<id>/…`, `?p=<id>`). id 는 실행마다 새로 만드는 무작위 값이다 — 폴더 경로가 주소에 드러나지 않고, 한 탭의 문서가 `../<다른 id>/` 로 다른 탭 프로젝트의 파일을 부를 수 없다 (md 의 링크·그림은 `resolveRef` 도 막는다). 열린 탭 목록은 서버가 들고 있어, 페이지를 다시 불러오거나 다른 실행이 폴더를 넘겨도 화면이 서버에 맞춘다 (`tabs_seq`).
- **문서 화면은 탭마다 하나를 겹쳐 둔다**: D33 의 칸 구조를 탭의 문서 화면으로 쓴다. 고르지 않은 탭은 `visibility: hidden` 으로 자리를 지킨다 — 탭을 오갈 때 다시 그리지 않고 스크롤 위치·그림 크기를 잃지 않는다 (`display:none` 은 스크롤을 잃고 숨은 동안 Mermaid·iframe 크기를 잴 수 없다). 숨은 탭에서 바뀐 문서는 트리·점만 갱신하고 그 탭을 고를 때 다시 그린다 — 보이지 않는 탭을 모두 그리지 않고, 바뀐 곳 강조도 그때 보인다.
- **선택된 탭만 다루는 모듈은 탭을 모른다**: `S.root`·`S.tree`·`S.fileMap` 등을 선택된 탭의 값을 읽고 쓰는 접근자로 바꿔, 트리·팔레트·검색·우클릭 메뉴는 거의 그대로 둔다. 렌더러만 칸의 탭(`pane.tab`)에서 프로젝트를 읽는다 — 그리는 중에 다른 탭을 골라도 원래 탭에 그리게.
- **다음 실행**: 열어 둔 탭과 선택된 탭(`tabs`·`active_tab`)을 되살리고, 탭마다 마지막 문서·위치(`projects`, `restore_last`)는 그 탭을 처음 고를 때 연다 — 탭이 많아도 시작이 느려지지 않게. 폴더 인자를 주면 그 폴더를 탭으로 더한다. `tabs` 가 없는 옛 설정은 `last_folder` 하나를 연다.
- **창은 하나 (`instance.py`)**: 두 번째 실행은 Windows 이름 있는 파이프로 첫 실행에 폴더를 넘기고 끝난다. 잠금 파일·포트 기록 대신 파이프를 쓴 것은 보기 전용 원칙(디스크에 쓰는 것은 config.json 하나) 때문이다. 표준 라이브러리 `multiprocessing.connection` 으로 충분하고, pickle 을 쓰지 않도록 JSON 바이트만 주고받는다. 파이프 이름에 사용자와 설정 폴더를 넣어 다른 사용자·점검용 실행(`LECTERN_CONFIG_DIR`)과 섞이지 않게 했다. 넘기는 쪽이 `AllowSetForegroundWindow` 를 불러 받는 쪽 창이 앞으로 나올 수 있게 한다. `--browser`·`--debug` 는 따로 뜬다 (개발용).
- **변경 (v0.9.1, 사용자 요청 2026-10-23)**: '프로젝트가 가장 중요한데 다른 글자와 별 차이가 없다' — 탭을 다른 글자보다 크고 굵게(14.5px, 굵게), 이름 앞에 폴더 아이콘, 선택된 탭은 강조색 바탕과 굵은 밑줄. 바탕·글자는 고른 트리 행과 같은 색 짝(`--ui-active-bg`·`--ui-active-fg`)이라 스타일 24종 모두 `ui_smoke` 의 대비 점검을 그대로 받는다.
- **지키는 것**: 탭은 프로젝트만이다 — 열린 문서 탭은 여전히 하지 않는다 (D7). 단축키는 브라우저와 같게 (Ctrl+1~8·Ctrl+9, Ctrl+Tab·Ctrl+PageDown, Ctrl+W, 가운데 버튼으로 닫기). 탭을 닫기 전에 그 탭의 마지막 위치를 보낸다.

## D35. 트리는 파일 이름, 마우스를 올리면 문서 제목

- **결정 (사용자 요청, 2026-10-23)**: '왼쪽 문서 목록에 문서 제목이 아니라 파일 이름이 나오고, 마우스를 위에 놓으면 문서 제목이 나오게' (v0.7.1). 트리와 최근 변경 목록의 기본을 파일 이름으로 바꾸고, 행의 툴팁에 문서 제목과 경로를 둔다.
- **'제목' 버튼은 남긴다**: 켜면 예전처럼 제목으로 보이고 툴팁은 경로와 제목. 거르기는 두 모드 모두 제목과 경로로 찾는다. 전체 검색 결과·폴더 개요·빠른 열기는 그대로 제목을 앞에 보인다 (검색어와 요약을 함께 보는 화면이라).
- **옛 설정 바꾸기**: 앱은 설정을 저장할 때 기본값도 함께 적으므로, 옛 파일의 `show_titles: true` 는 사용자가 고른 것인지 알 수 없다. 설정 형식 판(`version`)을 2로 올리고, 1인 파일은 읽을 때 `show_titles` 를 한 번 `false` 로 바꾼다 (`config._upgrade`). 그 뒤에 버튼으로 다시 켜면 그대로 남는다.

## D36. 문서 외 파일 — 문서 트리 아래 탐색기처럼

- **결정 (사용자 요청, 2026-10-23)**: '프로젝트에는 md, html 이외에도 다른 확장자를 가진 문서들이 있다. 문서 리스트 아래에 문서 이외 파일의 리스트를 추가하고, 중간에 분리선을 넣어 관리한다. 문서 이외 리스트는 윈도우 탐색기처럼 더블 클릭 등의 기능을' (v0.8.0). 사이드바 파일 탭을 문서 트리 + 분리선 + '문서 외 파일' 목록으로 나눈다. 레이아웃은 여전히 왼쪽 사이드바 하나다 (D7).
- **탐색기처럼, 보기 전용 안에서**: 누르면 고르고 두 번 누르거나 Enter 면 열기, 화살표·Home·End·글자 입력으로 옮기기, 우클릭 메뉴. 이름 바꾸기·지우기·옮기기·새로 만들기·끌어다 놓기는 넣지 않는다 (D1 — 디스크에 쓰지 않는다).
- **열기는 실행하지 않는다**: 탐색기의 두 번 누르기는 실행 파일을 실행하지만 Lectern 은 하지 않는다 (원칙 5). 여는 방법은 문서 속 링크와 같은 `osutil.open_path` — 안전한 형식은 기본 앱, 코드·글은 편집기. 실행·설치 파일, 압축, 데이터베이스, 매크로가 든 오피스 문서처럼 편집기로 읽을 수 없는 형식은 `REVEAL_ONLY_EXT` 로 묶어 탐색기에서 선택만 한다 (문서 속 링크도 같아졌다 — 전에는 편집기로 열려 했다). 사용자가 실행하려면 탐색기에서 직접 한다. '편집기로 열기'는 기본 앱 형식(csv·txt 등)을 편집기로 보고 싶을 때.
- **문서 트리와 따로 읽는다**: 소스가 많은 프로젝트는 파일이 수천 개라, 문서 트리 응답에 싣지 않고 `/api/others` 로 목록이 보일 때만 읽는다. 5000개에서 멈춘다. 감시는 문서 외 파일의 생성·삭제·이동만 남기고(`others`) 내용 수정은 보지 않는다 — Claude Code 가 소스를 고칠 때마다 목록을 다시 읽지 않게. 이때 문서 트리는 다시 읽지 않는다.
- **분리선**: 끌어서 아래 목록의 높이를 바꾸고(저장), 두 번 누르면 기본 높이. 머리줄을 눌러 목록을 접으면 문서 트리가 그만큼 길어진다. 사이드바 거르기는 두 목록에 함께 적용한다.

## D37. 이름 앞의 종류 아이콘, '파일' 목록, 종류별·폴더 보기

- **결정 (사용자 요청, 2026-10-23)**: '문서를 포함해서 파일 이름 앞에 종류를 나타내는 아이콘', ''문서 외 파일'이라 하지 말고 '파일'이라고만', '지금처럼 종류별로 모아 보거나 폴더 구조를 그대로 보여 주는 것을 고를 수 있게' (v0.9.0).
- **아이콘**: 문서 트리·최근 변경·파일 목록의 행마다 이름 앞에 종류 아이콘 (`icons.js`, 그림은 `index.html` 의 기호). md·html 은 따로 그리고 강조색으로 칠해 다른 파일과 구분한다 — 그래서 트리의 'HTML' 글자 표시는 뺐다 (폴더 개요에는 남김). 그림·표·문서·코드·압축·미디어·실행 파일·그 밖, 폴더. 여는 방법은 아이콘이 아니라 서버가 정한다.
- **'파일'**: 사이드바 머리줄과 목록 이름을 '파일'로. 사이드바 탭 이름도 '파일'이지만 사용자가 고른 이름이다.
- **두 보기 (사용자 말을 이렇게 읽음)**: '종류별로 모아 보기'는 지금처럼 문서는 위 트리, 문서가 아닌 파일은 분리선 아래로 나눠 보는 것, '폴더 구조 그대로'는 둘을 디스크의 폴더 구조대로 한 트리에 섞어 보는 것. 거르기 칸 옆 '폴더' 버튼으로 바꾸고 설정 `files_view` 에 남긴다. 기본은 지금과 같은 종류별.
- **폴더 보기의 행 동작**: 이 앱은 뷰어라 문서는 문서 트리처럼 한 번 눌러 연다. 문서가 아닌 파일은 탐색기처럼 두 번 눌러 연다 (실행하지 않음, D36). 폴더 행은 탐색기처럼 누르면 고르기만 하고, 폴더 개요는 우클릭 메뉴로 — 파일과 섞인 트리에서 폴더를 누를 때마다 본문이 개요로 바뀌면 탐색이 번거롭다.
- **만든 방법**: 폴더 보기는 서버에 새 API 를 두지 않고, 화면이 탭의 문서 트리와 `/api/others` 의 트리를 합친다 (둘 다 이미 받아 두므로). 정렬은 서버의 `natural_key` 와 같은 규칙을 JS 로.

## D38. 오른쪽 터미널 — 프로젝트 탭마다 PowerShell

- **결정 (사용자 요청, 2026-10-23)**: '오른쪽에 윈도우 파워셸 터미널을 넣고 싶다. 시작 위치는 프로젝트 폴더와 동일한 위치' — 먼저 검토안을 보이고, 사용자가 권장대로 진행하라고 했다 (v0.10.0). 본문 오른쪽(목차 자리)에 터미널 패널을 두고, 프로젝트 탭마다 셸 하나를 그 프로젝트 폴더에서 띄운다. 툴바 버튼·`` Ctrl+` `` 로 열고 닫는다.
- **원칙을 바꾼다**: 원칙 1(보기 전용)·5(코드를 실행하지 않음)를 Lectern 이 스스로 하는 일에 대한 것으로 좁힌다 (D1 변경). Lectern 은 여전히 파일을 만들거나 고치지 않고, 문서·링크·파일 목록에서 무엇도 실행하지 않는다. 터미널은 사용자가 직접 친 명령만 돌린다 — 셸로 글자를 보내는 길은 사용자의 키 입력·붙여 넣기(`POST /api/term/input`)뿐이고, 문서·링크·다른 기능이 셸에 명령을 보내는 API 는 두지 않는다.
- **사용자가 권장대로 고른 것**: 창 안의 웹 터미널(xterm.js + Windows 의사 콘솔) — 외부 Windows Terminal 창을 띄우는 것보다 문서와 한 화면에서 본다. 터미널을 열면 목차를 감춘다 (목차 버튼으로 함께 볼 수 있고, 설정 `toc_visible` 은 바꾸지 않는다). 탭마다 셸 하나. 기본 셸은 모든 Windows 에 있는 Windows PowerShell 5.1, 설정 파일의 `terminal_shell`(전체 경로)로 PowerShell 7 등으로 바꾼다. 아래 보안 장치를 함께 넣는다.
- **화면**: xterm.js 5.5 (+ fit·unicode11 애드온, `web/vendor/xterm`, MIT). 처음 열 때만 불러온다. 색은 문서 스타일과 상관없이 어둡게(Windows Terminal 의 Campbell) — PSReadLine 의 글자 색이 어두운 바탕을 가정한다. 글꼴은 PC 의 것만 (Cascadia Mono → Consolas → D2Coding → 맑은 고딕, D26). 한글처럼 두 칸인 글자는 unicode11 로 폭을 맞춘다.
- **주고받기**: 키 입력은 `POST /api/term/input`, 출력은 긴 폴링 `GET /api/term/read` (받은 곳 다음부터, 새 출력이 오거나 20초가 지나면 돌아온다). WebSocket 은 쓰지 않았다 — 새 의존성(flask-sock 등)이 필요하고 사내망 설치가 번거로워진다. 키 하나에 요청 하나지만 127.0.0.1 이라 지연을 느낄 수 없다. 출력은 셸마다 최근 512K 글자를 서버가 들고 있어, 패널을 닫았다 열거나 페이지를 다시 불러와도 이어 보인다.
- **의사 콘솔은 ctypes 로 Windows ConPTY 를 직접 부른다 (`conpty.py`, 새 의존성 없음)**: 검토안에서는 pywinpty 를 권했으나 시험해 보니 pywinpty 3.1.0 에 함께 든 OpenConsole/conpty.dll 로 띄운 PowerShell 5.1 이 한글을 cp949 로 내보내 깨졌다 (chcp 65001·출력 인코딩을 UTF-8 로 바꿔도 `한글` → `�ѱ�`). Windows 에 들어 있는 ConPTY(`kernel32.CreatePseudoConsole`)로는 같은 명령이 UTF-8 로 바르게 나왔다. pywinpty 의 `PtyProcess` 가 127.0.0.1 TCP 소켓으로 출력을 넘기는 점도 걸렸다. 그래서 pywinpty 를 빼고 표준 라이브러리로 만들었다 (Windows 10 1809 이상 — 그 밖에서는 터미널 API 가 501).
  - 셸은 작업 개체(Job Object, `KILL_ON_JOB_CLOSE`) 안에서 돈다: 멈춘 채 만들어 작업 개체에 넣은 뒤 시작한다. 셸에서 띄운 프로그램도 같은 작업 개체라, 탭을 닫거나 다시 시작하거나 앱이 끝나면(강제 종료 포함) 함께 끝난다. 탭을 닫기 전 '실행 중' 확인도 작업 개체 안의 프로세스 수로 한다.
  - `STARTF_USESTDHANDLES` 에 빈 핸들을 준다. 없으면 창 없는 앱(pythonw·Lectern.exe)의 표준 핸들이 셸로 넘어가 입출력이 의사 콘솔을 거치지 않는다.
  - 셸은 전체 경로로 띄운다 (D29 — 프로젝트 폴더의 `powershell.exe` 가 대신 실행되지 않게). 환경 변수는 앱이 시작할 때의 값을 준다 (`osutil` 이 실행 중에 넣는 `NoDefaultCurrentDirectoryInExePath` 가 셸로 새지 않게).
- **보안**: 터미널 API 는 셸을 다루므로 다른 API 보다 한 겹 더 막는다.
  - 비밀값: 서버가 실행마다 새 값(`term_secret`)을 만들어 `index.html` 에 싣고(`meta lec-term`), 터미널 API 는 `X-Term` 헤더로 그 값을 받아야 한다 — 창 모드 토큰이 없는 브라우저 모드에서도. 다른 사이트는 이 페이지를 읽을 수 없으므로(CORS 없음, Host 검사로 DNS 리바인딩도 막힘) 값을 모른다. `Origin` 이 오면 같은 출처여야 한다.
  - 스크립트: 문서 속 스크립트가 앱 출처에서 돌면 비밀값을 읽을 수 있으므로 `/` 의 CSP 에 `script-src 'self' 'unsafe-eval'` 을 둔다 (D14 변경). md 는 DOMPurify, html 문서는 스크립트 없는 iframe(D27) 이라는 지금의 방어에 한 겹 더한 것이다.
  - 셸 경로는 화면에서 바꿀 수 없다 (`terminal_shell` 은 `CLIENT_KEYS` 가 아님). 입력은 한 번에 65536자까지.
- **키**: 터미널 안의 키는 셸 것이다 (Ctrl+C·Ctrl+W·Esc·방향키 — Claude Code 같은 TUI 가 쓴다). 앱 단축키는 `` Ctrl+` ``(패널)와 Ctrl+Tab(다음 탭)만 받는다. Ctrl+C 는 고른 글이 있으면 복사, 없으면 셸로(중단). Ctrl+V 붙여 넣기. 우클릭은 Windows 콘솔처럼 고른 글이 있으면 복사, 없으면 붙여 넣기.
- **탭과 패널**: 패널을 닫아도 셸은 돈다. 다른 탭을 고르면 그 탭의 셸로 바뀐다 (패널이 열려 있으면 그 탭의 셸을 띄운다). 탭을 닫으면 그 셸을 끝내는데, 셸에서 띄운 프로그램이 돌고 있으면 먼저 묻는다. 셸이 끝나면(`exit`) Enter 로 다시 시작한다. 앱을 켤 때 패널은 늘 닫힌 채다 — 셸은 사용자가 열 때만 띄운다. 패널 폭은 경계를 끌어 바꾸고(`terminal_width`) 두 번 누르면 기본(본문 영역의 42%).
- **하지 않은 것**: 창을 닫을 때는 셸에서 프로그램이 돌고 있어도 묻지 않고 함께 끝낸다. 셸의 출력은 디스크에 남기지 않고, 앱을 다시 실행하면 셸은 새로 시작한다.
- **변경 (v0.12.0, 고침)**: 셸에서 띄운 프로그램(ping 등)이 Ctrl+C 로 멈추지 않을 수 있었다. 'Ctrl+C 무시' 표시(`SetConsoleCtrlHandler(NULL, TRUE)` 또는 새 프로세스 그룹으로 띄우면 켜진다)는 자식에게 물려지는데, Lectern 을 그렇게 띄운 쪽에서 오면 셸과 그 자식까지 Ctrl+C 를 무시한다 (점검 도구에서 그랬다). 셸을 띄우기 전에 이 프로세스의 표시를 끈다 — 창 모드의 Lectern 은 콘솔이 없어 자기에게는 영향이 없다.
- **변경 (v0.10.1, 사용자 요청 2026-10-23)**: '터미널의 스타일을 테마에 맞춰 적절하게' — 사용자가 추천대로 고름: 스타일마다 맞추고, 설정 창에 '터미널 색을 스타일에 맞춤'(끄면 늘 어둡게, 설정 `terminal_follow_style`). 바탕은 그 스타일의 코드 블록 바탕(`--md-code-bg` — 본문과 살짝 구분되는 코드 색), 글자는 `--md-fg`, 커서·선택은 `--md-link`. ANSI 16색은 이름이 같은 터미널 색표가 있는 스타일(Solarized·Gruvbox 라이트·Nord·Dracula·One Dark·GitHub·GitHub 다크)은 그것을, 나머지는 밝은/어두운 기본 색표를 쓴다. 밝은 기본 색표는 흰색(white·brightWhite)을 회색·검정으로 둔다 — 셸·프로그램은 어두운 바탕을 가정하고 '또렷한 글자'를 흰색으로 쓰기 때문이다. 그래도 프로그램이 고른 색(24비트 색 포함)이 바탕에 묻힐 수 있으므로 xterm 의 `minimumContrastRatio` 를 4.5 로 둔다 — 글자와 그 칸 바탕의 대비가 4.5:1 보다 낮으면 글자 색을 진하게·옅게 고친다 (Solarized 의 brightBlack 처럼 원래 색표가 바탕과 같은 색도). 스타일 파일을 바꿔 끼우면 다 불러온 뒤(`load`) CSS 변수를 읽어 열린 모든 터미널에 입힌다. 글꼴은 스타일을 따르지 않는다 (고정폭·한글 폭이 맞는 글꼴만, 원고 스타일은 본문 글꼴을 코드에도 쓴다).

## D39. 목차에 글의 구성 요소 — 제목 아래에 섞어서

- **결정 (사용자 요청, 2026-10-23)**: '오른쪽 목차 안에 글의 구성 요소들을 넣어 달라. 표, 그림, 박스글 등을 선택하면 그곳으로 이동' (v0.11.0). 사용자가 추천대로 고른 것: 목차의 각 제목 아래에 그 절의 구성 요소를 섞어서(종류별로 따로 모으거나 탭으로 바꿔 보는 대신 — 어느 절에 무엇이 있는지 한눈에), 목차 머리에 종류별로 켜고 끄는 버튼. 종류는 사용자가 여섯 가지를 모두 골랐다: 표·그림·박스글·다이어그램·코드·수식.
- **무엇을 구성 요소로 보나** (`toc.js` 의 `partKind`): 표(`table`), 그림(`img`·`figure` — 그림 틀·표 안의 그림과 32px 보다 작은 아이콘은 빼고), 박스글(인용·콜아웃, html 의 `aside`·`[role=note]`·`.callout`·`.admonition` — 박스 안의 박스는 바깥 것만), 다이어그램(Mermaid, 문법 오류 상자 포함), 코드(코드 블록, html 의 `pre`), 수식(블록 수식). 메타데이터·각주·제목 안의 것은 뺀다. md 와 html 문서 모두.
- **목차에 보이는 글**: 종류와 번호(표 1, 그림 2 … 문서 순서, 감춘 종류와 상관없이) + 짧은 설명 — 표는 캡션(`<caption>`, 또는 바로 앞의 '표 1. …'·통째로 굵은 짧은 단락, 없으면 머리행 첫 칸들)과 크기, 그림은 대체 글·제목·파일 이름, 박스글은 콜아웃 종류(참고·팁·중요·경고·주의, 아니면 '인용')와 첫 글, 다이어그램은 종류(흐름도·시퀀스 …)와 제목·첫 상자 글, 코드는 언어와 첫 줄, 수식은 TeX 원문. 길면 줄이고 마우스를 올리면 전체.
- **누르면**: 접힌 절은 펴고(`unfoldTo` — 장 하이라이트도 그 장으로), 작은 것은 화면 가운데, 큰 것은 위를 맞춰 보이고, 1.8초 동안 링크 색 테두리로 표시한다 (`lec-target`, 바뀐 곳 강조의 호박색과 구분). 지금 읽는 위치 표시는 제목만 따른다.
- **종류 버튼**: 그 문서에 있는 종류만 '표 2'처럼 개수와 함께 보인다. 누르면 그 종류를 목차에서 감추고(취소선) 다시 누르면 보인다. 설정 `toc_hidden_parts` 에 **감춘** 종류를 적는다 — 보일 종류를 적으면 나중에 새 종류를 더했을 때 이미 쓰던 사람에게 나오지 않는다.
- **목차가 보이는 때**: 전에는 제목이 둘 이상일 때만이었다. 이제 구성 요소가 하나라도 있으면 보인다 (제목이 없는 표 모음 문서도).

## D40. 터미널 모음 — 열린 프로젝트들의 터미널을 한 화면에

- **결정 (사용자 요청, 2026-10-23)**: '열린 프로젝트의 터미널만 모아서 보여 주는 탭 또는 버튼' (v0.12.0). 사용자가 추천대로 고른 것: 탭 막대 오른쪽 끝 버튼(누르면 탭처럼 켜짐, `` Ctrl+Shift+` ``), 칸 수에 맞춘 격자(2 = 좌우, 3~4 = 2×2, 5~6 = 3×2, 7~9 = 3×3, 10 = 4×3), 셸이 없는 프로젝트는 자리만 두고 누르면 시작.
- **탭이 아니라 덮는 보기**: 프로젝트 탭은 그대로 프로젝트만이다 (D34). 모음은 문서 화면 영역(`#lec-main`) 위를 덮는 격자이고, 버튼이 탭처럼 눌린 모양이 되며 그동안 프로젝트 탭은 고르지 않은 모양이다. 문서 칸은 그 아래에 그대로 있다 — `display:none` 으로 바꾸면 칸들의 스크롤 위치를 잃는다 (D34).
- **화면을 옮긴다**: 탭마다의 터미널 화면(xterm)을 하나만 두고, 모음을 열면 오른쪽 패널에서 칸으로 옮기고 닫으면 되돌린다. 새로 만들지 않으므로 셸 출력·스크롤이 그대로 이어지고 셸도 하나다. 칸 크기에 맞춰 셸의 글자 칸 수가 바뀐다 (Claude Code 같은 프로그램은 다시 그린다).
- **셸을 한꺼번에 띄우지 않는다**: 셸이 없는 프로젝트의 칸에는 '터미널 시작' 버튼만 둔다 — 탭이 10개여도 쓰지 않는 PowerShell 을 띄우지 않게.
- **오가기**: 프로젝트 탭을 누르면(이미 선택된 탭이어도) 모음을 닫고 그 프로젝트의 문서 화면으로. 칸의 '이 프로젝트로'와 칸 안의 `` Ctrl+` `` 는 그 프로젝트로 가서 오른쪽 터미널을 연다. 탭을 닫거나 폴더를 새로 열면 모음은 열린 채 칸만 바뀐다. 칸 머리를 두 번 누르거나 '크게'로 그 칸만 크게.
- **키**: 칸 안의 키는 셸 것이다. 앱은 Ctrl+Tab(다음 칸 — 모음 안에서는 탭이 아니라 칸을 오간다), `` Ctrl+` ``, `` Ctrl+Shift+` `` 만 받는다. 칸 밖에서도 문서 화면을 다루는 단축키(Ctrl+P·Ctrl+F 등)는 쓰지 않는다 — 가려진 화면에서 일어나 보이지 않으므로. 탭 고르기(Ctrl+1~9)·폴더 열기·설정·Esc 는 된다.
- **'실행 중' 표시**: 모아 보는 동안 2초마다 탭마다 셸에서 띄운 프로그램이 도는지(`/api/term/info` 의 `busy`) 보고 칸 머리에 '실행 중'·'대기'·'끝남'·'시작 전'. 여러 프로젝트에서 Claude Code 를 돌려 두고 어느 것이 일하는 중인지 한눈에 보려는 것이다. 버튼에는 돌고 있는 셸 수.
- **변경 (v0.13.2, 사용자 요청 2026-10-23)**: '터미널 모음 버튼과 개별 터미널 실행 버튼의 위치를 바꿀 수 있을까요', '목차 보이기 버튼도 아래로' — 탭 막대 오른쪽 끝에 '목차'·'터미널' 버튼(오른쪽 패널을 보이고 감춤 — 화면의 목차·터미널과 같은 순서, 보이면 강조색과 밑줄), 툴바의 설정 톱니 옆에 '터미널 모음' 버튼(이름과 돌고 있는 셸 수, 좁은 창에서는 아이콘과 수만). 여러 터미널을 겹친 모양의 아이콘으로 한 터미널과 구분한다. 모음을 보는 중에 '터미널'을 누르면 모음을 닫고 선택된 프로젝트의 오른쪽 터미널을 열고, '목차'를 누르면 모음을 닫고 목차를 보인다.
- **하지 않은 것**: 모음을 연 상태를 다음 실행에 되살리지 않는다 (오른쪽 터미널처럼 늘 닫힌 채 시작). 칸 크기 조절·순서 바꾸기는 없다 (탭 순서를 따른다).

## D41. 사이드바 '모아 보기' — 프로젝트의 표·그림 등을 종류마다

- **결정 (사용자 요청, 2026-10-23)**: '프로젝트 안에 있는 표만 모아 보기, 그림, 박스글, 수식, 다이어그램 등을 각각 모아서 볼 수 있으면' (v0.13.0). 검토안(본문 자리에 실제 표·그림을 그려 모으는 화면을 권함)을 보고 사용자가 고른 것: **사이드바 '모아 보기' 탭** (목록 — 이름·문서, 누르면 그 자리로), 폴더 개요의 버튼과 트리 폴더 우클릭으로도 열기, 그림은 작은 그림 격자, 문서별로 트리 순서.
- **세는 방법 — 목차와 같게**: 문서마다 본문과 같은 해석기로 화면 밖에서 그리고(md: markdown-it + 같은 정화 규칙을 `template` 에 — 그림을 부르지 않는다, html: `DOMParser` — 스크립트·그림 없음) 목차의 `readParts` 로 센다. 종류·번호·이름(표 1 · 캡션 · 크기, 박스글은 콜아웃 종류 등)이 그 문서의 목차와 같다. 누르면 그 문서를 열고, 그려진 화면에서 같은 종류·번호의 것을 `readParts` 로 찾아 목차처럼 간다 (접힌 절은 펴고 잠깐 테두리). 원문 줄 위치 대신 종류·번호로 찾는 것은 html 문서에도 같은 방법이 통하기 때문이다.
  - 그래서 판정은 그림을 불러오기 전과 후가 같아야 한다: 아이콘은 불러온 크기가 아니라 width·height 속성으로 거르고(목차도 바뀜), 불러오지 못해 글로 바뀐 그림 자리(`.image-off`)도 그림으로 센다.
  - 서버(Python)에서 세지 않았다 — 같은 해석기가 없어 새 의존성이 필요하거나 목차와 개수가 어긋난다. 서버·API 는 그대로다.
- **속도**: 처음 열 때 범위 안의 문서를 4개씩 함께 읽으며 '문서 읽는 중 N/M'. 읽은 결과는 탭마다 문서의 수정 시각과 함께 기억하고(`tab.partsCache`), 문서가 바뀌면(트리를 새로 받으면) 바뀐 문서만 다시 읽는다. 목록은 800개까지 그린다 (넘으면 거르기로 좁히라고 알린다). 그림은 목록에서 보일 때 불러온다.
- **그림**: 작은 그림 격자. 같은 그림(같은 파일·주소)을 여러 문서가 쓰면 처음 것 하나에 '+N곳' (마우스를 올리면 다른 문서들). 본문과 같은 규칙으로 불러온다 — 프로젝트 밖은 막고, 인터넷 그림은 설정 `external_images` 를 따른다.
- **범위·여는 곳**: 탭을 누르면 프로젝트 전체(또는 그 탭에서 마지막으로 본 범위). 폴더 개요의 '모아 보기: 표 · 그림 · …' 버튼은 그 폴더와 하위의 그 종류, 트리의 폴더·프로젝트 우클릭 '이 폴더의 표·그림 등 모아 보기'는 그 폴더의 종류 중 있는 첫 종류로. 사이드바가 숨어 있으면 보인다. 종류·범위·거르기·순서(트리 순서 / 최근 수정 순)·스크롤은 프로젝트 탭마다 남긴다.
- **하지 않은 것**: 본문 자리의 모아 보기 화면(실제 표·수식을 그려 견주기) — 사용자가 사이드바 목록을 골랐다. 필요해지면 같은 `readParts` 결과로 더할 수 있다.

## D42. 사이드바 파일 탭의 '문서'·'파일'·'코드' 세 묶음

- **결정 (사용자 요청, 2026-10-23)**: '문서, 파일로 구분되는데 지금 파일은 접어 넣을 수 있다. 문서라고 이름을 붙이고 문서도 접어 넣을 수 있도록, 그리고 아래에 코드 항목도 — 각종 코드로만 같은 구조로 볼 수 있게' (v0.14.0). 사용자가 추천대로 고른 것: '파일' 목록에서 코드는 뺀다(세 묶음이 겹치지 않게), 코드는 아이콘의 코드 종류 그대로 — 소스·스크립트·웹(css·소스 폴더의 html)·설정(json·yaml·toml·ini·xml)·ipynb.
- **묶음**: 종류별 보기에서 위에서부터 '문서 N'(문서 트리), '파일 N'(문서도 코드도 아닌 파일 — PDF·오피스·그림·데이터·압축·실행 파일 등), '코드 N'. 머리줄을 눌러 묶음마다 접는다 (`docs_visible`·`others_visible`·`code_visible`). 펼친 첫 묶음이 남은 높이를 갖고, 그 아래 펼친 묶음은 위 분리선을 끌어 높이를 정한다 (`others_height`·`code_height`, 두 번 누르면 기본 — 파일 30%, 코드 26%). 그래서 '문서'를 접으면 '파일'이 남은 높이를 갖는다. 분리선이 없는 묶음 사이에는 선을 긋는다.
- **코드 목록은 파일 목록과 같은 모양**: 같은 서버 응답(`/api/others`)을 화면이 `isCode` 로 나눈다 — 서버·API 는 그대로다. 폴더 먼저·접힌 채로, 두 번 누르기·Enter 로 열기(코드는 편집기로 — 실행하지 않음), 키보드·우클릭·거르기·생기고 지워지면 반영, 목록마다 펼친 폴더·고른 행·스크롤을 탭마다 남긴다.
- **폴더 보기는 그대로**: '폴더' 버튼을 켜면 묶음 머리줄·문서 트리·코드 목록을 감추고 한 트리에 문서·파일·코드를 폴더 구조 그대로.
- **덤**: 목록에서 같은 글자를 거듭 치면(탐색기처럼) 그 글자로 시작하는 다음 행으로 간다 — 전에는 'rr' 처럼 이어진 글자로 찾아 멈췄다.

## D43. 코드 읽기 화면과 코드 목차

- **결정 (사용자 요청, 2026-10-23)**: '코드에서 코드는 선택하면 문서와 같이 읽기 모드로 화면에 보여 주고, 오른쪽에 문서처럼 목차도' (v0.15.0). 'ROADMAP 하지 않기로 한 것'의 '뷰어 안 코드 보기 화면'(D11)을 사용자가 다시 요청했다. 사용자가 추천대로 고른 것: 코드 목록에서 한 번 누르면 읽기 화면·두 번 누르면 편집기, 목차는 함수·클래스와 구분 주석, 문서 속 코드 경로·링크는 읽기 화면의 그 줄로.
- **화면 종류 `code`**: `nav.js` 의 세 번째 화면 (`doc`·`overview`·`code`) — 뒤로/앞으로·스크롤 기억·자동 새로고침·찾기(Ctrl+F)가 문서처럼 된다. 마지막 위치 기록(position.js)은 문서만이다 (다음 실행에 코드를 다시 열지 않는다).
- **보이는 모양**: 머리줄(파일 이름·폴더·언어, '편집기로 열기'·'전체 복사' — 파일 이름은 문서 제목과 같은 스타일의 제목 글꼴, 버튼은 앱 글꼴로 상태줄의 '편집'과 같게: v0.26.1 사용자 요청, 본문 글꼴이 명조인 스타일에서 버튼이 명조로 보였다), 줄마다 줄 번호, 언어 색은 이미 들여온 highlight.js 로(새 라이브러리 없음, 없는 언어는 색 없이), 긴 줄은 접어서(가로 스크롤 대신 — 읽기 화면). 색·바탕은 문서 스타일의 코드 색을 따른다. 상태줄에 언어·줄 수·크기·수정 시각. 4MB 가 넘거나 글자가 아닌 파일은 보이지 않고 편집기로 열라고 알린다 (1MB 가 넘으면 색 없이).
- **줄이 화면의 최상위 블록**: 줄(`.cv-line`)을 `#lec-view` 의 바로 아래에 두어, 자동 새로고침 때 바뀐 줄 강조(diffmark)·'바뀐 곳' 버튼과 문서 안 찾기가 문서와 같은 코드로 된다.
- **자동 새로고침**: 서버는 코드 같은 문서 외 파일의 내용 수정을 변경 기록에 남기지 않는다 (D36 — 소스를 고칠 때마다 문서 트리를 다시 읽지 않게). 그래서 코드 화면은 보고 있는 동안 2초마다 그 파일의 수정 시각·크기(HEAD `/doc/…`)를 보고, 바뀌었으면 다시 그린다. 서버는 그대로다.
- **목차** (`outline.js`): 구문 분석기 없이 언어마다 줄 단위 규칙 — Python·JS/TS·Java/C#/Kotlin/Swift/Dart·Go·Rust·C/C++·Ruby·PHP·Lua·Perl·R·셸·PowerShell(#region)·배치(:이름표)·SQL(CREATE)·CSS(선택자·@media)·HTML(제목)·JSON/YAML(위 두 단계 키)·TOML/INI(섹션)·.env(키). 들여쓰기로 단계를 매기고(메서드는 클래스 아래), `# ---- 그리기 ----` 같은 구분 주석은 맨 위 단계의 '§'. 종류 표시는 § C T ƒ · # H :. 지금 읽는 위치를 제목처럼 표시하고, 누르면 그 줄을 위에 두고 잠깐 테두리. 여러 줄 문자열·주석 안을 잘못 잡을 수 있다 (목차일 뿐이다).
- **여는 곳**: '코드' 목록(한 번 누르기·Enter·우클릭 '읽기 화면에서 보기'), 폴더 보기의 코드 파일, 문서 속 경로 표기(`src/app.py:42` → 42행), 문서 속 코드 파일 링크(`#L42`). 편집기는 두 번 누르기, 우클릭 '편집기로 열기', 화면 위 버튼, 줄 우클릭 '편집기에서 이 줄 열기'. 보고 있는 코드는 '코드' 목록에서 상위 폴더를 펴고 강조한다.
- **줄 우클릭**: 이 줄·고른 글 복사, Claude용 위치(`@경로 12~20행` — 고른 줄 범위), 편집기에서 이 줄 열기, 경로 복사, 코드 전체 복사.
- **하지 않은 것**: 고치기(보기 전용), 코드 접기, 빠른 열기(Ctrl+P)·전체 검색에 코드 넣기(v0.16.0 에서 넣었다 — D44), ipynb 를 노트북 모양으로 (지금은 JSON 으로 보인다).

## D44. 빠른 열기·전체 검색에 코드

- **결정 (사용자 요청, 2026-10-23)**: '기능을 추가해주세요' — D43 의 '하지 않은 것'에 남긴 '빠른 열기(Ctrl+P)·전체 검색에 코드 넣기'를 다음 기능으로 골랐다 (v0.16.0). 사용자가 추천대로 고른 것: 전체 검색은 '문서'·'코드' 버튼으로 찾을 곳을 고르기, Ctrl+P 는 문서와 코드를 함께 — 문서 먼저.
- **코드 = 사이드바 '코드' 목록의 파일**: 서버의 `scanner.CODE_EXT`·`is_code` 와 화면의 `icons.js` code 종류가 같은 확장자 목록이다 (두 곳을 함께 고친다 — `tests/test_search.py` 가 맞춰 본다). 숨김·제외·링크·5000개 한도도 '코드' 목록(`scan_others`)과 같다. '파일' 목록(문서도 코드도 아닌 파일)은 찾지 않는다.
- **전체 검색**: `GET /api/search` 에 `docs`(기본 1)·`code`(기본 0 — 이 값을 보내지 않는 옛 화면은 그대로 문서만). 결과는 문서 먼저, 그다음 코드 — 묶음마다 200파일·1000곳 한도라 코드가 많아도 문서 결과를 밀어내지 않는다. 코드는 글자 그대로 찾고(html 처럼 보이는 글자만 고르지 않음, 제목 없음), 2MB 가 넘는 파일(잠금 파일·큰 JSON 등)은 건너뛴다. 화면: 검색 칸 아래 '문서'·'코드' 버튼(설정 `search_docs`·`search_code`, 둘 다 기본 켬 — 둘 다 끄면 고르라고 알림), 결과에 '코드' 묶음 머리, 코드 결과를 누르면 코드 화면의 그 줄로 가서 검색어를 표시한다.
- **읽은 글 기억** (`search.TextCache`): 코드는 수천 개일 수 있어 검색어를 칠 때마다 디스크를 다 읽지 않게, 탭(Project)마다 읽은 글을 (수정 시각, 크기)와 함께 기억한다. 바뀐 파일은 다시 읽고, 64M 글자를 넘으면 더 기억하지 않는다 (읽기만). 문서도 같은 것을 쓴다.
- **빠른 열기**: 맞는 문서를 먼저, 그다음 맞는 코드 (모두 60개 — 맞는 코드가 있으면 문서가 많아도 코드 20개까지는 보인다). 코드는 종류 아이콘과 함께 보이고 고르면 코드 화면. 입력 전(최근 수정 순)은 문서만. 코드 목록은 사이드바 '코드' 목록이 받은 것을 쓰고, 아직 받지 않았으면 Ctrl+P 를 열 때 받는다.
- **하지 않은 것**: 정규식·단어 단위 검색, 함수·클래스 이름으로 찾기(기호 검색), 코드가 바뀌었을 때 결과를 저절로 다시 찾기 (코드의 내용 수정은 변경 기록에 남지 않는다 — D36. 다시 찾으면 바뀐 파일을 새로 읽는다).

## D45. 사용설명서(F1)와 단축키 표

- **결정 (사용자 요청, 2026-10-23)**: '사용설명서(F1)과 단축키를 보여주는 버튼' (v0.17.0). 사용자가 추천대로 고른 것: 설명서는 문서 화면을 덮는 읽기 화면(터미널 모음과 같은 방식), 버튼은 툴바 설정 옆 '?' 하나 — 누르면 단축키 표, 그 안에 '사용설명서 열기 (F1)'.
- **설명서 내용**: `web/help/manual.md` — 앱과 함께 설치되는 Markdown (README 의 사용법을 사용자용으로 장마다 다시 쓴 것). 처음 열 때 `/static/help/manual.md` 로 받아 문서와 같은 markdown-it·박스글·표·코드 블록 꾸미기(`doc.js` 의 `decorateBlocks`)로 그린다. 본문은 `.md-body` 라 지금 문서 스타일·글자 크기를 따른다. 설명서 속 링크는 설명서 안의 제목(#…)으로만 간다 (다른 주소로 가면 앱 창이 떠난다).
- **덮는 화면**: `#lec-help` 는 `#lec-main` 전체(사이드바·문서·목차·터미널)를 덮는다 — 터미널 모음보다도 위. 문서 칸(탭)에 속하지 않으므로 폴더를 열기 전 시작 화면에서도 된다 (시작 화면에 '사용설명서' 버튼). 왼쪽은 장 목록(h2·h3, 읽는 곳 표시), 닫기는 F1·Esc·✕. 문서를 열거나 다른 탭을 고르면(`view`), 또 프로젝트 탭·목차·터미널·터미널 모음 버튼이나 `` Ctrl+` `` 를 누르면 닫힌다 — 가려진 화면이 바뀌어도 보이지 않으니.
- **찾기**: 설명서를 연 동안 Ctrl+F 는 설명서 안을 찾는다 — `find.js` 의 `setFindTarget({root, scroller})` 가 찾기 막대를 설명서로 옮기고, 닫으면 문서 화면으로 되돌린다. 찾기 칸에서 Esc 로 닫으면 초점을 본문(스크롤 상자)으로 돌린다 (숨은 칸에 초점이 남아 다음 Esc 가 칸으로 가던 것 — 문서 화면에서도 같다).
- **단축키 표**: `help.js` 의 `SHORTCUTS` 하나로 '?' 버튼의 표와 설명서의 '단축키' 장(`<!-- 단축키 표 -->` 자리)을 만든다 — 단축키를 더하면 여기에 넣는다. Ctrl+/ 로도 열고 닫는다. 묶음을 두 단으로 (단은 높이를 제한하면 옆으로 넘치므로 바깥 상자가 세로로 스크롤).
- **키**: F1·Ctrl+/ 는 터미널 안에서는 셸 것이다 (D38 — 본문을 누른 뒤에). 터미널 모음을 보는 중에도 칸 밖이면 된다. 설명서를 연 동안 ↑↓·PageUp·PageDown 은 장 하이라이트가 아니라 설명서를 넘긴다.
- **하지 않은 것**: 설명서를 별도 창이나 프로젝트 문서처럼 열기, 인터넷의 설명서(로컬 전용), 설명서 인쇄.

## D46. 영어 화면 (언어 설정)

- **결정 (사용자 요청, 2026-10-23)**: '한글 전용인데 English 로 옵션에서 선택하고 싶다' (v0.18.0). 사용자가 추천대로 고른 것: 범위는 전부(앱 화면·서버 문구·날짜·개수·스타일 이름·사용설명서 영어판·설치 프로그램), 기본은 자동(Windows 표시 언어), 용어표를 먼저 확인 — 표대로 승인, '모아 보기' = Elements, '장 하이라이트' = Focus, '문서 열기' = Quick open.
- **한국어 문장이 열쇠**: 코드에는 지금처럼 한국어 문장을 쓰고 `t('문서 열기')` 로 감싼다. 영어 사전이 그 문장을 영어로 바꾼다. 이름 열쇠(`toolbar.open`) 대신 이것을 고른 이유: 코드가 한국어 그대로 읽히고, 빠진 번역은 한국어로 보일 뿐 화면이 깨지지 않고, 600곳을 이름으로 바꾸는 공사가 없다. 값을 끼울 자리는 `{이름}`(`t('문서 {n}개', { n })`), 영어 복수형은 사전 값 `[하나, 여럿]`(n 이 1 이 아니면 뒤의 것, n 이 없으면 앞의 것).
- **언어는 서버가 정한다**: 설정 `language`(`auto`·`ko`·`en`, 기본 auto). auto 는 Windows 표시 언어 — `GetUserDefaultUILanguage` 가 한국어면 ko, 아니면 en (`i18n.system_language`). 서버가 `index.html` 의 `<html lang>` 에 넣고(`{{LANG}}`), 화면(`web/js/i18n.js`)은 그 값을 읽어 페이지 하나 동안 그대로 쓴다 — 그래서 모듈 맨 위 상수(스타일 이름·단축키 표 등)에도 `t()` 를 쓸 수 있다. 바꾸면 페이지를 다시 불러온다 (열린 탭·문서 위치·터미널 셸은 서버에 있어 그대로).
- **화면**: `t()`, `translatePage()`(index.html 의 글자와 title·placeholder·aria-label — `translate="no"` 안은 빼고), 사전 `web/js/lang/en.js`(JSON). 날짜는 'just now·5 min ago·yesterday·Oct 3', 개수는 단수·복수. 설정 창 맨 위에 '언어 · Language' — 제목과 언어 이름(한국어·English)은 번역하지 않는다 (다른 언어로 잘못 골라도 찾을 수 있게).
- **서버**: `lectern/i18n.py` 의 `t()`·`N_()`(모듈을 읽을 때 정하는 상수에 표시만)·`EN` — 화면에 나가는 오류·알림 문구 (API 오류, 탭 수 제한, 셸 오류, 설정 파일 오류 — 설정 파일 오류는 그 파일에 적힌 language 로).
- **사용설명서**: 영어판 `web/help/manual.en.md` (용어는 위 표대로). '단축키' 장은 두 판 모두 같은 `SHORTCUTS` 로 만든다.
- **설치 파일**: Inno Setup 에 영어를 더했다 — Windows 표시 언어가 한국어면 한국어, 영어면 영어, 둘 다 아니면 고른다. 탐색기 우클릭 메뉴 이름도 그 언어('Lectern으로 열기' / 'Open with Lectern'). `tools/context_menu.py` 도 Windows 표시 언어를 따른다.
- **지키는 법**: `tests/test_i18n.py` — JS·index.html·Python 의 한국어가 모두 `t()`(Python 은 `N_()` 도)로 감싸였는지, 영어 사전에 빠진 것·안 쓰는 것이 없는지. 템플릿 글자에는 한국어를 적지 않는다 (`${t('…')}` 로). 번역하지 않을 것(문서 내용을 읽는 정규식, 조사 고르기 인자, 개발용 로그·명령줄 도움말)은 그 줄에 `// i18n-ok`·`# i18n-ok`. ui_smoke 의 [영어 화면]은 영어로만 된 프로젝트를 English 로 열고 화면 곳곳(메뉴·검색·모아 보기·코드·설정·단축키·설명서·터미널 모음)을 연 뒤 앱 글자에 한글이 남았는지 찾는다.
- **그대로 둔 것**: 문서 내용·파일 이름, 터미널 안(셸이 쓰는 말), 개발 문서(README·docs·CLAUDE.md), 개발용 명령줄 도움말, 개발자 도구 로그.
- **주의**: `t()` 를 쓰는 모듈에서는 지역 변수 이름을 `t` 로 짓지 않는다 (함수가 가려진다 — 이번에 tabs·terminal·gather 등의 `t` 를 `tb`·`term` 등으로 바꿨다).

## D47. 목차 폭 조절과 글자 한 단계 크게

- **결정 (사용자 요청, 2026-10-23)**: '문서와 목차 크기를 마우스로 변경할 수 있도록, 문서의 폰트 크기를 한 단계 높여' (v0.19.0).
- **목차 폭**: 문서 칸과 목차 사이에 경계(`#lec-toc-resizer`)를 두고 끌어 목차 폭을 바꾼다 — 사이드바 폭 조절과 같은 방식(`resize.js` 가 둘을 함께 다룬다). 160~560px, 문서 칸은 360px 이상 남긴다. 설정 `toc_width` 에 저장, 두 번 누르면 기본(232px). 목차를 감추거나(목차 버튼·터미널) 좁은 창(1080px 이하)이라 목차가 없으면 경계도 없다.
- **글자 한 단계**: '한 단계'는 툴바 글자 크기의 다음 단계(100% → 110%)로 읽었다. 툴바에 보이는 배율은 그대로 두고, Lectern 스타일 문서(md·코드 화면·스타일 없는 html·사용설명서)에 곱하는 기준을 1.1 로 했다 (`textsize.js` 의 `BASE` — `--md-scale` = 툴바 배율 × 1.1). 그래서 툴바의 '100%' 가 예전 110% 크기이고, 이미 다른 배율을 쓰던 사람도 모두 한 단계씩 커진다. 단 폭도 같이 곱해져 줄 길이는 그대로다. 24종 스타일의 `--md-size` 를 하나하나 고치지 않은 것은, 스타일끼리의 크기 차이를 그대로 두고 한 곳에서 바꾸려고.
- **그대로 둔 것**: 문서가 스타일을 정한 html 보고서는 그 문서가 정한 크기 (툴바 배율만 zoom 으로). 앱 UI 글자는 그대로.

## D49. 제외 폴더를 '자료' 목록에

- **결정 (사용자 요청, 2026-10-24)**: '자료에는 문서, 코드 이외의 모든 파일을 볼 수 있으면 좋겠다' (v0.20.0). 빠져 있던 것은 둘이었다 — 제외 폴더(`dist`·`build`·`node_modules`·`venv`·`__pycache__` 등과 설정 `exclude_dirs`)와 숨김(`.`으로 시작·숨김 속성). 사용자가 추천대로 고른 것: 제외 폴더만 '자료'에 흐리게, 접힌 채로, 펼칠 때 안을 읽는다. 숨김은 그대로 숨긴다 (원칙 3·4 — 서버가 숨김 경로를 404 로 막는 것도 그대로).
- **접힌 노드**: `scan_others` 는 제외 폴더 안을 훑지 않고 `{type:'dir', children: null, excluded: true}` 로만 싣는다 — 안이 비었는지도 보지 않는다 (비어 있어도 나온다). `node_modules` 처럼 파일이 수만 개인 폴더를 목록을 읽을 때마다 훑지 않으려고. 파일 수(머리줄 개수·5000개 한도)에도 넣지 않는다.
- **펼칠 때 한 단계씩**: `GET /api/others/dir?p=&path=` → `list_dir` 가 그 폴더의 바로 안만 읽는다 (숨김·링크는 빼고, 하위 폴더는 다시 접힌 노드, 항목 5000개까지 — `MAX_DIR_ENTRIES`). 제외 폴더 안이 아닌 경로는 400 (그 밖은 `/api/others` 가 이미 싣는다), 숨김·밖·폴더가 아닌 경로는 404. 화면은 받은 것을 탭에 두고(`tab.others.lazy`) 목록을 다시 읽어도 붙여 쓴다. 접으면 버리고 다시 펼치면 새로 읽는다 — 감시가 제외 폴더 안을 보지 않으므로 이것이 그 안을 새로 보는 방법이다 (F5 도).
- **안은 종류를 나누지 않는다**: 제외 폴더 안의 것은 문서·코드도 모두 '자료'에 둔다 (폴더 보기에서는 합친 트리에). 코드 파일은 한 번 누르면 읽기 화면, 그 밖은 두 번 누르면 `osutil.open_path` (실행하지 않음) — 다른 자료와 같다. 사이드바 거르기는 제외 폴더 안을 찾지 않는다 (읽어 둔 것만 찾으면 펼친 적이 있는지에 따라 결과가 달라진다).
- **감시**: 제외 폴더 안의 변경은 그대로 버리고, 제외 폴더 자체가 생기거나 지워지면(`build` 를 지우고 다시 만드는 빌드 등) `others` 로 남긴다 — '자료'에 바로 나오고 사라진다. 폴링 대체도 제외 폴더 경로를 함께 비교한다.
- **흐리게**: 행의 아이콘·이름을 60% 로 (`.row.excluded`) — 제외 폴더와 그 안. 마우스를 올리면 '제외 폴더 — 펼칠 때 안을 읽습니다. 문서 트리와 검색에는 나오지 않습니다.'
- **그대로 둔 것**: 문서 트리·전체 검색·Ctrl+P·모아 보기·'코드' 목록에는 제외 폴더가 여전히 없다. 설정 `exclude_dirs` 의 뜻도 그대로('문서 트리에서 뺄 폴더' — 이제 '자료'에는 접혀 나온다).

## D50. 코드·자료의 최근 변경·이름 검색·파일 종류

- **결정 (사용자 요청, 2026-10-24)**: '문서에서 최근 변경, 검색, 모아보기가 가능하다 — 코드와 자료도 파일 단위로 최근 변경, 검색(파일 이름), 모아보기(엑셀/ppt/pdf/png…, py, ipynb, js…)를' (v0.21.0). 배치는 세 안(세 탭에 범위 버튼 / 파일 탭의 묶음 안에서 / 섞어서) 가운데 사용자가 추천대로 **세 탭에 범위 버튼**을 골랐다 — 하는 일마다 한 곳이고 사이드바 탭 수는 그대로다.
- **최근 변경**: 탭 위에 '문서'·'코드'·'자료' 버튼(설정 `recent_docs`·`recent_code`·`recent_others`, 모두 기본 켜짐). 켠 종류를 섞어 최근 것부터 50개. 문서는 트리의 수정 시각(문서를 고치면 트리를 새로 받는다), 코드·자료는 `GET /api/others/recent` — 서버가 '자료'·'코드' 목록의 스캔(`scan_others`)을 쓰되, 그 뒤로 내용이 바뀐 파일만 수정 시각을 새로 읽는다. 목록은 이 탭이 보일 때만 받는다 (`recent.js` — 최근 변경 목록을 `tree.js` 에서 떼어 냈다).
- **문서 외 파일의 내용 수정 (touch)**: D36 은 문서 외 파일의 내용 수정을 버렸다 (소스를 고칠 때마다 목록을 다시 읽지 않게). 이제 감시가 그것을 `ChangeLog.touch(경로)` 로 남긴다 — 순번은 늘지만 `others_seq` 는 그대로라 '코드'·'자료' 목록은 다시 훑지 않고, `/api/changes` 의 `touched` 로 화면의 최근 변경만 다시 받는다. 폴링 대체도 문서 외 파일의 수정 시각을 비교한다. 문서 트리 스캔 캐시는 touch 가 아닌 마지막 순번(`tree_seq`)을 본다 — 코드를 고칠 때마다 검색이 문서 트리를 다시 훑지 않게. 기억하는 경로는 5000개까지 (넘으면 오래된 것부터 — 그 파일은 다음 스캔까지 옛 수정 시각).
- **검색**: '자료' 버튼을 더했다 (설정 `search_others`). 맨 위에 '이름이 맞는 파일' — 켠 종류에서 이름(문서는 제목도)에 검색어가 든 파일, 이름이 검색어로 시작하는 것 먼저·그다음 최근에 고친 순, 100개까지. 그 아래는 지금처럼 본문 결과 (자료는 본문을 찾지 않는다 — PDF·엑셀은 글자로 읽을 수 없다). 이름은 화면이 트리와 '자료'·'코드' 목록에서 찾는다 (서버에 묻지 않는다). Enter 는 본문 결과가 있으면 첫 결과로, 이름만 맞으면 첫 파일에 초점.
- **모아 보기**: 위에 '문서 속 요소' / '파일 종류'. 파일 종류는 범위 안의 파일을 묶음(문서·코드·자료)마다 형식별 버튼으로 — 엑셀(xls·xlsx·xlsm·xlsb)·파워포인트·워드·한글은 한 이름, 나머지는 확장자를 대문자로 (`icons.js` 의 `fileType`). 고르면 그 형식의 파일 목록(트리 순서 / 최근 수정 순, 거르기는 이름·경로), 그림 파일(png·jpg·gif·webp·bmp·svg·ico·avif)은 작은 그림 격자. 처음 고른 형식이 없으면 자료 → 코드 → 문서 순으로 가장 많은 것. 범위는 문서 속 요소와 같고, '코드'·'자료' 목록의 폴더 우클릭 '이 폴더의 파일을 종류별로 모아 보기'로 그 폴더만.
- **행 동작은 '코드'·'자료' 목록과 같게** (`others.js` 의 `bindFileRows`): 문서는 한 번 누르면 뷰어, 코드는 한 번 누르면 읽기 화면·두 번 누르면 편집기, 자료는 두 번 누르거나 Enter 로 연다 (실행·압축 파일은 탐색기에서 선택만 — `osutil.open_path`). 한 번 누르기로 자료를 열지 않는 것은 실수로 엑셀 같은 앱이 뜨지 않게. 우클릭은 그 목록과 같은 메뉴.
- **넣지 않은 것**: 제외 폴더(D49) 안의 파일 — 세지도 찾지도 않는다. 자료의 본문 검색(PDF·오피스 글자 읽기는 새 의존성이 필요하다).

## D51. 우클릭 메뉴에서 터미널에 붙여 넣기

- **결정 (사용자 요청, 2026-10-24)**: '선택된 영역, 선택 경로 등을 터미널에 복사 붙이기' (v0.22.0). D38 은 '문서·링크·다른 기능이 셸로 명령을 보내는 길은 만들지 않는다'였다 — 이것을 **사용자가 우클릭 메뉴에서 고른 글만, Enter 없이**로 넓힌다. 문서나 링크가 스스로 셸에 글을 보내는 길은 여전히 없다.
- **모양**: 우클릭 메뉴의 복사 항목 옆에 터미널 버튼(`.menu-term`) — 메뉴가 길어지지 않고, 복사할 수 있는 것은 모두 터미널에도 넣을 수 있다. 붙는 항목: 선택한 글, Claude용 위치(`@경로 40~52행`), 원문·절 원문, 텍스트, 코드, 링크 주소, 코드 화면의 이 줄, `@경로`, 전체 경로, 파일 이름 (문서 본문·코드 화면·트리·'코드'·'자료' 목록·최근 변경·검색·모아 보기). 표·그림·다이어그램·LaTeX 는 붙이지 않는다. 경로·위치는 끝에 공백을 붙이고(이어서 치도록), 공백이 든 전체 경로·파일 이름은 따옴표로 감싼다.
- **넣는 길**: 사용자의 Ctrl+V 와 같다 — xterm 의 `paste` 가 줄바꿈을 CR 로 바꾸고, 받는 프로그램이 붙여넣기 모드(bracketed paste)를 켰으면 감싸서 `onData` → `POST /api/term/input`. 서버 API 는 그대로다 (셸에 글자를 보내는 API 는 여전히 하나). 끝의 줄바꿈은 떼어 Enter 를 누르지 않는다.
- **여러 줄**: 사용자가 고른 대로 Windows Terminal 처럼 한 번 묻는다 — 셸 프롬프트(PowerShell)에서는 줄마다 명령으로 실행될 수 있어서. 받는 프로그램이 붙여넣기 모드를 켜 두었으면(Claude Code 등 — xterm 의 `modes.bracketedPasteMode`) 줄바꿈이 실행되지 않으므로 묻지 않는다.
- **터미널**: 그 프로젝트 탭의 터미널로 넣는다. 닫혀 있으면 열고 셸을 띄운다. 넣은 뒤 초점은 터미널로. 셸이 끝나 있으면 넣지 않고 알린다.
- **그대로 둔 것**: 터미널 안의 Ctrl+V·우클릭 붙여 넣기는 지금처럼 묻지 않는다.

## D52. 터미널 자리 — 오른쪽 / 아래 (자동은 창 모양)

- **결정 (사용자 요청, 2026-10-24)**: '모니터가 가로일 때 문서와 터미널을 수평으로, 세로일 때 수직으로 자동 변경 (기본은 자동, 선택은 수동)' (v0.23.0). 무엇을 보고 바꿀지는 사용자가 추천대로 **창 모양**을 골랐다 — 창이 세로로 길면(높이 ≥ 폭, CSS `orientation: portrait`) 아래. 세로 모니터에 최대화한 창은 물론, 가로 모니터에서 반쪽으로 붙인 창도 위아래가 된다. 창 크기가 바뀌면 그때 바뀐다 (`matchMedia` 의 change).
- **설정**: `terminal_position` — `auto`(기본) · `side` · `bottom`. 설정 창의 '터미널 자리'와 터미널 머리줄의 버튼(오른쪽 ↔ 아래 — 누르면 그 자리로 고정되고, 자동은 설정 창에서 되돌린다).
- **아래일 때**: `html.term-bottom` 이면 `#lec-main` 이 격자가 된다 — 위 줄에 사이드바·문서·목차, 그 아래 경계와 터미널이 사이드바를 뺀 전체 폭. DOM 은 그대로라 터미널 화면·셸이 이어진다. 목차는 가리지 않는다 (오른쪽 터미널만 목차 자리를 쓴다). 경계를 끌어 높이(`terminal_height`, 120px 이상, 문서는 160px 남김), 두 번 누르면 기본(40%).
- **그대로 둔 것**: 터미널 모음(D40)은 자리와 상관없이 문서 화면 위를 덮는다. 오른쪽일 때의 폭(`terminal_width`)은 따로 기억한다.

## D53. 내 스타일 (사용자 CSS)과 AI 용 설명서

- **결정 (사용자 요청, 2026-10-24)**: '사용자 스타일 작성 기능 — 클로드 코드 등 AI 가 작성하기 위한 자세한 설명서 포함' (v0.24.0). '하지 않기로 한 것'의 '사용자 테마 폴더 자동 스캔'을 사용자가 다시 요청했다. 둘 곳은 추천대로 **설정 폴더** `%APPDATA%\Lectern\styles` — 어느 프로젝트를 열든 스타일 목록에 나온다.
- **Lectern 은 읽기만**: 스타일 파일을 만들거나 고치는 것은 사용자나 AI 다. 앱이 쓰는 것은 설정 창의 '스타일 폴더 열기'가 폴더가 없을 때 만드는 빈 폴더 하나뿐 (원칙 1 의 config.json 옆).
- **파일 하나 = 스타일 하나**: 맨 앞 머리 주석 `/* lectern-style … */` 에 `name`·`dark`·`base`. `base` 는 바탕으로 깔 기본 스타일 — 그 css 를 `#lec-theme-css` 로 먼저 입히고 내 파일을 `#lec-user-css` 로 얹는다. 그래서 바꿀 변수만 적어도 된다. `dark` 는 앱 UI·highlight.js·터미널 색표·Mermaid 를 어둡게 (`data-ui`). 다이어그램 색은 그 스타일의 CSS 변수(`--md-bg`·`--md-th-bg`·`--md-heading`·`--md-code-bg`·`--md-muted`·`--md-fg`)에서 만든다 (`theme.js` 의 `mermaidFromCss`).
- **바로 반영**: 화면이 3초마다 `GET /api/styles` 로 목록(이름·수정 시각)을 받는다. 새 파일은 목록 맨 아래 '내 스타일' 묶음에, 고른 스타일의 파일이 고쳐지면 다시 입히고 다시 그린다 — AI 가 저장할 때마다 사용자가 바로 본다. 파일을 지우면 기본 스타일로.
- **로컬 전용 지키기**: 서버가 내보낼 때(`/userstyle/<파일>`, `styles.sanitize_css`) `@import`, `data:` 가 아닌 `url()`, `image-set()` 을 지운다. CSS 이스케이프로 숨긴 글자(`\75 rl(`·`u\rl(`)는 왼쪽부터 한 번에 먼저 풀고(`\\` 는 한 묶음), 그래도 이스케이프를 다 지우고 보면 숨긴 주소가 남는 스타일은 통째로 쓰지 않는다 (빈 css). 앱 페이지(`/`)의 CSP 에 `style-src 'self' 'unsafe-inline'` 을 더해 인터넷의 css 를 `@import` 하는 길도 막는다 (글꼴은 원래 `font-src 'self'`). 그림은 설정 `external_images` 를 따르므로 거르기가 지킨다. (v0.25.0 점검에서 검토자가 `\\u\\r\\l(` 처럼 숨긴 주소가 빠져나가는 것을 찾아 고쳤다.) 1MB 넘는 파일·하위 폴더·숨김·링크는 읽지 않는다.
- **AI 용 설명서**: `web/help/styles.md`(영어판 `styles.en.md`) — 저장할 곳, 머리 주석, 변수 표, 규칙을 적을 수 있는 구조(선택자 표)와 건드리지 말 것(`lec-*`), 지킬 것(인터넷 금지, PC 글꼴, `--md-scale`, 대비 4.5:1, dark), 예시 둘, 확인 순서. 설치 폴더에 함께 들어가므로 설정 창의 'Claude Code용 요청 복사'가 그 전체 경로와 스타일 폴더 경로를 적은 요청 글(원하는 모양은 사용자가 이어서)을 복사한다. 옆의 터미널 버튼은 그 글을 터미널에 넣는다 (D51).
- **그대로 둔 것**: 기본 스타일 24종과 묶는 방식. 내 스타일은 어느 묶는 방식에서나 맨 아래 '내 스타일' 묶음이다.

## D54. 편집 모드 — 보기 전용의 예외

- **결정 (사용자 요청, 2026-10-24)**: '아주 간단한 문서편집기 — 문서와 코드를 읽고 있을 때 간단한 편집 모드로 변경' (v0.25.0). D1 의 '문서 편집·저장'('하지 않기로 한 것')을 사용자가 다시 요청했다. 편집기는 사용자가 **코드 편집기 라이브러리**를 골랐다 (추천은 단순한 글 칸이었다) — 줄 번호·언어 색·괄호 맞춤·찾아 바꾸기.
- **원칙 1 의 예외**: 사용자가 편집 모드에서 저장할 때만 그 파일 하나에 쓴다. 이미 있는 문서(md·html)와 코드 파일만 — 새로 만들기·이름 바꾸기·지우기는 여전히 없다. 프로젝트 밖·숨김은 `resolve_inside` 가 막고, 문서가 스크립트로 저장을 부를 길은 없다 (스크립트가 돌지 않는다 — D27·D38, POST 는 토큰·JSON).
- **CodeMirror 5** (`web/vendor/codemirror`, `tools/update_vendor.py`): 6 은 ES 모듈을 묶는 도구(번들러)가 있어야 해서 원칙 6 에 맞지 않는다. 5 는 스크립트 파일 그대로 쓸 수 있다. 처음 편집할 때 불러오고(터미널의 xterm 처럼), 언어는 확장자에 맞는 모드 파일만. 색은 문서 스타일(`--md-*`)에서, 어두운 스타일은 글자색을 One Dark 계열로.
- **모양**: 칸 위를 덮는 편집 상자 — 아래의 문서 화면은 그대로 두어, 저장하면 자동 새로고침이 그 아래를 다시 그리고 닫으면 고친 결과가 보인다. 여는 곳은 탭 막대 오른쪽 끝의 [편집] 버튼(켜기/끄기 — 사용자 요청으로 v0.25.2 에 더함, 화면 순서대로 [편집] [목차] [터미널]), 상태줄의 '편집', 코드 화면 머리줄의 '편집', 우클릭 '이 문서 편집'·'여기를 편집'(그 블록·줄에서), Ctrl+E. 줄을 주지 않으면 읽던 곳의 원문 줄에서 연다 (D55). Ctrl+S 저장, Esc 닫기, Ctrl+F·Ctrl+H·Alt+G 는 편집기의 찾기·바꾸기·줄로 가기 (편집 상자 안의 키는 편집기 것 — 탭 옮기기·Ctrl+E·Ctrl+P·도움말만 앱이).
- **안전**: 원문(`GET /api/source`)은 LF 로 주고, 저장(`POST /api/save`) 때 그 파일의 줄바꿈(섞여 있으면 많은 쪽)·BOM 을 되살린다. UTF-8 글 파일만(D1), 2MB 까지, 읽기 전용 파일은 고치지 않는다. 원문을 줄 때의 내용(SHA-256)과 지금 파일의 내용이 다르면(그사이 Claude Code 등이 고침) 409 — 화면이 물어서 덮어쓰거나(force) 편집을 이어 간다. 처음엔 수정 시각·크기로 보았으나, 같은 순간에 같은 크기로 바뀐 것을 놓쳐(점검 중 테스트가 가끔 실패) 내용으로 바꿨다. 같은 폴더의 짧은 이름의 임시 파일(`.lectern-….tmp`)에 다 쓴 뒤 Windows `ReplaceFileW` 로 바꿔 끼운다 — 원래 파일의 속성(숨김 등)·만든 시각·ACL 이 남는다 (`os.replace` 는 이것들을 잃었다). 바꿔 끼울 수 없으면 조금 기다려 다시, 그래도 안 되면 그 자리에 쓴다. 원래 자리에 새 내용이 들어갔는지 확인하기 전에는 임시 파일을 지우지 않는다 — 저장이 끝내 안 되면 오류에 그 임시 파일의 경로를 알린다. 저장하지 않은 편집은 다른 화면으로 가기·편집 닫기·탭 닫기(다른 물음 뒤 마지막에, 탭이 실제로 닫힌 뒤에 치운다)·언어나 인터넷 그림 설정을 바꿔 다시 불러오기 전에 묻고, 창을 닫을 때는 서버가 묻는다(화면이 `POST /api/editing` 으로 목록을 알려 두고, `app.py` 의 closing 처리기가 Windows 메시지 상자로).
- **그 밖에 점검에서 고친 것**: 다른 화면을 그리는 중에는 편집을 열지 않는다(떠날 화면에 열리던 것), 크기·글자 크기·스타일이 바뀌면 CodeMirror 를 다시 잰다(커서 자리 어긋남), 편집 상자 안의 우클릭은 아래 화면의 메뉴를 띄우지 않는다, 저장하지 않은 목록은 차례대로·다시 보내고 화면을 다시 불러오면 서버가 비운다.
- **그대로 둔 것**: '편집기로 열기'(VS Code 등)는 그대로다. 자료(PDF·엑셀 등)는 편집하지 않는다. (v0.25 에는 편집하는 동안 목차·같은 파일의 검색 결과를 누르면 편집 상자 아래의 화면만 움직였다 — v0.26.0 에 편집기가 그 줄로 가게 고쳤다, D55.)

## D55. 편집 모드의 위치 잇기 — 읽는 화면·편집기·목차

- **결정 (사용자 요청, 2026-10-24)**: '문서 읽는 위치, 편집 위치, 목차 선택을 연동' (v0.26.0). 편집 상자는 칸 위를 덮는 그대로다 (D54) — 편집기와 미리 보기를 나란히 두는 화면은 만들지 않는다 (원칙 6, 읽기와 편집을 [편집]으로 오가는 지금 방식에 맞춘다).
- **어떻게** (`web/js/editsync.js` 가 계산, `editor.js` 가 잇는다): 읽는 화면의 블록은 원문 줄 범위를 안다 — md 의 `data-lines`, 코드 화면의 줄. 편집기의 '지금 보는 곳'(커서가 화면 안이면 커서, 아니면 화면 맨 위에서 40px 아래)의 원문 자리를 읽는 화면에서 찾아, 같은 높이에 오게 아래 화면을 스크롤해 둔다 (블록 안·블록과 블록 사이는 줄 수에 맞춰 높이를 나눈다). 그래서 목차의 '지금 읽는 위치'(편집 중에는 그 자리가 든 절 — `pane.tocLimit`)와 마지막 위치 기억(position.js)이 저절로 따라오고, 닫으면 읽는 화면이 이미 편집하던 곳에 있다 (접힌 절 안이면 펴고, 장 하이라이트도 그 장으로 — `unfoldTo`). 열 때는 거꾸로, 읽던 곳의 원문 줄이 편집기의 같은 높이에 온다.
- **목차·모아 보기·검색**: 편집 중에 목차(제목·구성 요소)·모아 보기·검색 결과(편집 중인 파일의 것)를 고르면 편집기가 그 줄로 가서 잠깐 표시한다 (`toc.js` 의 `setEditJump`, 검색은 'edit' 이벤트 {line}).
- **줄이 늘거나 줄면**: 읽는 화면은 마지막으로 그린 원문의 줄이다. 편집기의 바뀐 곳 가운데 줄 수가 바뀐 것만 기록해 두고(`logChange`) 줄 번호를 옮긴다(`toEditor`·`toView`). 저장한 것을 화면이 다시 그리면(`rendered` 이벤트) 그 저장까지의 기록을 버린다. 블록마다 CodeMirror 책갈피를 다는 방법은 블록이 많은 문서에서 무겁고 다시 그릴 때마다 새로 달아야 해서 쓰지 않았다.
- **html 문서**: 블록의 원문 줄을 모르므로 제목만 잇는다 — 원문에서 n 번째 `<h1>`~`<h6>` 태그(주석과 script·style·textarea·title·template 안은 뺀다)의 줄 = 화면의 n 번째 제목. 제목과 제목 사이는 줄 수에 맞춰 나눈다. 원문과 화면의 제목 수가 다르면 그 뒤로 조금 어긋날 수 있다.
- **그대로 둔 것**: 편집하는 동안 앱의 문서에서 찾기·바뀐 곳·장 하이라이트의 ↑↓ 는 편집기를 옮기지 않는다 (아래 화면만 움직이고, 편집기를 움직이면 다시 편집기에 맞춘다). 줄 번호가 없는 검색 결과도 그렇다.

## D56. 차트 — Vega-Lite·ECharts·Plotly·Graphviz

- **결정 (사용자 요청, 2026-10-24)**: 'Mermaid 이외에 쓸 수 있는 도해·차트 라이브러리' 를 물은 뒤 추천 1·2·3 — Vega-Lite(데이터 차트), Graphviz(구성도·의존 관계), ECharts(종류가 많은 차트)를 넣기로 (v0.27.0). 코드 블록 언어는 `vega-lite`(`vegalite`)·`vega`·`echarts`·`dot`(`graphviz`). Mermaid 12.1 에도 xychart·pie·sankey 등 간단한 차트가 있어 설명서·예제에 함께 적었다. 이어서 사용자 요청으로 Plotly 를 더했다 (```plotly, v0.28.0) — 나눈 판(기본 1.2MB·2D 1.5MB) 대신 사용자가 **전체판**(`plotly.js-dist-min` 4.1.2, 4.8MB)을 골랐다: Claude 가 쓴 Plotly 설정(Python 의 `fig.to_json()` 포함)이 종류 때문에 막히지 않게.
- **라이브러리**: `vega` 6.4·`vega-lite` 6.5·`echarts` 6.1·`@viz-js/viz` 3.31 (Graphviz 를 WebAssembly 로, 파일 하나) — 모두 묶는 도구 없이 쓰는 UMD 판이 있다 (원칙 6). `web/vendor` 에 넣고(`tools/update_vendor.py`) 그 차트가 있는 문서를 처음 그릴 때 불러온다 (약 3.2MB). WebAssembly 는 `/` 의 CSP 의 `'unsafe-eval'`(D38)로 돈다. Viz.js 패키지에는 라이선스 파일이 없어 Viz.js(MIT)·Graphviz(EPL-2.0)·Expat(MIT) 전문을 `tools/vendor-licenses` 에 두고 받을 때 함께 넣는다. ECharts(Apache-2.0)는 NOTICE 도 함께 둔다.
- **움직이지 않는 SVG**: 모두 SVG 글자로 그린다 (Vega `toSVG`, ECharts 서버 그리기 모드, Plotly `toImage` 의 svg, Viz.js). 인쇄·우클릭 '그림 복사'(PNG)·눌러서 크게 보기·목차와 모아 보기의 '다이어그램'이 Mermaid 와 같게 된다. 마우스를 올려 값 보기·확대 같은 움직임은 하지 않았다 — 라이브러리가 문서 안에서 이벤트를 다루게 되고, 읽는 앱에는 그림이면 충분하다.
- **문서가 할 수 있는 것을 늘리지 않는다**: 설정은 JSON 으로만 읽는다. ECharts 예제처럼 따옴표 없는 키·작은따옴표·주석·끝 쉼표·`option =` 은 읽지만(`parseSpec` — 직접 만든 작은 읽개), 함수는 오류다 (`eval` 하지 않는다 — D27 과 같은 까닭). 라이브러리가 만든 SVG 도 문서처럼 DOMPurify 와 그림 주소 훅을 거친다 — 차트 설정으로 인터넷 그림(ECharts `graphic`·Vega `image`)이나 링크(Vega `href`·Graphviz `URL`)를 넣을 수 있기 때문이다. 링크는 푼다 (`bindLink` 가 보지 못한 링크를 누르면 앱 창이 떠난다). ECharts·Plotly 는 그리는 동안 그림을 직접 불러오므로(그린 뒤 거르기로는 늦다) 그리기 전에 설정에서 data: 가 아닌 그림 주소를 지운다 — ECharts 는 `image` 키와 'image://' 기호를 설정 끝까지(`dropImages`), Plotly 는 `layout.images`·image 종류의 `source`. Plotly 의 지도 종류(scattergeo·choropleth·…mapbox·…map)는 인터넷에서 나라 경계·지도 타일을 받아야 해서 까닭을 보이고 그리지 않는다. Vega 는 데이터를 못 읽어도 빈 그림을 그리므로, 오류·'Loading failed' 기록을 모아 두었다가 그림 대신 원문과 까닭을 보인다. Vega 의 `data.url` 은 문서 기준 상대경로로 이 프로젝트 안의 파일만 읽는다 (`resolveRef` — 인터넷 주소는 오류, 놓쳐도 CSP `connect-src 'self'` 가 막는다).
- **색·글꼴·크기**: 색은 Mermaid 와 같은 스타일 색표(`mermaidTheme()` — 내 스타일이면 CSS 변수)에서 Vega config·ECharts 테마를 만든다. 스타일을 바꾸면 문서를 다시 그리므로 따라온다. 글꼴은 앱 글꼴, 글자는 라이브러리 기본보다 조금 크게. ECharts 는 바탕을 문서 바탕색으로 칠한다 — 비우면 밝은 바탕으로 보고 바깥 이름표에 흰 테두리를 둘렀다. 글꼴 목록에 큰따옴표가 있으면 ECharts 가 만든 style 속성이 깨져서 작은따옴표로 준다. Graphviz 는 글꼴 없이 글자 폭을 어림해 배치하는데 기본 Times 로 어림하면 한글이 상자보다 넓어져서, Verdana 로 어림하고 앱 글꼴로 그린다. 기본 검정·흰 바탕은 스타일 색으로 바꾸고, 채운 상자 안의 글자는 채움의 밝기에 맞춘다.
- **폭**: ECharts·Plotly 와 `width: "container"` 인 Vega-Lite 는 문서 폭으로 그린다. 문서는 화면 밖 무대에서 그린 뒤 목차가 나오며 좁아지므로, 그린 폭과 보이는 폭이 16px 넘게 다르면 다시 그린다 (ResizeObserver — 사이드바·터미널·창 크기에도). 줄여서 보이면 글자가 작아지기 때문이다. ECharts 의 높이는 설정의 `height`(ECharts 에는 없는 키, 기본 360), Plotly 는 `layout.height`(기본 400). Plotly 의 색은 설정에 `layout.template` 이 없을 때만 스타일 색으로 (있으면 — Python 의 fig.to_json() 처럼 — 그것).
- **그대로 둔 것**: JS 차트가 든 html 보고서는 여전히 그려지지 않는다 (스크립트를 돌리지 않는다 — D27). 어두운 스타일에서 인쇄하면 차트는 그 스타일 색 그대로다 (Mermaid 도 같다). 차트를 고친 CSV 는 문서를 다시 그릴 때 반영된다 (자료 파일의 수정은 문서 변경으로 오지 않는다 — D50).

- **그대로 둔 것**: 예제를 사용자 문서 폴더로 복사하는 것은 하지 않았다 (앱이 사용자 파일을 만들게 된다). 둘러보기의 영어판은 나중에.

## D58. 시작하다 멈춘 프로그램 알림 — 터미널

- **결정 (사용자 요청, 2026-10-24)**: 'Lectern 터미널에서 Claude 실행 중에 터미널이 멈췄는데 같은 현상이 또' — 점검하니 Lectern 탓이 아니라 PC 의 보안 프로그램(Fasoo DRM 의 커널 드라이버)이 프로세스 생성을 막은 것이었다. 고를 것 셋(Lectern 이 알아채 알림·IT 에 예외 요청·그대로) 가운데 사용자가 '1번'을 골랐다.
- **본 모양** (두 번 모두 같았다): Claude Code 가 띄운 `git.exe` 가 스레드 하나만 일시 정지(대기 이유 Suspended)로 남고, 모듈 0개(로더가 한 번도 돌지 않음)·CPU 0. 그 핸들에서는 종료·일시 정지 풀기·핸들 복제 권한이 깎여 있다. Claude Code 의 주 스레드는 `CreateProcessW` 안에서 끝없이 기다려 키 입력도 받지 않는다 — 사용자에게는 '터미널이 멈춤'으로 보인다. Lectern 의 작업 개체는 `KILL_ON_JOB_CLOSE` 만 있어(메모리 제한 등 없음) 원인이 아니다. 작업 개체째 끝내는 것(다시 시작)은 핸들 권한과 상관없이 된다.
- **알아채기** (`conpty.PseudoConsole.stuck_children`, 읽기만 한다): 셸에서 프로그램이 돌 때만 3초마다(`terminal.STUCK_CHECK`) 작업 개체 안의 프로세스(`JobObjectBasicProcessIdList`)를 보고, 셸이 아닌 것 가운데 ① 만들어진 지 10초(`STUCK_AFTER`)가 넘었고 ② 로더가 돌지 않았고(`EnumProcessModulesEx` 가 `ERROR_PARTIAL_COPY` — PEB 의 모듈 목록이 아직 없음) ③ 스레드가 모두 일시 정지(`NtQuerySystemInformation` 의 프로세스·스레드 목록)인 것. 로더가 돈 것을 본 프로세스는 다시 열어 보지 않는다. 셋을 다 보는 것은 디버거가 멈춰 둔 프로그램·막 시작하는 프로그램을 멈춘 것으로 보지 않으려고. 바뀌면 기다리는 긴 폴링(`/api/term/read`)을 깨워 `stuck: [{pid, name}]` 로 알리고, `/api/term/info` 에도 싣는다.
- **보이기**: 터미널 머리줄 아래 붉은 띠(무엇이 멈췄는지·까닭·다시 시작하면 무엇이 끝나는지·`claude --continue`)와 띠의 **다시 시작**, 머리줄 ↻ 강조. 보이지 않는 탭의 터미널이면 알림을 한 번. 터미널 모음 칸 머리에 '멈춤'과 ↻ 강조.
- **스스로 끝내지 않는다**: 멈춘 것만 따로 끝낼 수 없고(종료 권한이 깎임), 다시 시작은 셸과 거기서 돈 것을 모두 끝내므로 사용자가 고른다. 셸에 명령을 보내지도 않는다 (D38).
- **그대로 둔 것**: 보안 프로그램이 막는 것 자체는 Lectern 이 풀 수 없다 — 잦으면 IT 에 Claude Code·git 의 예외를 요청하는 것이 근본 해결이다. 터미널 밖(Windows Terminal 등)에서 돌린 Claude Code 는 보지 않는다.

## D59. 발표 문서 — Marp 형식의 md 를 슬라이드로

- **결정 (사용자 요청, 2026-10-24)**: 'presentation 형태의 md 도 지원할 수 있을까 — 지금 쓰는 다이어그램·차트도 쓸 수 있으면' (v0.31.0). 이 PC 에 Claude Code 가 쓴 Marp 덱(`marp: true`, Mermaid 포함)이 있었고, 지금 Lectern 은 그것을 긴 문서 한 편(맨 위에 Marp 설정 표, 슬라이드 사이는 가로줄)으로 보였다. 고를 것 넷(A. Lectern 자체 슬라이드, B. A + reveal.js 발표, C. Marp 그대로 — marp-core, D. 문서 그대로 + 구분만) 가운데 사용자가 **A** 와 발표 모드·인쇄 한 장에 한 쪽·`style:` CSS 를, 알아볼 파일은 **`marp: true` 만**을 골랐다. '넘치면 글까지 줄여 맞춤'은 고르지 않았다 — 글은 Marp 처럼 잘리고 '넘침'을 표시한다.
- **왜 자체 렌더러인가**: 슬라이드를 문서와 같은 렌더러(markdown.js·doc.js)로 그리면 Mermaid·차트(D56)·수식·코드 색·표·박스글·경로 링크·우클릭 원문 복사·편집 위치 잇기(D55)가 그대로 된다 — Marp 자체는 Mermaid·차트를 그리지 못한다. 새 라이브러리가 없다 (원칙 2·6). marp-core 는 브라우저판이 없어(CommonJS, MathJax·postcss) 묶는 도구로 만들어 넣어야 하고, 자기 markdown-it 이라 Lectern 의 기능을 다시 붙여야 했다. reveal.js(약 170KB)는 테마에 웹 글꼴이 들어 있고(D26) 키보드를 직접 잡는다.
- **나누기**: markdown-it core 규칙(`slideRule`)이 맨 위 수준의 줄(`---`)마다 토큰을 감싼다 — DOM 을 나중에 쪼개는 것보다 원문 줄 범위(`data-lines`)·지시어 주석을 그 자리에서 다룰 수 있다. HTML 주석 블록은 모든 줄이 Marp 지시어면 지시어(맨 앞 설정 → 주석은 그 장부터 → `_` 는 그 장만), 아니면 발표자 노트 (Marp 와 같다).
- **크기**: Marp 처럼 1280×720 에 그리고(작성자의 `style:` px 값이 Marp 에서와 같은 크기로 보이게) 화면 폭에 맞춰 transform 으로 줄인다. 글자는 본문 × 1.8. Mermaid·차트는 자기 글자(12~16px)로 그리므로 그대로 두면 슬라이드에서 읽을 수 없을 만큼 작다 — Mermaid 는 최대 폭을 1.7배로, 차트는 폭 ÷ 1.7 로 그려 키운다 (`SLIDE_ZOOM`). 화면 밖 무대에서는 줄이지 않는다 (Mermaid 가 글자 크기를 transform 된 크기로 재면 상자보다 글자가 커진다).
- **넘침**: 넘치는 슬라이드는 큰 그림·다이어그램·차트부터 남은 높이에 맞춰 줄이고(최소 슬라이드 높이의 30%), 그래도 넘치면 아래가 잘리고 틀에 '넘침'. AI 가 쓴 덱은 자주 넘친다 — 작성 안내(`writing.md`)에 '한 장에 제목 하나와 짧은 글머리표 대여섯 줄'을 적었다.
- **style: CSS**: 그 문서의 슬라이드에만 — `:is(#lec-panes, #lec-present, .lec-stage) [data-deck="n"] { … }` 중첩 규칙으로 감싼다 (id 무게라 스타일의 `.md-body h2` 를 이긴다). `@import`·`@font-face`·`url()`(data: 밖)·`image-set()` 은 지운다 (원칙 2 — 내 스타일 D53 과 같은 까닭). 중첩 안에서는 `@page`·`:root` 가 먹지 않아 앱 화면·인쇄를 건드리지 못한다. 슬라이드의 너비·높이는 style 속성이라 덮이지 않는다.
- **발표 모드**: 슬라이드를 복제해 창 전체에 (원본을 옮기면 자동 새로고침과 엇갈린다). 키는 발표가 모두 받는다. 전체 화면은 창 모드에서 pywebview `toggle_fullscreen` (js_api `set_fullscreen` — 창에서만 되는 기능이라 `native.py` 에, 원칙 6). 발표자 화면(다른 창의 노트·다음 장)은 하지 않았다 — 노트는 N 으로 아래에.
- **인쇄**: 쪽 크기를 슬라이드 크기로(`@page lec-slide`, 이름 있는 쪽) 한 장에 한 쪽. 이것을 하다가 인쇄 규칙이 app.css(뒤에 읽힘)의 같은 무게 규칙에 져서 칸이 absolute 인 채 인쇄되고 있었음을 알았다 — 보통 문서는 넘치는 내용을 잘라 이어 찍어 드러나지 않았지만 쪽 나누기·쪽 이름은 먹지 않았다. 인쇄 규칙을 `!important` 로 고쳤고, Mermaid 가 body 끝에 붙이는 말풍선 자리 때문에 생기던 빈 쪽도 없앴다.
- **그대로 둔 것**: Marp 테마(`theme: gaia`·`uncover`)와 그 모양은 흉내 내지 않는다 — 색·글꼴은 Lectern 스타일(24종·내 스타일). 그림 필터(`sepia`·`blur`), 조각으로 나타내기·장면 전환, PPTX 만들기는 없다 (보기 전용, PDF 는 인쇄로). Slidev·reveal.js 형식은 알아보지 않는다 (사용자가 'marp: true 만'을 골랐다).

## D60. CSV·텍스트 보기, 터미널 버튼 알림

- **결정 (사용자 요청, 2026-10-24)**: 우클릭 메뉴의 '터미널에 붙여 넣기'가 '복사만 된다'는 보고를 점검했더니 기능은 정상이고(사용자 설정 사본·Claude Code 로 재현 — 한 줄·여러 줄·설정 창 모두 들어감) 작고 흐린 아이콘 대신 복사 항목을 누른 것이었다. 사용자가 고친 것 두 가지와 csv·txt 보기를 요청했다 (v0.32.0).
- **터미널 버튼**: 아이콘에 '터미널' 글자를 붙이고 강조색·구분선으로 복사 항목과 나눴다. 넣으면 "'탭' 탭의 터미널에 넣었습니다 — Enter 는 누르지 않았습니다" 알림 — 전에는 아무 표시가 없어 복사와 헷갈렸다. 빈칸이 있는 `@경로`는 따옴표로 감싸려 했으나, Claude Code 의 `@` 자동 완성이 빈칸을 그대로 둔 경로를 넣고(직접 확인) 공식 문서는 프롬프트의 빈칸 규칙을 적지 않으며 CLAUDE.md 가져오기에서는 따옴표가 안 된다고 적고 있어 지금 모양 그대로 둔다.
- **csv·txt 보기**: 사용자가 고른 것 — 한 번 누르면 Lectern 에서(두 번 누르면 기본 앱), 열마다 거르기 칸, 표 위의 통계 줄, 보기에서만 CP949. 새 화면 종류를 만들지 않고 코드 화면(D43)에서 본다 — 줄 번호·찾기·편집 모드·위치 잇기·우클릭 메뉴·수정 시각 보기·뒤로 가기가 그대로 된다. csv·tsv 는 '자료' 목록에 남는다 (코드가 아니다).
- **CSV 표**: 구분자·머리행은 어림하고 막대의 '첫 줄은 머리행'으로 바꾼다. 거르기는 엑셀식 값 목록 대신 글로 — 포함·`!`·`=`·숫자 비교·범위 (사용자가 고름 — 값 종류가 많은 열에도 된다). 머리행을 누르면 정렬 (거르기 칸과 함께 제안해 고름). 통계는 숫자 열 개수·합계·평균·최소·최대·중앙값, 글자 열 개수·고유값·최빈 — 거른 행으로 다시 센다. 숫자 판정은 본문 표의 숫자 열(1,234·-3.5%·$105·12억)과 같다. 행은 원문 줄 번호를 달아 Claude용 위치가 원문과 맞고, '이 줄 복사'는 칸을 이은 글이 아니라 원문 줄이다. 그리는 행은 2,000개까지 (개수·통계는 전부). 거르기·정렬은 파일마다 이번 실행 동안 기억한다 — 파일이 바뀌어 다시 그려도 그대로.
- **인코딩 (D1 의 예외)**: 엑셀이 저장한 CSV 는 보통 CP949, '유니코드 텍스트'는 UTF-16 이라 csv·tsv·txt·log 를 볼 때만 UTF-16(BOM) → UTF-8 → CP949 순서로 읽는다 (브라우저 `TextDecoder` — WHATWG 의 euc-kr 은 CP949). 상태줄에 인코딩을 보인다. 편집 모드는 지금처럼 UTF-8 만 고친다 (다른 인코딩으로 다시 쓰지 않는다). 코드·문서는 그대로 UTF-8 만.
- **그대로 둔 것**: 엑셀(xlsx) 보기, 차트로 그리기, 보이는 행만 복사는 하지 않았다. 전체 검색·Ctrl+P 는 csv·txt 를 찾지 않는다 (이름은 검색의 '이름이 맞는 파일'에 나온다).

## D61. 모아 보기의 캡션과 우클릭 메뉴

- **결정 (사용자 요청, 2026-10-24)**: '모아 보기에 표·그림 등의 캡션이 있으면 캡션을 기본으로, 우클릭으로 터미널로 보내기도' (v0.33.0).
- **캡션 알아보기** (`toc.js` 의 `captionOf` — 목차와 모아 보기가 같이 쓴다): `<caption>`·`<figcaption>`, 또는 요소 바로 앞·뒤의 짧은 단락(90자까지)이 번호 붙은 캡션(`표 1.`·`<표 2>`·`[그림 1]`·`〈표 Ⅱ-15〉`·`표 3-1`·`Table 2:`·`Fig. 3` — 표·그림·도표·차트·사진·다이어그램·코드)이거나 통째로 굵게·기울여 쓴 줄. 사용자 문서(KMI 자문자료)의 캡션이 `**〈표 Ⅱ-15〉 철재의 HS코드**` 꼴이라 꺾쇠·로마 숫자를 넣었다. 관례대로 표·다이어그램은 위, 그림은 아래가 먼저이고, 코드는 번호 붙은 것만. 두 요소 사이의 단락은 머리 낱말이 말하는 종류만 가져가고(표 캡션을 그림이 가져가지 않게), 그림 뒤면 그 그림의 것, 표·다이어그램·코드 앞이면 그것의 것으로 본다.
- **보이기**: 모아 보기는 캡션이 있으면 캡션(쓴 그대로 — 저자의 번호 포함)이 이름이고 그 아래 '표 3 · 6행 2열'(우리 번호와 크기·종류). 없으면 전처럼 '표 3' 과 머리행·대체 글. 목차는 그대로 '표 n · 설명'이고 설명에 캡션(번호를 뗀 것)이 먼저 쓰인다. 거르기 칸은 캡션도 찾는다.
- **우클릭** (`parts.js` 의 `partMenu`): 문서에서 보기, Claude용 위치 복사(`@문서 a~b행 ('캡션')` — 요소와 캡션 단락의 원문 줄, md 의 `data-lines`), 원문 복사(md — 그 줄들), 문서 경로 메뉴. 복사 항목은 D51 의 터미널 버튼이 붙는다. html 문서는 줄을 몰라 `@문서 ('캡션')` 만.
- **그대로 둔 것**: 박스글·수식에는 캡션을 찾지 않는다. 그림을 한 칸에 모으는 것(같은 그림은 '+N곳')은 그대로 — 그 칸의 이름은 처음 문서의 캡션.

## D62. 모아 보기의 차트·할 일·링크·출처와 문서 정보

- **결정 (사용자 요청, 2026-10-24)**: '차트(Plotly·ECharts 등)도 모아 보기에서 모아서 보게, 모아 보기 하면 좋을 것 추천' (v0.33.0). 제안에서 사용자가 고른 것: 차트를 따로 작은 그림으로, 그리고 추천 넷 모두 — 할 일, 링크와 깨진 링크, 출처·각주, 문서 정보(frontmatter).
- **차트**: '다이어그램'에서 떼어 '차트' 종류 — Vega-Lite·Vega·ECharts·Plotly (`toc.js` 의 `CHART_LIBS`). Graphviz(dot)는 구성도라 다이어그램에 남긴다. 목차에도 '차트'로 나온다. 모아 보기에서는 그림처럼 작은 그림 격자 — 칸이 보일 때 화면 밖 무대(560px)에서 본문과 같은 `renderCharts` 로 그려 SVG 를 넣는다 (하나씩 — 라이브러리가 무겁다, 문서 기준 CSV 도 읽는다). 그린 것은 항목에 남겨 스타일이 같으면 다시 쓴다. 차트를 그리지 않은 채(원문) 미리 세어 두므로 번호는 본문과 같다.
- **할 일·링크·출처**: 목차에는 넣지 않는다 (절 아래에 늘어놓으면 목차가 붐빈다) — `readParts(root, {more: true})` 일 때만 센다 (모아 보기가 셀 때와 찾아갈 때). 종류 아래 작은 단추로 고른다 (`SUBS`): 할 일은 안 한 것(처음)·한 것·모두, 링크는 모두·깨진 것·인터넷·프로젝트 안, 출처는 모두·출처·각주.
  - 할 일: `li.task-list-item`(markdown-it-task-lists) 또는 html 의 체크 칸이 있는 `li`. 글은 안의 목록을 뺀 것, 한 것은 줄을 긋는다.
  - 링크: `a[href]` 중 문서 안 앵커·각주 링크를 뺀 것과 본문 속 경로 표기(`a.path-link` — 그래서 화면 밖에서도 md 는 `linkPaths` 를 돌린다. 그 함수가 template 조각의 맨 위 글을 다루지 못하던 것을 고쳤다). 대상은 `resolveRef` 로 가른다(문서·코드·자료·폴더·인터넷·메일·프로젝트 밖). 트리에 없는 프로젝트 안 파일은 문서마다 한 번 `/api/exists` 로 물어 없으면 '깨짐' (숨김·밖도 열 수 없으므로 깨짐). 이때 `dirs: true` 로 폴더도 묻는다 — 문서가 없는 폴더를 `/` 없이 가리킨 링크(`[src](src)`, 본문에서 누르면 탐색기로 열린다)를 깨짐으로 세지 않고 '폴더'로 (전체 점검에서 고침). 인터넷 주소는 확인하지 않는다 (원칙 2).
  - 출처: '자료:'·'출처:'·'원자료:'·'Source:' 로 시작하는 단락(`※`·`*` 앞붙이도)과 각주(`.footnotes li` — 이름 '각주 n').
- **문서 정보**: 세 번째 보기 '문서 정보' — 맨 앞 설정(frontmatter)을 `slides.js` 의 `readYaml`(한글 키·`[a, b]`·`- a` 목록을 읽게 늘렸다. 들여 쓴 하위 키는 점으로 이은 키 — `author:` 아래의 `name:` 은 `author.name`, Claude 메모의 `metadata.type`. 목록 항목의 이어진 줄 같은 그 밖의 들여 쓴 줄은 건너뛴다 — 전체 점검 전에는 맨 위 키로 섞여 들어왔다)로 읽어, 키 단추(그 키가 있는 문서 수) → 값마다 문서. 값이 날짜(YYYY-MM…)면 최근 것부터, 수면 작은 것부터, 아니면 문서가 많은 값부터. 맨 앞 설정은 있는데 그 키가 없는 문서는 '값 없음'. Marp 설정·title·name·description 처럼 키로 묶을 뜻이 없는 것(문서마다 다른 이름·설명)은 단추로 보이지 않는다 (`META_SKIP`). html 문서의 meta 태그는 읽지 않는다.
- **그대로 둔 것**: Mermaid·Graphviz 다이어그램은 목록 그대로 (작은 그림은 차트만 — 사용자가 고름). 할 일의 체크를 바꾸는 것은 하지 않는다 (보기 전용 — 편집 모드에서). 인터넷 링크가 살아 있는지 보지 않는다.
