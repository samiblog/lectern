# 일정과 알림

> 고른 WORK.md 의 '일정' 절 끝에 일정 한 줄을 넣고, Lectern 이 켜져 있는 동안 창 안에 오늘의 업무·곧 시작·오늘 기록 알림을 띄운다.

## 일정 더하기

| 하려는 일 | 마우스 | 키 |
|---|---|---|
| 창 열기 | 업무 현황의 **일정 더하기** · 달력의 날짜 숫자 | **Alt+S** |
| 날짜 | 오늘 · 내일 · 요일 단추, 달력 단추 | **Ctrl+;** |
| 시각 | 시작 · 끝나는 시각, **종일** | — |
| 넣기 | **넣기** | **Enter** |
| 그만두기 | — | **Esc** |
| 넣은 것 빼기 | 창 오른쪽 아래의 **되돌리기** | — |

창에서 날짜 · 시각 · 내용 · 넣을 곳을 정하고 **넣기**를 누르면 고른 WORK.md 의 '일정' 절 끝에 한 줄이 들어간다.

## 넣을 곳

| 상황 | 동작 |
|---|---|
| 고를 수 있는 곳 | 공통 또는 끝나지 않은 업무 — 나무 차례로, 하위는 위 업무의 경로와 함께 |
| 처음 골라진 곳 | 지금 보는 문서·폴더가 속한 가장 깊은 업무 — 하위 폴더의 문서를 보고 있으면 그 하위 업무 |
| 달력의 날짜 숫자로 열면 | 묶음 폴더의 개요나 하위 업무 칸에서는 그 업무 |
| 넣는 자리 | '일정' 절 끝. 절이 없으면 문서 끝에 만든다 |
| '일정' 절로 보는 제목 | `## 일정` · `### 일정`. `## 일정 (11월)` 처럼 뒤에 괄호·콜론이 붙어도 된다. `# 일정 관리 개선` 같은 업무 제목은 아니다 |

## 넣지 않는 때

| 상황 | 동작 |
|---|---|
| 내용이 비었거나 끝나는 시각이 시작보다 앞 | 넣지 않고 까닭을 보인다 |
| 같은 일정을 두 번 | 막지 않는다 |
| 창을 연 사이 파일이 바뀌었거나 지워짐 | 넣지 않고 알린다 |
| 같은 WORK.md 를 편집 모드로 고치는 중 | 편집기에서 저장할 때 바뀐 것을 알리고 묻는다 |
| 넣은 뒤 파일을 고쳤으면 | **되돌리기**는 고친 글을 지키려고 되돌리지 않고 알린다 |

## 직접 쓰기

WORK.md 에서 직접 써도 된다. '일정' 절의 마지막 줄에서 **Shift+Enter** 로 새 줄을 열고 아래 모양으로 쓴다.

| 일정 | 쓰는 모양 |
|---|---|
| 시각이 있는 일정 | `- 2026-11-14 10:00 팀 회의` |
| 끝나는 시각까지 | `- 2026-11-12 14:00-15:00 팀장 보고` |
| 종일 | `- 2026-11-20 종일 워크숍` |
| 반복 (매주 월) | 아직 없다 — 날짜마다 한 줄씩 쓴다 |

## 알림

Lectern 이 켜져 있는 동안 창 오른쪽 아래에 띄우고, 닫을 때까지 남는다.

| 알림 | 언제 |
|---|---|
| 오늘의 업무 | 켤 때 한 번(날짜가 바뀌면 다시) — 마감 지남 · 오늘 · 3일 안, 기한이 지났거나 오늘인 할 일, 오늘 일정, 확인할 줄. 알릴 것이 없으면 띄우지 않는다 |
| 곧 시작 | 시각이 있는 일정의 10분 전, 한 번 — 이미 시작한 일정은 알리지 않는다 (절전에서 깨어나도 지난 알림이 몰리지 않음) |
| 오늘 기록 | 17:30 이 지나면 한 번 — 오늘 WORK.md 가 바뀌지 않은 진행 중 과제 |

| 상황 | 동작 |
|---|---|
| Windows 알림 · 알림 영역 | 쓰지 않는다 |
| 창이 가려져 있으면 | 다시 볼 때 쌓여 있다 |
| Lectern 을 끄면 | 알림도 없다 |
| 끄기 | 설정 창의 **업무 알림** (기본은 켜짐) |
| Lectern 을 다시 켜면 | 띄운 알림을 기억해 두지 않아서 오늘의 업무가 또 나온다 |
