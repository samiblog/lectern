# 글쓰기 스타일과 다듬기

> 보고서를 개발 문서처럼 쓰지 않게 — 글쓰기 스타일로 실무자처럼 쓰게 하고, 다듬기 점검으로 고를 것만 고치고, 내 문체 노트로 내 글의 규칙을 남긴다.

Claude Code 의 기본 역할은 개발자다. 보고서를 맡겨도 본문에 파일 경로, '**굵은 이름** — 설명' 꼴의 나열, 화살표, '다음과 같습니다:' 같은 개발 문서의 버릇이 섞이기 쉽다.

| 무엇 | 하는 일 | 어디서 |
|---|---|---|
| 글쓰기 스타일 | 그 글을 쓰는 실무자처럼 쓴다 — 넷 가운데 고른다 | 설정 창 **글쓰기 스타일** → **스타일 고르기…** |
| 다듬기 점검 | 사람이 쓴 글의 틀린 말·읽기 어려운 곳을 표로 먼저 보이고, 고른 것만 고친다 | 문서 여백 우클릭 **다듬기 점검 요청** |
| 내 문체 | 내가 직접 쓴 글로 지킬 것과 따라 하지 않을 버릇을 노트로 남긴다 | 문서 여백 우클릭 **내 문체 견본으로 보내기** · 설정 창 **내 문체** |

셋 모두 Lectern 은 요청 글만 터미널에 넣는다 (Enter 는 누르지 않음). 파일을 고치거나 설치하는 것은 AI 도구가 먼저 보이고 물은 뒤 사람이 그렇다고 할 때다.

## 글쓰기 스타일 넷

넷 모두 개발자·AI 글버릇을 빼고 다 쓴 뒤 다시 읽는다. 무엇을 기준으로 쓰는지가 다르다.

| 스타일 | 이런 글에 | 다른 점 |
|---|---|---|
| 리서치 글쓰기 | 보고서 · 검토 의견 · 분석 메모 | 읽는 사람과 판단할 것을 먼저, 폴더 밖 자료와 웹까지 근거를 넓힘, 글 종류마다 기준 |
| 업무 보고 | 결재·보고용 한 장 보고, 회의 자료 | 개조식이 기본, 맨 위에 결론과 결재권자가 할 일, 숫자는 계획·전년 대비, 누가·언제까지, 붙임 |
| 학술 글 | 논문 · 연구 보고서 · 학회 발표문 | 확인한 문헌만 인용(지어내지 않음), 주장의 세기를 근거에 맞춤, 단위·불확실성, 한계 |
| 쉬운 설명 | 설명서 · 안내문 · 교육 자료 | 할 수 있게 되는 일을 먼저, 짧은 문장과 쉬운 말, 번호 하나에 동작 하나, 막히는 곳을 미리 |

## 고르기 창

| 왼쪽 항목 | 무엇 |
|---|---|
| Lectern 에 든 넷 | 위의 표 |
| Claude Code 기본 | 스타일 없이. **이 폴더는 Claude Code 기본으로**는 켤 곳을 '○○ 폴더에서 끄기'로 바꾼다 (열린 폴더가 있을 때만 — 그 뒤 스타일을 고르면 다시 '켜기') |
| 내 글쓰기 스타일 | 개인 폴더 `~/.claude/output-styles` 에 있는, Lectern 의 것이 아닌 출력 스타일 — 켜기만 한다 |
| 새 스타일 만들기 | 요청 글 — 넷 가운데 가장 가까운 것을 바탕으로 새 스타일을 짓고, 초안을 보인 뒤 물어서 개인 폴더에 저장. 끝에 원하는 글을 이어 적는다 |

오른쪽에는 맞는 글, 바뀌는 것, **견본**(같은 요청을 Claude Code 에 스타일 없이와 그 스타일로 실제로 시킨 결과의 앞부분), 설치 상태, 지금 이 폴더에서 듣는 스타일이 보인다. **원문 보기**로 스타일 파일 전체를 읽고, **이 스타일로**를 누르면 설정 창의 '고른 스타일'이 바뀐다. Claude Code 기본과 내 글쓰기 스타일은 쓰는 AI 도구가 Claude Code 일 때만 보인다. 새로 만든 스타일은 설정 창을 다시 열면 내 글쓰기 스타일에 나오고, Claude Code 는 다시 시작해야 쓴다.

## 설치하고 켜기

| 차례 | 할 일 |
|---|---|
| 1 | 보고서를 쓰는 폴더를 연 채 설정 창(**Ctrl+,**) **글쓰기 스타일**에서 스타일을 고른다 |
| 2 | 켤 곳을 고른다 — **○○ 폴더에서 켜기**(기본) · **모든 폴더에서 켜기** · **○○ 폴더에서 끄기** (○○ 은 열린 폴더 이름) |
| 3 | **바뀌는 파일**을 본다 — 스타일 파일(`~/.claude/output-styles/` 안)과 켜는 값을 적을 설정 파일의 전체 경로 |
| 4 | **▣** 를 누르고 Enter — AI 도구가 지금 상태를 알리고, 스타일 파일을 설치(없거나 다를 때)하고 켤지 묻는다 |
| 5 | 그렇다고 하면 설치하고 그 설정 파일에 `"outputStyle"` 한 값만 적는다. 두 파일 모두 `.claude` 폴더 안이라 Claude Code 가 허락을 한 번 더 묻는다 — 바뀌는 파일에서 본 것과 같으면 허락 |
| 6 | 스타일 파일을 새로 설치했으면 Claude Code 를 끝냈다가(`/exit`) 다시 띄운다 |

| 경우 | 어떻게 하나 |
|---|---|
| 코드를 쓰는 폴더 | 켜지 않는다 — 넷 모두 개발 지침(범위 지키기, 고친 뒤 확인하기)을 뺀다. 내 글쓰기 스타일은 맨 앞 설정에 `keep-coding-instructions: true` 가 없으면 뺀다. **모든 폴더에서 켜기**를 고르면 이 경고가 보인다 |
| 모든 폴더에 켠 뒤 코드 폴더에서 | 그 폴더를 열고 **○○ 폴더에서 끄기**로 요청하거나, Claude Code 에서 `/output-style` 로 기본을 고른다 — 폴더의 값이 모든 폴더의 값보다 앞선다 |
| 폴더마다 다른 스타일 | 한 폴더에는 하나가 듣는다 — 스타일 파일은 개인 폴더에 여럿, 켜는 값만 폴더마다 (보고서 폴더는 리서치 글쓰기, 결재 문서 폴더는 업무 보고) |
| Lectern 을 새 판으로 바꾼 뒤 '바꿈 — Lectern 의 것과 다름' | 같은 요청 글로 다시 설치한다 |
| Codex · Antigravity · OpenCode | 출력 스타일 대신 개인 지시 파일이나 그 폴더의 `AGENTS.md` 의 '글쓰기' 절에 넣는다 — 넣을지 먼저 묻는다 |

## 리서치 글쓰기로 쓰면

| 달라지는 것 | 어떻게 |
|---|---|
| 글 종류에 맞게 | 서술식은 문단으로(첫 문장이 주장), 개조식은 위 항목에 결론·아래 항목에 근거로. 개조식을 나쁜 글로 보지 않는다. "개조식으로"·"서술식으로"를 붙이면 그대로 |
| 개발자 글버릇을 뺀다 | 본문에 파일 경로·코드 표기·굵은 이름 나열·화살표·작업 보고 말투를 쓰지 않고, 출처는 끝의 출처 절에 문서 이름으로 |
| AI 글버릇을 줄인다 | '첫째·둘째', '~로 판단됩니다', '한편·또한'의 되풀이, 절마다 붙는 요약 문장, 빈 꾸밈말 |
| 소제목을 주장으로 | '6월 값은 전망 범위의 위쪽에 있다' — 소제목만 훑어도 흐름이 잡힌다 |
| 분량을 지킨다 | PDF 양식에서 A4 한 쪽은 공백 빼고 서술식 1,000자, 개조식 800자 안팎 |
| 자료의 어색한 표현은 고쳐 쓴다 | '230천 t' → '23만 t'. 인용한 문장과 숫자 값은 그대로 |

다른 셋도 개발자·AI 글버릇과 다시 읽기는 같다. 요청에 읽는 사람·목적·글 종류·분량을 붙이면 글이 가장 많이 달라진다 — 예: "구매팀장이 3분기에 언제 살지 정할 수 있게, 개조식으로 A4 한 쪽. 개요 확인 없이 바로 써." 긴 글이면 핵심 주장과 쪽 배분을 개요로 먼저 보이고 멈춘다.

## 다듬기 점검

| 차례 | 할 일 |
|---|---|
| 1 | 내가 쓴(또는 고친) md 문서의 여백을 우클릭해 **다듬기 점검 요청**. 몇 줄만이면 줄을 고르거나(**Shift+↓**) 장을 하이라이트(**Alt+H**)한 뒤 우클릭 **이 범위 다듬기 점검 요청** |
| 2 | 터미널에서 Enter — 파일을 고치기 전에 표가 나온다: 번호 · 등급 · 어디 · 원문 · 고친 안 · 까닭 |
| 3 | 고를 것을 말한다 — "틀림만 고쳐 줘", "1·3·7번만", "취향 빼고 모두". 고른 곳만 고치고 나머지 글자는 그대로, 고친 곳은 Lectern 에 바로 보인다 |

| 등급 | 무엇 | 예 |
|---|---|---|
| 틀림 | 고친 안이 하나뿐인 것 | 왠만하면 → 웬만하면, 상승세를 띄고 → 띠고, 지향·지양이 뒤바뀜 |
| 읽기 어려움 | 틀리지 않았지만 읽는 사람이 막히는 곳 | 겹말(남은 잔량), 번역투(~에 대한 검토를 진행하였다), 조건이 얽힌 긴 문장, 풀지 않은 약어 |
| 취향 | 둘 다 맞는 것 | 구매할 만한·구매할만한, 글 종류에 따라 관습인 공문 투 |
| 확인 필요 | 표현이 아니라 내용 | 앞뒤가 맞지 않는 숫자, 근거가 보이지 않는 주장 — 고치지 않고 알리기만 |

인용(따옴표·인용 상자 안, 규정에서 옮긴 문장), 숫자 값, 기관·법령 이름, 맞게 쓴 말(대금 결제의 '결제', '일절')은 건드리지 않는다. 같은 버릇이 되풀이되면 끝에 '자주 나온 것'으로 알린다. 그냥 "다듬어 줘"라고 시키면 묻지 않고 내용까지 고쳐 쓰기 쉽다 — 다듬기 점검 요청은 표를 먼저 보이게 한다.

## 내 문체

| 차례 | 할 일 |
|---|---|
| 1 | 내가 직접 쓴 글(AI 와 함께 쓴 글은 빼고)의 여백을 우클릭해 **내 문체 견본으로 보내기**. 여러 편이면 설정 창 **내 문체**의 요청 글 끝에 `@경로` 를 이어 붙인다 — Word·PDF 로 쓴 예전 보고서도 된다 |
| 2 | AI 도구가 세 칸(아래 표)으로 정리한 노트 초안을 보인다 — 아직 저장하지 않는다 |
| 3 | 칸을 옮기거나 지우라고 말한 뒤("이건 내 방식이니 따라 해", "이건 빼") 좋다고 하면 저장한다 |
| 4 | 견본을 더할 때마다 노트가 보태진다. 두 편 이상에서 보인 것만 적고, 예문은 견본을 옮기지 않고 새로 지어 쓴다 — 기밀 보고서가 견본이어도 숫자·이름이 노트로 새지 않는다 |

| 칸 | 무엇 | 쓰는 때 |
|---|---|---|
| 지킬 것 | 읽는 사람이 기대하는 규칙 — 말투, 용어, 숫자·단위·날짜 쓰는 법 | 늘 |
| 참고할 것 | 즐겨 쓰는 방식 — 문장 길이, 결론을 두는 자리 | 글 종류와 읽는 사람이 맞을 때만 |
| 따라 하지 않을 것 | 읽기 어렵게 하는 버릇 — 겹말, 번역투, 아주 긴 문장 | 쓸 때 따라 하지 않고, 다듬기 점검 때 먼저 살핀다 |

| 경우 | 어떻게 되나 |
|---|---|
| 저장하는 곳 | Claude Code 는 개인 규칙 파일 `~/.claude/rules/내-문체.md` 하나 — 어느 폴더·어느 글쓰기 스타일에서나 같은 노트. 다른 도구는 개인 지시 파일의 '내 문체' 절 |
| 저장할 때 | `.claude` 폴더 안이라 Claude Code 가 고쳐도 되는지 한 번 더 묻는다 — 허락한다. 다시 시작해야 읽는다 |
| 예전 판처럼 스타일 파일 끝에 '내 문체' 절이 있으면 | 이 파일로 옮길지 묻는다 |
| 항목의 글 종류 | '메모:', '서술식 보고서:', '공통:' 처럼 어디서 본 것인지 붙는다 — 메모의 합니다체가 보고서로 번지지 않고, 노트에 없는 종류의 글에는 '공통:'(용어, 숫자·날짜 표기, 출처 쓰는 법)만 |
| 보고서 글의 기본과 부딪치면 | 내 문체가 앞서지 않는다 — 지킬 것은 따르고, 읽기 어렵게 하는 버릇은 따라 하지 않는다 |
| 폴더마다 다른 규칙 (기관 양식, 존댓말) | 그 폴더의 `CLAUDE.md` 에 둔다 |
