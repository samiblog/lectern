# Toolbar

> The row at the very top of the window — fit the view with text size, document width, line numbers, style and section focus, and open the Quick open box, settings, keyboard shortcuts, the work board and All terminals.

## Buttons (from the left)

| Button | What it does | Keys |
|---|---|---|
| Sidebar | Show or hide the sidebar on the left | **Ctrl+B** |
| ‹ · › | Back · forward — including jumps within the same document | **Alt+←** · **Alt+→** (the mouse back and forward buttons too) |
| Quick open | Open a document or code file by name, title or path — start with `>` to find a command | **Ctrl+P** · **Ctrl+Shift+P** |
| − · 100% · + | Document text size | **Ctrl+=** · **Ctrl+-** · **Ctrl+0** |
| Narrower · Width 100% · Wider | Left-right width of the md document body | — |
| Line numbers | Source line numbers in the left margin of md documents | **Alt+L** |
| Style · ∧ · ∨ | Colors and fonts of the text, toolbar and sidebar | — |
| Focus · ∧ · ∨ | Keeps only the section with the current line sharp; ∧·∨ beside it go to the previous and next section | **Alt+H** |
| ⚙ | Settings window | **Ctrl+,** |
| ? | Keyboard shortcuts (the user guide is **F1**) | **Ctrl+/** |
| Work | Work board — status, due dates, to-dos and events of the folders with a WORK.md | **Alt+W** |
| All terminals | The terminals of all open projects on one screen | **Ctrl+Shift+\`** |

With picked lines, Focus keeps those lines sharp. In documents not divided into sections and in the code view, it is the same as **Ctrl+Enter** (select lines).

## Text size and document width

| | Text size | Document width |
|---|---|---|
| What changes | The document's text | The left-right width of the md document body — the text stays the same size; lines get longer or shorter |
| Range | 80%–200% (100% is already set slightly large for comfortable reading) | 80%–200%; widen all the way for **Full width** (the whole document pane) |
| Back to default | Click **100%** in the middle · **Ctrl+0** | Click **Width 100%** in the middle |
| When the window is narrow | — | Widens only up to the document pane's width |
| What stays the same | The app screen (to zoom the whole app, **Ctrl+Wheel**) | The code view · Lectern slides · HTML documents with their own style |
| Next start | The size you chose | The width you chose |
| Print · PDF | Not applied | Not applied |

## Tables when the width changes

Table column widths are fitted automatically. They are fitted again when you change the window or sidebar width, the text size or the document width.

| Case | Behavior |
|---|---|
| Each column | Starts at the width of its longest word — so a column with little text isn't squeezed to a letter or two and makes rows tall |
| Remaining width | Shared out in a few ways, each actually drawn, and the best is used — the lowest table, following how much text each column holds, with at least two words per line |
| Rows tall because of the leftmost column | Widening that column is tried too |
| Header row · leftmost column | Not broken in the middle of a word — they wrap at spaces (if a long word makes the table overflow sideways, only that table breaks words) |
| Scrolling sideways | The last resort — inside the table, only when there are so many columns that text would wrap vertically, or when numbers (which don't wrap) can't fit |
| File · printing | Only the shown widths change; the file stays the same. Printing and PDF reflow tables to the page width |

If cells are still long, split the table or move long explanations out of it. When you hand documents to AI tools (Claude Code and others), the Lectern writing guide tells them to write that way.

## Line numbers

| Case | Behavior |
|---|---|
| Numbers | Lines of the source file — the same lines as the `@path line 12` sent to AI tools |
| Lines not on screen, such as blank lines | Skipped |
| Text that wraps on screen | Numbered on its first line only |
| Code view | Always numbered |
| Printing | Not printed |

## Style

| To do | How |
|---|---|
| Pick a style | One of 25 in the list — the text, toolbar and sidebar colors change together |
| Compare one after another | **∧** · **∨** next to the list — the previous or next style |
| Follow Windows dark mode | **Auto (system)** at the top of the list |
| Change how the list is grouped | Settings window — by use · by mood · by brightness |
| Go to the settings window | **Style settings…** at the bottom of the list |
| Styles you made | The **My styles** group at the bottom of the list |
| Make my style | **Make my style…** near the bottom of the list — below |

Styles apply to the screen only. Paper and PDF always use the same report layout.

## Making your own styles

| What | How |
|---|---|
| One style | One CSS file — put it in the `%APPDATA%\Lectern\styles` folder and it appears under **My styles** |
| Make one on screen | **Make my style…** in the style list (also **Make on screen…** in the settings window and the command finder) — pick fonts (body · headings), sizes (text · line spacing · width), colors (text · headings · links · table header) and lists (weight and size of top items) on top of the current style, and the document shows them at once. Type a name and **Save** — one CSS file with only the changed fields is made and selected |
| Change it again on screen | Open it again while that style is selected and its values load. **Save** asks first and replaces that file — or **Save as a new style**. If the file changed in the meantime, it is not replaced |
| On top of a hand-written style | Open it while that style is selected and its rules are copied into the new file under your values — the original file stays as it is |
| Fonts · colors | Fonts come from those on this PC (or type a name). If a text color has low contrast with the background (below 4.5:1), you are told |
| Hand it to an AI tool | Paste **Copy request for Claude Code** from the settings window into the AI tool and add the look you want (for example 'navy headings, a dark navy table header with white text, serif body text'). The request names the style guide that comes with the app and the folder to save in. **▣** next to it puts it straight into the terminal |
| Refine while looking | While that style is selected, changes to its file are applied again within a few seconds — keep asking, like 'make the headings larger' |
| Open the folder · remove a style | **Open style folder** in the settings window — delete a file and it leaves the list |
| Internet fonts · images | Removed by the app — only fonts on the PC are used |
