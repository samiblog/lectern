# Work tree, kanban and Gantt

> The WORK.md files of subfolders are tied into a tree and gathered at the top, and in the list, kanban, Gantt and calendar you change one line of that task's WORK.md in place.

## Work tree

The WORK.md of a project folder oversees everything, and the WORK.md of a subfolder covers one piece of work in it. In between you can have a group folder that ties several sub-tasks together as one.

```text
2026 metals research/      WORK.md   overview
├─ issue-reports/          WORK.md   group
│  ├─ 01-copper/           WORK.md   small task
│  └─ 02-lithium/          WORK.md   small task
└─ regular/                (no WORK.md — skipped)
   └─ weekly/              WORK.md   directly under the overview
```

| Rule | What happens |
|---|---|
| Parent | The WORK.md of the nearest folder above — folders without a WORK.md are skipped |
| In the files | Each holds only its own work. Lectern gathers them in three places — the work board, the folder overview of an overview or group folder ('Work in this folder'), and the **Sub-tasks** panel below the document when you open a parent WORK.md (a panel that is not in the file and does not show in print or PDF) |
| An empty status | Worked out from the sub-tasks — if any sub-task is blocked it is blocked, then at risk · active · planned · on hold in that order; when all are finished it is done. Worked-out values carry a `*`. A status written in the file wins |
| What comes up | A summary such as '5 sub-tasks · active 3 · blocked 1' and the earliest due date among open sub-tasks ('next 11-20'). Sub-tasks' to-dos, events and alerts come with their path, such as 'Overview › Issue reports › 02 Lithium' |
| Mismatches | Under Needs attention on the work board — a parent done while sub-tasks are open ('Sub-tasks still open'), a sub-task due later than its parent ('Sub-task due later') |
| Expanding | Three levels at first; **▸** expands and folds. Finished sub-tasks are folded behind 'Show n done or dropped' |
| Clicking a sub-task | Opens its WORK.md in the project tab that contains it, without opening that folder on its own |
| Remembering | Opening a project finds the WORK.md files in its subfolders and adds them to the work folder list (not inside hidden or excluded folders). They stay after the tab is closed, and while it is closed Lectern still reads only those WORK.md files, one each. If you rename or move a subfolder while the project is open, the next reading follows it to its new place |

## Four views

Choose from **List · Kanban · Gantt · Calendar** above the tree. Dates come from `start:` (start) and `due:` (due date) in the WORK.md front matter.

| View | What |
|---|---|
| List | One row per task — active and planned (earliest due first), on hold, done and dropped (folded), in that order; sub-tasks are indented below |
| Kanban | Leaf tasks (tasks without sub-tasks) as cards in status columns |
| Gantt | Date bars next to the same tree as the list |
| Calendar | Task bars on a month grid, with each day's due dates, starts, to-do dates and events |

## Changing from the top

Choosing something on a row of the tree (work board · folder overview · Sub-tasks panel) changes **one line of that task's WORK.md**. The changed file gets an amber dot in the tree.

| Where you choose | Line that changes |
|---|---|
| Status cell → status menu (groups also have 'Clear — work out from sub-tasks') | `status:` in the front matter |
| Due cell → calendar | `due:` in the front matter |
| Priority cell → menu | `priority:` in the front matter |
| To-do cell (2 / 5) → checkbox in the expanded list | `[ ]` ↔ `[x]` on that to-do line |
| Due button in the expanded list → calendar | `(YYYY-MM-DD)` at the end of that to-do line |
| 'Add a to-do' field in the expanded list → **Enter** | One `- [ ] text (due)` line at the end of the 'To do' section |

| Case | What happens |
|---|---|
| Right-clicking a row | **Open this task · Change status · Change due date · Change priority** |
| The text of a to-do or of the log itself | Open that WORK.md and change it there (the 'line n' button in the expanded list) |
| If that line or the file changed meanwhile | It is read again right before the change; if it changed (elsewhere, or by an AI tool), nothing is written, the view is redrawn and you are told — just choose again |
| Words for status values | Those the file uses — a file with Korean values such as `status: 진행` gets Korean |

## Kanban

There are five columns: planned · active · watch (blocked · at risk) · on hold · done · dropped. If a leaf task has an empty or unreadable status, one more column, 'No status', is added. Groups are not cards; they show as the path above the cards. A card shows the path of the tasks above, the title, status, due date (D-n), priority, to-do progress (3/5) and the next to-do.

| To do | Mouse | Keys |
|---|---|---|
| Change status | Drag the card to another column — the watch column asks for blocked or at risk, the done column for done or dropped | — |
| Open the WORK.md | Click the card | **Enter** · **Space** |
| Menu — Open this task · change status · due date · priority | Right-click the card | Menu key |

A column shows up to 40 cards; the rest is given as a count.

## Gantt

| What | Shape |
|---|---|
| Rows | The same work tree as the list — same expanded and folded rows |
| A task with a start and a due date | A bar |
| A task with only one date | A point ◆ on that day |
| Group | A thin bar from the earliest to the latest day of its sub-tasks |
| Colors · today | The same colors as the kanban columns; the red vertical line is today |
| Ticks | Weekly when the span is within 70 days, monthly beyond that |
| Clicking a bar · name | Opens that WORK.md |
| Clicking the **Start** · **Due** cell | A calendar opens and the day you pick goes into that task's front matter — dates are not changed by dragging (a wrong drag would change the file straight away) |
| **Copy as Mermaid Gantt** | Copies the tasks shown now as Mermaid Gantt text — paste it into a md document and it becomes a schedule chart. One section per top-level task, done faded, blocked and at risk in red, active highlighted. Tasks without dates are left out, and you are told how many |

## Calendar

The month grid starts on Sunday. Tasks whose start is before their due date (and that have no subtasks) are drawn as bars from start to due, and below them each day shows due dates (■) · starts (▶) · to-do dates (☐) · events (•, with the time). Finished tasks show events only, and the calendar on the work board also shows the events and to-dos of the common WORK.md.

| To do | How |
|---|---|
| Move between months | **‹** · **This month** · **›** |
| Add an event on that day | Click the date number — in a group folder's overview or the Sub-tasks panel, that task is chosen as where it goes |
| Go to the line | Click the item — that line of that WORK.md |

## Date picker

Wherever you enter a date — the due date of a work card, the date in Add event, the due dates in the tree — a calendar opens. While editing a document (line edit box · edit mode), press **Ctrl+;** and the day you pick goes in at the cursor as `YYYY-MM-DD`. **Date** in the Insert window (**/**) does the same.

| Key | Does |
|---|---|
| **←** · **→** | A day |
| **↑** · **↓** | A week |
| **PageUp** · **PageDown** | A month |
| **Home** · **End** | Start · end of the week |
| **T** | Today |
| **Enter** | Pick |
| **Esc** | Cancel (closes only the calendar) |

There are 'Today' · 'Tomorrow' · 'This Friday' · 'Next Monday' buttons, plus **Clear** when changing a date. Days with a due date, a to-do date or an event have a dot.
