| 그 폴더의 개요 | 사이드바 트리에서 폴더 이름 누르기 ('문서' 목록의 폴더에서 **Enter** 도) |

## 본문이 그리는 것

| 요소 | 원문 | 화면 |
|---|---|---|
| 표 | Markdown 표 | 숫자 열은 오른쪽, 머리행이 위에 붙어 따라온다 — 아래 '표' |
| 코드 블록 | 언어 이름을 적은 코드 블록 | 언어 색 · 오른쪽 위 **복사** |
| 강조글 | `> [!NOTE]` 같은 콜아웃 | 제목 줄 없이 종류의 색으로 |
| 박스글 | `<!-- box -->` ~ `<!-- /box -->` | 테두리와 제목 띠가 있는 상자 — 아래 '박스글' |
| 수식 | `$…$` · `$$…$$` · math · latex 코드 블록 | 수식으로. `$105` 같은 달러 표기는 그대로 |
| 다이어그램 | mermaid 코드 블록 | 그림으로 — 모양은 번호로 고른다, 아래 '도해 스타일' |
| 차트 | `vega-lite` · `echarts` · `plotly` · `dot` 코드 블록 | 그림으로 — 아래 '차트' |
| 각주 · 체크리스트 | `[^1]` · `- [ ]` | 각주 · 체크 칸 |
| 그림 | `![설명](경로)` | 누르면 크게 |
| 파일 경로 | `src/app.py:42` | 실제로 있는 파일이면 링크 — [링크와 파일 열기](3.4-링크와-파일-열기.md) |
| 문단 안의 줄바꿈 | 원문의 Enter · 줄 끝 공백 둘 · `<br>` | 화면에서도 줄이 바뀐다 (Word 의 Shift+Enter 처럼 — 개조식 글이 그대로) |
| 번호 · 글머리 글자로 시작하는 줄 | `1. 요약` · `1.2` · `가.` · `(1)` · `①` · `□` · `○` · `ㅇ` · `-` · `※` 로 시작하는 제목 · 문단 · 목록 항목 | 화면에서 둘째 줄로 꺾이면 그 글자 뒤에 맞춰 들여 쓴다 — 줄바꿈 뒤의 줄은 그대로. 종이 · 내보낸 html 은 글자의 평균 폭으로. 원문은 바꾸지 않는다 |
| 글머리 글자 목록 (개조식) | 줄 맨 앞의 `□`·`ㅁ` · `○`·`ㅇ` · `-` · `·` — `□` · `○` · `·` 로 시작하는 줄부터 빈 줄 · 제목까지 (`-` 로 시작하면 Markdown 목록) | 줄마다 목록의 항목으로. 하위 수준은 들여 쓴다 — 수준은 글머리 글자의 차례 `□` > `○` > `-` > `·` 가운데 그 문서가 쓴 것으로 (원문의 앞 빈칸은 보지 않는다). `①` · `1.` · `※` 줄은 위 항목의 한 수준 아래, 머리 글자가 없는 줄은 위 항목에 이어 쓴 줄. 원문은 바꾸지 않는다 |
| 목록의 수준 | 하위 항목이 있는 목록 — Markdown 목록 · 글머리 글자 목록 모두 | 맨 위 항목은 진하게 · 조금 크게, 그 사이를 조금 띄운다 (외부 보고서처럼). 셋째 수준부터 조금 작게. 하위가 없는 목록 · 할 일 목록 · 인용 속 · Lectern 슬라이드는 그대로, GitHub 스타일은 끈다. 종이 · PDF · Word 도 같다. 굵기 · 크기는 [내 스타일 만들기](2.1-툴바.md#내-스타일-만들기)의 '목록' 칸으로 |

줄바꿈을 표준 Markdown 처럼 이어서 보려면 설정 '보기'의 **문단 안의 줄바꿈 보이기**를 끈다.

## 표

| 하려는 일 | 방법 | 결과 |
|---|---|---|
| 표 복사 | 마우스를 올려 오른쪽 위 **복사** · 우클릭 **표 복사** | 엑셀에는 칸이 나뉘고 워드 · 메일에는 표로 |
| 칸 맞춤 고르기 | 설정 '보기'의 **표 칸 맞춤** | **기본**: 글은 왼쪽 · 숫자는 오른쪽 · 칸의 위. **보고서식**: 머리행과 짧은 열(칸의 글이 모두 열 글자 안 — 구분 · 상태 · ○×)은 가운데, 숫자는 오른쪽, 긴 글은 왼쪽, 칸의 세로 가운데 |
| 한 열만 다르게 | 칸 우클릭 **이 열 왼쪽 맞춤** · **가운데 맞춤** · **오른쪽 맞춤** | 원문의 구분 줄에 `:---` · `:---:` · `---:` 를 쓴다 — 설정보다 앞선다 |
| 열 맞춤 표시 지우기 | 그 열에서 우클릭 **이 열 맞춤 표시 지우기** | 다시 설정을 따른다 |
| 차트로 보기 | 우클릭 **차트로 보기** | [표를 차트로 보기](3.6-코드와-자료-보기.md#표를-차트로-보기) |

설정의 칸 맞춤은 보이는 것만 바꾸고 파일은 그대로다. 인쇄 · PDF · html 로 저장에도 그대로 간다.

## 박스글

본문과 따로 읽는 글 상자다. 보고서에서 본문의 흐름과 떨어진 주제를 가볍게 다룰 때 쓴다.

| 하려는 일 | 원문 · 방법 | 결과 |
|---|---|---|
| 상자 만들기 | `<!-- box -->` 줄과 `<!-- /box -->` 줄 사이에 글 · 표 · 그림 | 테두리와 제목 띠가 있는 상자. 다른 뷰어에서는 두 줄이 보이지 않아 보통 글로 읽힌다 |
| 제목 달기 | 첫 줄을 한 줄로 | 제목 띠에 |
| 번호 달기 | `박스 1. 제목` | 표 · 그림처럼 번호 — `[박스 1](#박스-1)` 로 가리킨다 |
| 접고 펴기 | 제목 띠 오른쪽의 화살표 | 접어 두어도 인쇄에는 모두 나온다 |
| 닫는 줄을 빠뜨리면 | — | 다음 제목 앞에서 끝난 것으로 본다 |
| 넣지 않는 것 | 제목(`#`) · 다른 박스글 | — |

전에 '박스글'이라 부르던 `> [!NOTE]` 종류는 이제 강조글이다.

## 차트

| 코드 블록의 언어 | 무엇 |
|---|---|
| `vega-lite` | 데이터 차트 |
| `echarts` | 도넛 · 캔들 등 여러 차트 |
| `plotly` | 상자 그림 · 선버스트 등 분석용 차트 — Python 의 `fig.to_json()` 결과도 |
| `dot` · `graphviz` | 구성도 · 의존 관계 |

색은 문서 스타일을 따른다. 설정은 JSON 이고 함수는 쓸 수 없다. 데이터는 문서 안에 적거나 프로젝트 안의 CSV · JSON 파일을 상대경로로 가리킨다 (인터넷 주소는 읽지 않는다). 마우스를 올려 값 보기 같은 움직임은 없고, Plotly 의 지도 차트는 인터넷의 지도 자료가 있어야 해서 그리지 않는다.

## 도해 스타일

Mermaid · Graphviz 그림의 모양을 번호로 고른다. 색은 문서 스타일을 따르고 번호는 모양만 정한다 — 어두운 스타일 · 인쇄에서도 어울린다.

| 번호 | 이름 | 모양 |
|---:|---|---|
| 1 | 기본 | 예전 그대로 (설정을 바꾸지 않으면 모든 그림) |
| 2 | 보고서 선 | 흰 상자 · 진한 테두리 · 직각으로 꺾는 선 — 흑백 인쇄에 |
| 3 | 카드 | 둥근 모서리 · 옅은 그림자 — 화면 · 발표에 |
| 4 | 진한 채움 | 진한 상자에 밝은 글자 |
| 5 | 선만 | 채움 없는 가는 선 — 논문 · 책에 |
| 6 | 손그림 | 손으로 그린 듯한 선 — 초안에 (Graphviz 는 1) |
| 7 | 단계 색 | 묶음(subgraph)마다 다른 옅은 색 |
| 8 | 제목 띠 | 상자 위에 진한 제목 띠, 아래에 내용 |
| 9 | 옅은 제목 띠 | 옅은 띠에 진한 제목 글자, 아래에 내용 |
| 10 | 제목 줄 | 굵은 제목 아래 가는 줄, 그 아래 흐린 내용 |

| 하려는 일 | 방법 | 결과 |
|---|---|---|
| 그림 하나의 모양 | 그림 우클릭 **도해 스타일…** — 그 그림을 번호마다 그린 창에서 누르거나 화살표 키 · **Enter** | 그림 블록에 `%% 스타일: 3 카드` 한 줄 (Graphviz 는 `// 스타일: 3 카드`) — 있으면 바꾼다. **Ctrl+Z** 로 되돌린다 |
| 그림 · 차트 하나의 색 | 우클릭 **색 조합…** — 그 그림을 여덟 가지 색으로 그린 창에서 (아래 '색 조합') | `%% 색: 2 보고서 남색` (Graphviz · 차트는 `// 색: 2 보고서 남색`) — 모양 줄이 있으면 그 줄에 `%% 스타일: 3 카드 · 색: 2 보고서 남색` |
| 그 그림을 기본대로 | 같은 창의 **설정 따르기** (문서의 기본 줄이 있으면 **문서의 기본 따르기**) — 블록에 줄이 있을 때만 | 표시 줄에서 그것을 지운다 |
| 번호가 어떤 모양인지 | 우클릭 메뉴의 오른쪽 글(`3 카드`), 고르기 창의 **모양 견본 모두 보기**, 설정 창의 **모양 견본** · **색 조합 견본** | 표시 줄의 번호 뒤 이름은 사람이 읽으라고 붙인다 — Lectern 은 앞의 번호만 읽는다 |
| 가로 ↔ 세로 | 그림 우클릭 **세로로 바꾸기** · **가로로 바꾸기** | 그림의 방향 글자만 (`flowchart LR` ↔ `TD`, Graphviz 는 `rankdir`). 문서 폭에 상자 넷이 넘으면 세로가 낫다 — 가로 여섯 상자는 글자가 본문의 60% 쯤으로 준다 |
| 한 문서의 그림 모두 | 문서 위쪽에 `<!-- 도해: 스타일 8 · 색 2 -->` 한 줄 | 화면에는 보이지 않는다. 블록의 표시 줄 → 문서의 줄 → 설정 차례 |
| 표시 줄이 없는 그림 모두 | 설정 '보기'의 **도해 스타일 · 색 조합** (고르기 창의 **기본 도해 스타일 바꾸기…** 도) | 미리보기를 보며 기본 번호를 고른다 |
| Claude 에게 | "Mermaid 3번 스타일, 색 2번으로 그려 줘" | 작성 안내(`writing.md`) 옆의 `diagrams.md` 를 읽고 그 줄을 적는다 |
| 강조 | 상자에 `:::key`(핵심) · `:::warn`(주의) · `:::muted`(보조) — Graphviz 는 `[class="key"]` | 번호가 정한 색으로 칠한다 |
| 제목과 내용으로 나눈 상자 (8 · 9 · 10) | 상자 글을 줄바꿈 — Mermaid `<br>`, Graphviz `\n` | 첫 줄이 제목, 나머지가 내용. 한 줄 상자는 제목만 |

### 색 조합

모양과 따로 고르는 색 번호다. 차트의 계열 색(Vega-Lite · ECharts · Plotly, Mermaid 의 원그래프 · xy 차트)과 도해의 상자 · 핵심 강조 · 단계 색 · 제목 띠가 바뀌고, 글자 · 바탕 · 선은 문서 스타일 그대로다. 계열이 하나인 막대 · 선은 그 색 조합의 첫 색, 열지도는 그 색의 농담으로 그린다. 차트가 색을 직접 정했으면 그 색이 먼저다 — 캔들 · 폭포의 오름 · 내림 색도 바뀌지 않는다. 이런 차트는 고르기 창의 칸이 모두 같고, 창 위에 까닭이 나온다. 칸은 갈리지만 원문의 색이 일부 남는 그림(막대는 바뀌고 Claude 가 색을 적은 선만 남는 것 등)에도 옅게 알린다.

| 원문이 색을 정한 그림 | 하는 것 |
|---|---|
| 어느 줄인지 | 고르기 창 위의 알림에 원문의 몇째 줄 무엇인지 (`52째 줄 "lineStyle": {"color": "red"…`) |
| 그 그림의 색을 빼게 | 알림 옆 **Claude 에 색 지정 빼기 요청** — 그 블록의 자리와 작성 안내를 적은 요청 글을 터미널에 넣는다 (Enter 는 누르지 않음). 도해 스타일 창에서는 **모양 · 색 지정 빼기 요청** |
| 문서의 그림 · 차트 모두 | 탭 막대의 **AI 요청** → **그림 · 차트의 색 지정 빼기 요청** |
| 앞으로 쓰는 그림 | 작성 안내가 색을 적지 않게 한다 (계열은 데이터의 열로, 강조는 투명도, 전망은 점선). 설정 'AI 도구'의 Lectern 요약이 예전 판이면 그 줄에 **예전 판의 요약** 이 보인다 — 요청 글을 다시 붙이면 새 요약으로 바꾼다 |

| 번호 | 이름 | 색 |
|---:|---|---|
| 1 | 문서 스타일 | 지금 그대로 (설정을 바꾸지 않으면 모든 그림) |
| 2 | 보고서 남색 | 남색 농담 + 주황 강조 하나 |
| 3 | 회색 + 강조 | 첫 계열만 색, 나머지는 회색 |
| 4 | 선명한 구분 | 서로 잘 갈리는 열 가지 색 |
| 5 | 색약 친화 | Okabe-Ito 색표 |
| 6 | 따뜻한 | 주황 · 적갈 계열 |
| 7 | 차가운 | 남 · 청록 · 보라 계열 |
| 8 | 파스텔 | 옅은 색 |

표시 줄은 주석이라 다른 곳(GitHub 등)에서는 기본 모양 · 색으로 그려진다 (차트의 `//` 줄은 Lectern 만 읽는다 — 다른 도구에 붙일 때는 뺀다). 고르기 창은 쓰기 전에는 파일을 바꾸지 않는다 — **Esc** · 바깥을 누르면 그대로 닫는다. 창을 연 뒤 그 그림이 다른 곳에서 바뀌었으면 쓰지 않고 알린다. 사용설명서의 흐름도는 늘 기본이다. Word · pptx 로 낼 때의 그림은 아직 기본 모양 · 색이다. 예제: `guide/도해-스타일-예제/` 의 도해 스타일 견본 · 색 조합 견본.

### 내 도해 스타일 · 내 색 조합

마음에 드는 그림의 모양 · 색을 번호로 남겨 두고 다른 그림에도 쓴다. 모양은 11번부터, 색은 9번부터다.

| 하려는 일 | 방법 | 결과 |
|---|---|---|
| 이 그림의 모양을 내 스타일로 | 그림 우클릭 **이 모양으로 내 도해 스타일 만들기…** (고르기 창 아래에도) | 그 그림의 자리 · 다음 번호 · 저장할 폴더를 담은 요청 글이 터미널에 들어간다 (Enter 는 누르지 않음). Claude 가 이름과 값을 보이고 물은 뒤 파일 하나를 쓴다 |
| 이 차트의 색을 내 색 조합으로 | 차트 우클릭 **이 색으로 내 색 조합 만들기…** | 같은 길 — 색 9번부터 |
| 쓰기 | 고르기 창의 '내 것' 칸, 또는 `%% 스타일: 11 우리 회사` · `%% 색: 9 회사 색` | 파일을 만들거나 고치면 몇 초 안에 그림이 따른다 (다시 불러오지 않아도) |
| 기본으로 | 설정 '보기'의 **도해 스타일 · 색 조합** 에서 '내 것' 묶음 | 표시 줄이 없는 그림 모두 |
| 파일 보기 · 고칠 것 | 같은 자리의 **내 도해 스타일 폴더 열기**, 그 아래의 빨간 줄 | 설정 폴더의 `diagram-styles` — 파일 하나가 스타일 하나. 틀린 값 · 겹친 번호 · 모르는 열쇠는 빼고 파일마다 까닭을 보인다 |

- 파일은 정해진 값(바탕 번호, 모서리 · 테두리 · 선 모양 · 선 굵기 · 점선 · 그림자 · 채움 · 간격 · 굵은 글자 · 제목 상자 · 단계 색 · 손그림, 색 조합은 계열 색)만 받는다. CSS 는 받지 않는다. Lectern 은 이 폴더를 읽기만 한다.
- 그 파일이 없는 PC(문서를 받은 동료)에서는 기본 모양 · 색으로 그린다 — 표시 줄의 이름은 남는다. 설정의 기본 번호도 그 파일이 없어지면 1 이다.
- Claude 가 읽는 안내: 설치 폴더의 `web/help/diagram-styles.md`.

## 차트의 데이터

| 하려는 일 | 방법 | 결과 |
|---|---|---|
| 크게 보기 | 차트 누르기 | 크게 |
| 그림으로 복사 | 우클릭 **그림 복사** | PNG |
| 그린 데이터 보기 | 마우스를 올려 **표** (다시 누르면 접는다) | 차트 아래에 표로. 30행이 넘으면 처음 · 끝과 일정한 간격의 30행 — **모두 보기**로 5,000행까지 |
| 데이터 복사 | 마우스를 올려 **복사** | 데이터 전부 — 엑셀(칸이 나뉨) · 워드(표) |
| CSV 의 데이터를 문서 안으로 | **데이터를 문서 안으로 넣기** | CSV 를 읽어 차트의 원문에 값으로 — 문서만 보내도 다른 PC 에서 차트와 표가 보인다 (**Ctrl+Z** 로 되돌린다) |

표는 차트의 원문에서 읽는다 — 차트가 값을 거르거나 합쳐 그리면(변환 · 집계) 그 전의 값이다. 데이터가 CSV 파일에 있는 차트는 표 대신 파일 이름을 알린다. Lectern 슬라이드의 차트와 Graphviz 에는 단추가 없고, 단추와 표는 인쇄 · PDF 에 나오지 않는다.

## HTML 문서

AI 도구(Claude Code 등)가 만든 html 보고서도 문서로 본다.

| 상황 | 동작 |
|---|---|
| 트리 | `HTML` 표시와 함께 나온다 |
| 문서의 스타일 | 그대로 보인다 |
| 스크립트 · 인터넷 CSS | 막는다 — 스크립트로 그리는 차트는 보이지 않는다 |
| 앱 소스 폴더(`src` · `public` · `web` 등)의 html | 문서로 보지 않는다 |
| 고치기 | 전체 편집으로만 — [고치는 길 고르기](4.1-고치는-길-고르기.md) |
| 담기 | 하지 않는다 — 원문 줄이 없다 |
