# Writing styles and polish

> So reports are not written like developer documents — a writing style makes the AI write like a practitioner, a polish check fixes only what you pick, and a voice note keeps the rules of your own writing.

Claude Code's default role is a developer. Even when it writes a report, developer habits creep into the body: file paths, "**Bold label** — explanation" lists, arrows, "as follows:".

| What | What it does | Where |
|---|---|---|
| Writing style | Writes like a practitioner of that kind of writing — choose one of four | Settings window **Writing style** → **Choose a style…** |
| Polish check | Shows errors and hard-to-read spots in writing a person wrote as a table first, then fixes only what you pick | Right-click a document's margin, **Ask for a polish check** |
| My voice | Keeps a note, from writing you wrote yourself, of what to keep and which habits not to copy | Right-click a document's margin, **Send as a style sample** · Settings window **My style** |

In all three, Lectern only puts a request into the terminal (Enter is not pressed). Files are changed or installed only after the AI tool shows what it will do and asks, and you say yes.

## The four writing styles

All four drop developer and AI habits and reread when done. They differ in the standard they write to.

| Style | For | What is different |
|---|---|---|
| Research writing | Reports · review comments · analysis memos | The reader and the decision first, evidence widened beyond the folder and onto the web, a standard for each kind of document |
| Business report | One-page reports for approval, meeting papers | Bullet points by default, the conclusion and what the approver must do at the top, numbers against plan or last year, who does what by when, attachments |
| Academic writing | Papers · research reports · conference papers | Cites only sources it has checked (never invented), matches the strength of a claim to the evidence, units and uncertainty, limits |
| Plain explanation | Manuals · guides · training material | What the reader will be able to do first, short sentences and plain words, one action per numbered step, common snags in advance |

## The chooser

| Item on the left | What |
|---|---|
| The four in Lectern | The table above |
| Claude Code default | No style. **Claude Code default in this folder** switches where it is on to 'Turn off in …' (only when a folder is open — choosing a style afterwards switches it back to 'Turn on') |
| My writing styles | Output styles in your personal folder `~/.claude/output-styles` that are not Lectern's — they are only turned on |
| Make a new style | A request — builds a new style from the closest of the four, shows the draft, asks and saves it in your personal folder. Add what you write at the end |

On the right you see what it is for, what changes, **samples** (the start of what Claude Code actually wrote for the same request with no style and with that style), whether it is installed, and the style that applies in this folder now. **View source** shows the whole style file, and **Use this style** changes the chosen style in the settings window. Claude Code default and My writing styles show only when the AI tool is Claude Code. A new style you made appears under My writing styles when you open the settings window again, and Claude Code uses it after a restart.

## Installing and turning on

| Step | To do |
|---|---|
| 1 | With the folder where you write reports open, choose a style under **Writing style** in the settings window (**Ctrl+,**) |
| 2 | Choose where it is on — **Turn on in …** (default) · **Turn on in all folders** · **Turn off in …** (… is the open folder's name) |
| 3 | Check **Files that change** — the full paths of the style file (in `~/.claude/output-styles/`) and of the settings file that gets the value that turns it on |
| 4 | Press **▣** and Enter — the AI tool tells you how things stand and asks whether to install the style file (if it is missing or different) and turn it on |
| 5 | Say yes and it installs it and writes just the one value `"outputStyle"` in that settings file. Both files are inside a `.claude` folder, so Claude Code asks for permission once more — allow it if it matches what you saw in Files that change |
| 6 | If the style file was newly installed, quit Claude Code (`/exit`) and start it again |

| Case | What to do |
|---|---|
| A folder where you write code | Do not turn it on — all four drop the development instructions (stay in scope, check after changing). Your own writing style drops them unless its settings at the top have `keep-coding-instructions: true`. Choosing **Turn on in all folders** shows this warning |
| In a code folder after turning it on in all folders | Open that folder and send the request with **Turn off in …**, or pick the default with `/output-style` in Claude Code — a folder's value comes before the all-folders value |
| A different style for each folder | One style applies in a folder — the style files sit side by side in your personal folder, and only the value that turns one on differs per folder (Research writing in a reports folder, Business report in a folder of approval papers) |
| 'Change — Different from Lectern's' after updating Lectern | Install again with the same request |
| Codex · Antigravity · OpenCode | Instead of an output style, it goes in a 'Writing' section of the personal instruction file or of that folder's `AGENTS.md` — the tool asks first |

## Writing with Research writing

| What changes | How |
|---|---|
| Fits the kind of document | Narrative in paragraphs (the first sentence is the claim); bullet points with the conclusion in the top item and the evidence in the items under it. Bullet points are not treated as bad writing. Add "as bullet points" or "as narrative" and it writes that way |
| Drops developer habits | No file paths, code formatting, bold-label lists, arrows or task-report phrasing in the body; sources go by document name in a closing sources section |
| Cuts AI habits | Repeated "First, … Second, …", "it is judged that", chains of "Moreover" and "Also", a summary sentence at the end of every section, empty modifiers |
| Headings as claims | "June prices sit at the top of the forecast range" — skimming the headings alone gives the flow |
| Keeps to the length | In the PDF layout, one A4 page holds about 500 words of narrative, about 400 in bullet points |
| Rewrites awkward wording from the material | A table unit copied into a sentence ('230 thousand t' → '230,000 t'). Quoted sentences and the values of numbers stay as they are |

The other three share the developer and AI habits and the reread. Adding the reader, the purpose, the kind of document and the length to the request changes the writing most — for example: "So the purchasing manager can decide when to buy in Q3 — bullet points, one A4 page. Write it straight away, no outline." For a long piece it first shows an outline of the key claims and the page split, then stops.

## Polish check

| Step | To do |
|---|---|
| 1 | Right-click the margin of a md document you wrote (or edited) and choose **Ask for a polish check**. For a few lines only, pick the lines (**Shift+↓**) or focus the section (**Alt+H**), then right-click and choose **Ask for a polish check of this range** |
| 2 | Press Enter in the terminal — before any file changes, a table appears: number · group · where · original · proposed · why |
| 3 | Say what to apply — "errors only", "just 1, 3 and 7", "everything but preferences". Only the picked spots change and every other character stays; the changes show in Lectern right away |

| Group | What | Examples |
|---|---|---|
| Error | Only one right fix | spelling ("it's" for "its"), a word in the wrong sense ("principle" for "principal"), two words swapped so the sentence says the opposite |
| Hard to read | Not wrong, but the reader stumbles | redundancy ("past history"), nominalisations ("conduct a review of"), long sentences with tangled conditions, unexplained abbreviations |
| Preference | Both are fine | two accepted forms, set phrases that are the convention in some kinds of document |
| To check | Content, not wording | numbers that disagree, claims without visible support — reported only, never changed |

Quotations (in quotation marks or quote blocks, sentences taken from regulations), the values of numbers, names of institutions and laws, and words that are used correctly in context are left alone. If the same habit keeps coming back, it is listed at the end under "Came up often". If you just say "polish this", the AI tends to rewrite the content too without asking — the polish check request makes it show the table first.

## My voice

| Step | To do |
|---|---|
| 1 | Right-click the margin of something you wrote yourself (leave out writing done with an AI) and choose **Send as a style sample**. For several pieces, add `@paths` after the request from **My style** in the settings window — old reports written in Word or saved as PDF work too |
| 2 | The AI tool shows a draft note in three groups (table below) — nothing is saved yet |
| 3 | Tell it what to move or drop ("this is how I write, follow it", "drop this"), and when you say it is good it saves |
| 4 | Every sample you add adds to the note. Only what shows up in two or more pieces is noted, and examples are written fresh rather than copied from the samples — so even with a confidential report as a sample, figures and names do not leak into the note |

| Group | What | When it is used |
|---|---|---|
| Keep | Conventions the reader expects — register, terms, how numbers, units and dates are written | Always |
| Lean towards | What you like to do — sentence length, where the conclusion goes | Only when the kind of document and the reader match |
| Do not copy | Habits that make writing hard to read — redundancy, nominalisations, very long sentences | Not copied when writing, and looked for first in a polish check |

| Case | What happens |
|---|---|
| Where it is saved | For Claude Code, one personal rule file, `~/.claude/rules/my-voice.md` — the same note in every folder and every writing style. For other tools, a 'My style' section of the personal instruction file |
| When saving | It is inside the `.claude` folder, so Claude Code asks once more whether it may change it — allow it. Claude Code reads it after a restart |
| If, as in earlier versions, a 'My style' section is at the end of the style file | It asks whether to move it into this file |
| The kind of document for each item | Each item says where it was seen, such as 'Memos:', 'Narrative reports:' or 'All:' — so a memo's register does not spill into a report, and for a kind the note does not cover only the 'All:' items (terms, notation of numbers and dates, how sources are given) are used |
| When it clashes with the basics of report writing | Your style does not come first — conventions to keep are followed, and habits that make writing hard to read are not copied |
| Rules that differ by folder (an institution's template, a register) | Put them in that folder's `CLAUDE.md` |
