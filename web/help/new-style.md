# 내 글쓰기 스타일 만들기 — AI 용 안내 (Lectern)

사람이 자기 글에 맞는 글쓰기 스타일(Claude Code 의 출력 스타일)을 하나 만들어 달라고 할 때 읽는다. Lectern 설정 창의 '글쓰기 스타일 고르기 → 새 스타일 만들기' 요청 글이 이 안내의 경로를 주고, 사람이 원하는 글을 이어서 적는다.

## 차례

1. 사람이 원하는 글을 확인한다 — 누가 읽는 무슨 글인지, Lectern 에 든 스타일과 무엇이 달라야 하는지. 정말 알 수 없을 때만 짧게 묻는다.
2. Lectern 에 든 스타일 넷 가운데 가장 가까운 것을 바탕으로 고른다. 이 안내와 같은 폴더에 있다 — `research-writing.md`(보고서·검토 의견·분석 메모), `business-report.md`(결재·보고용 한 장 보고), `academic-writing.md`(논문·연구 보고서), `plain-explainer.md`(설명서·안내문·교육 자료). 영어판은 `.en.md`. 고른 것과 그 까닭을 알린다.
3. 바탕 스타일을 고쳐 새 스타일을 짓는다.
   - 맨 앞 설정(`---` 사이)에는 `name`(목록에 보일 이름 — Lectern 스타일의 이름과 겹치지 않게)과 `description`(한 줄)만 둔다. `keep-coding-instructions` 는 적지 않는다 — 코드가 아니라 글을 위한 스타일이다.
   - 첫 문단(누구로서 무엇을 쓰는지), '무엇을 먼저 따르나', '쓰기 전에', 그 글의 기준 절, '쓸 때', '쓴 뒤에'를 그 글에 맞게 고친다.
   - '남의 글을 옮기거나 다듬을 때'·'개발자 글버릇을 쓰지 않는다'·'AI 글버릇을 쓰지 않는다'·'답할 때' 네 절은 바탕의 것을 그대로 둔다. 그 글에서 꼭 달라야 할 것(학술 글의 인용 형식처럼)은 그 글의 기준 절에 적고 '이 점은 이 절이 앞선다'고 밝힌다.
   - 사람의 내 문체 노트(`~/.claude/rules/내-문체.md`)는 스타일에 옮겨 적지 않는다 — '무엇을 먼저 따르나'의 넷째 줄이 노트를 읽게 한다.
   - 사람이 견본 글을 주었으면 그 글의 짜임·분량·말투를 기준에 반영하되, 견본의 숫자·이름·문장은 옮기지 않는다.
4. 초안 전체를 대화에 보이고 고칠 것을 받는다. 이 단계에서는 파일을 쓰지 않는다.
5. 사람이 좋다고 하면 `~/.claude/output-styles/` 에 영문 소문자와 `-` 로 된 파일 이름(예: `weekly-brief.md`)으로 저장한다. 같은 이름의 파일이 있으면 바꿀지 다시 묻는다. 그 폴더는 `.claude` 안이라 Claude Code 가 쓰기 전에 허락을 한 번 더 묻는다.
6. 저장한 뒤 알린다 — Claude Code 를 다시 시작해야 읽는다는 것, 켜는 것은 Lectern 설정 창을 다시 열어 '글쓰기 스타일 고르기'의 '내 글쓰기 스타일'에서 골라 요청하거나 Claude Code 에서 `/output-style` 로 한다는 것, 이 스타일은 Claude Code 의 개발 지침을 빼므로 코드를 쓰는 폴더에서는 켜지 않는다는 것.

## 다른 AI 도구

Codex·Antigravity·OpenCode 에는 출력 스타일이 없다. 같은 차례로 짓되, 맨 앞 설정을 빼고 본문을 그 도구의 개인 지시 파일(Codex `~/.codex/AGENTS.md`, Antigravity `~/.gemini/AGENTS.md`, OpenCode `~/.config/opencode/AGENTS.md`)이나 그 프로젝트의 `AGENTS.md` 에 '글쓰기' 절로 넣을지 묻는다. 본문의 `##` 제목은 `###` 로 한 단계 내린다. 글쓰기 절은 한 파일에 하나만 둔다 — 이미 있으면 바꿀지 묻고, 그 안의 '내 문체' 부분은 그대로 남긴다.
