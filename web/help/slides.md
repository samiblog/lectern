# Lectern 발표 문서 작성 안내 (AI 용)

사용자가 슬라이드를 만들어 달라고 하면 이 안내대로 `.md` 파일 하나를 쓴다. 사람은 Lectern 의 슬라이드 창에서 보고, 칸 안의 글을 한 줄씩 고친다.

Marp 에서 출발했지만 Lectern 전용 형식이다. 다른 앱에서는 칸이 글자로 보인다. 발표 자료를 HTML 로 만들지 않는다.

## 1. 뼈대

```markdown
---
marp: true
title: 2026년 구리 시장 전망
paginate: true
footer: 원자재 리서치 · 2026-11
---

<!-- _class: lead -->
<!-- _paginate: false -->

# 2026년 구리 시장 전망

수요 둔화와 공급 차질 사이에서

---

<!-- layout: two -->

## 재고는 줄고 가격은 올랐다

::: a card
### 재고

거래소 재고는 **19.2만 t** 이다.
:::

::: b
| 분기 | 가격 |
|---|---:|
| 1Q | 8,650 |
| 2Q | 9,120 |
:::
```

- 맨 앞 설정의 `marp: true` 가 있어야 슬라이드가 된다.
- 장은 `---` 줄로 나눈다. 앞뒤에 빈 줄을 둔다.
- 슬라이드 크기는 1280×720 이다.
- 제목(`#`·`##`)은 칸 밖에, 한 장에 하나만 쓴다.
- 지시어는 그 장의 맨 앞에 HTML 주석으로 쓴다.
- 그 밖의 HTML 주석은 발표자 노트다. 장 안 어디에 써도 되고 칸 밖의 글로 치지 않는다. 마지막 칸 뒤에 두면 읽기 좋다.
- 표지·장 구분 같은 `lead` 장은 칸 없이 쓴다. 맨 앞 설정의 `footer` 는 `lead` 장에도 나온다.
- 각주는 쓰지 않는다. 출처는 칸 안에 짧게 쓰거나 노트에 쓴다.

## 2. 칸

`::: 이름 낱말…` 줄부터 `:::` 줄까지가 칸이다. 칸 안은 보통 Markdown 이다.

- 표, 목록, 박스글, 그림, 수식, Mermaid, 차트를 모두 넣을 수 있다.
- 머리 줄과 닫는 줄을 빠뜨리지 않는다. 칸을 다른 칸 안에 넣지 않는다.
- 배치가 있는 장의 글은 제목 말고는 모두 칸 안에 쓴다.

꾸밈 낱말:

| 낱말 | 모양 |
|---|---|
| `card` | 테두리 있는 카드 |
| `accent` | 강조 색 상자 |
| `dark` | 어두운 상자 |
| `note` | 노란 메모 |
| `kpi` | 큰 숫자 카드. 첫 줄의 `**숫자**` 가 크게 나온다 |
| `center` | 글을 위아래 가운데로 |
| `text-center` · `text-right` | 글을 가로 가운데·오른쪽으로 |
| `cols-2` · `cols-3` | 글을 2단·3단으로 |

낱말은 여럿 쓸 수 있다 (`::: b card center`, `::: a kpi accent`). 글이 적은 칸은 `center` 를 쓰면 위에 몰리지 않는다.

KPI 칸은 이렇게 쓴다.

```markdown
::: a kpi
**9,120**
LME 가격 ($/t)
:::
```

숫자를 더 키우려면 칸 크기를 쓴다 (`::: a kpi 28`). 숫자는 칸 크기의 약 2배로 나온다.

## 3. 배치

장마다 `<!-- layout: 이름 -->` 을 쓴다. 뒷장으로 물려주지 않는다.

| 이름 | 칸 | 모양 |
|---|---|---|
| `two` | a b | 좌우 반반 |
| `two-left` | a b | 왼쪽 2 : 오른쪽 1 |
| `two-right` | a b | 왼쪽 1 : 오른쪽 2 |
| `three` | a b c | 세 칸 |
| `quad` | a b c d | 2×2 |
| `left-stack` | a b c | 왼쪽 큰 칸 a, 오른쪽에 b 위 c 아래 |
| `right-stack` | a b c | 왼쪽에 a 위 c 아래, 오른쪽 큰 칸 b |
| `kpi` | a b c d e | 위에 작은 칸 넷, 아래에 넓은 칸 e |
| `kpi-two` | a b c d e | 위에 작은 칸 셋, 아래에 넓은 칸 d 와 작은 칸 e |
| `stack` | a b | 위아래 |

틀에 없는 배치는 격자로 쓴다. 칸 이름으로 그림을 그린다고 생각하면 된다. 줄은 `/` 로 나눈다.

```markdown
<!-- grid: a a b / c d b -->
<!-- cols: 1fr 1fr 1.2fr -->
<!-- rows: 1fr 1fr -->
```

- 격자에 `t` 를 쓰면 제목 자리다 (`t t / a b`). 제목을 쓰는 장은 `t` 를 넣는다. `t` 가 없는 격자에는 제목을 쓰지 않는다.
- `cols` 는 열마다, `rows` 는 줄마다 하나씩 적는다. `t` 줄도 센다 (`t t / a b / c d` 면 `rows` 는 셋). `1fr`·`auto`·`200px` 를 쓸 수 있다.
- `cols`·`rows` 는 적지 않아도 된다. 열은 같은 폭, 줄은 `t` 줄만 글 높이이고 나머지는 같은 높이가 된다.

자리를 직접 정할 칸은 `at x y 너비 높이` 를 쓴다. 단위는 px 이고 슬라이드의 왼쪽 위가 0 0 이다. `layout` 없이 쓴다.

```markdown
::: hub note at 460 250 300 120
### 철강 마진

스프레드가 핵심이다
:::
```

- 쓸 수 있는 곳은 x 56~1224, y 110~660 이다. 위는 제목, 아래는 꼬리말 자리다.
- 칸끼리, 또는 제목과 겹치면 점검에 나온다.
- 칸 사이를 잇는 선은 그리지 못한다. 선이 꼭 필요하면 `mermaid`·`dot` 으로 그린다. 그 글은 한 줄 편집이 안 된다. 사람이 글을 고쳐야 하면 작은 칸에 화살표 글자(→)를 쓴다.

## 4. 글자 크기

기본은 제목 30pt, 소제목 20pt, 본문 18pt, 표 14pt, 박스글 16pt, 코드 14pt 이다. PowerPoint 의 pt 와 같다. 스타일이 바뀌어도 크기는 그대로다.

바꿀 때는 필요한 만큼만 쓴다.

| 범위 | 쓰는 법 |
|---|---|
| 문서 전체 | 맨 앞 설정에 `text: 제목 26, 표 12` |
| 그 장 | `<!-- text: 표 12 -->` |
| 그 칸 | 칸 머리 줄에 수 (`::: b card 14`) |

구성 요소는 `제목` `소제목` `본문` `표` `박스글` `코드` 다. 영어 `title` `sub` `body` `table` `box` `code` 도 된다. 칸 크기를 쓰면 그 칸의 표·박스글도 같은 크기가 된다.

## 5. 분량 기준

글이 넘치면 줄어들지 않고 잘린다. 화면을 볼 수 없으므로 이 기준 안에서 쓴다. 칸의 글 양이 기준을 넘으면 장을 나눈다.

본문 한 줄은 35px, 소제목 한 줄은 50px, 표 한 행은 40px 이다. 18pt 한글은 한 줄에 칸 폭 ÷ 23 글자가 들어간다. 모두 약값이다.

| 배치 | 칸 | 크기(px) | 본문 줄 | 한 줄 글자 | 표 행 |
|---|---|---|---:|---:|---:|
| `two` | a b | 575×555 | 15 | 24 | 12 |
| `two-left` | a | 767×555 | 15 | 32 | 12 |
| `two-left` | b | 383×555 | 15 | 16 | 12 (3열까지) |
| `two-right` | a | 383×555 | 15 | 16 | 12 (3열까지) |
| `two-right` | b | 767×555 | 15 | 32 | 12 |
| `three` | a b c | 377×555 | 15 | 16 | 12 (3열까지) |
| `quad` | a b c d | 575×270 | 7 | 24 | 5 |
| `left-stack` | a | 690×555 | 15 | 29 | 12 |
| `left-stack` | b c | 460×270 | 7 | 19 | 5 |
| `right-stack` | a c | 460×270 | 7 | 19 | 5 |
| `right-stack` | b | 690×555 | 15 | 29 | 12 |
| `kpi` | a b c d | 279×144 | 숫자 + 1줄 | 11 | 쓰지 않는다 |
| `kpi` | e | 1168×397 | 11 | 50 | 9 |
| `kpi-two` | a b c | 377×144 | 숫자 + 1줄 | 15 | 쓰지 않는다 |
| `kpi-two` | d | 773×397 | 11 | 33 | 9 |
| `kpi-two` | e | 377×397 | 11 | 16 | 9 (3열까지) |
| `stack` | a b | 1168×270 | 7 | 50 | 5 |

- `card`·`accent`·`dark`·`note` 칸은 안쪽 여백이 있어 폭 32px, 높이 24px 가 줄어든다.
- 격자·`at`·`cols-2` 칸은 칸 크기로 어림한다. 격자의 쓸 수 있는 폭은 1168, 높이는 제목을 빼고 555 다.
- 글자 크기를 바꾸면 비례해서 달라진다. 표를 12pt 로 줄이면 표 행이 35px 이 된다.
- 한 장의 글은 짧게 쓴다. 문단보다 짧은 목록이 낫다.
- 차트·다이어그램·그림은 칸에 맞게 줄어든다. 글은 줄어들지 않는다.

## 6. 차트와 그림

차트는 코드 블록으로 쓴다. `vega-lite`, `echarts`, `plotly`, `dot`, `mermaid` 를 쓸 수 있다. 칸 안의 차트는 칸의 폭과 남은 높이에 맞춰 그려진다. 같은 칸에 제목이나 글을 함께 써도 된다.

- `vega-lite`: `"width": "container"` 를 쓰고 `height` 는 쓰지 않는다. 값은 `data.url` 이나 문서 안의 `data.values` 로 준다.
- `echarts`: ECharts 의 option 을 JSON 으로 쓴다. `height`·`width` 는 쓰지 않는다.
- `plotly`: `{"data": […], "layout": {…}}` JSON 으로 쓴다. 지도 종류는 쓰지 않는다.
- 설정은 JSON 값만 쓴다. 함수는 안 된다.
- 차트의 값은 한 줄 편집으로 고치지 못한다. 사람은 Ctrl+E 로 고친다. 자주 바뀌는 값은 CSV 로 빼면 표로 고칠 수 있다.

```vega-lite
{
  "width": "container",
  "data": {"url": "data/월별.csv"},
  "mark": "line",
  "encoding": {
    "x": {"field": "월", "type": "ordinal", "sort": null},
    "y": {"field": "가격", "type": "quantitative", "scale": {"zero": false}}
  }
}
```

- `data` 의 경로와 그림 경로는 **이 md 파일이 있는 폴더 기준**의 상대 경로다.
- 다른 폴더의 문서를 바꿀 때는 경로를 다시 확인한다. 새 파일은 원본과 같은 폴더에 둔다.
- 인터넷 주소의 자료는 읽지 않는다.
- 금액의 `$` 는 그대로 쓴다 (`$11,220`, `$/t`). 수식은 `$x$` 처럼 `$` 바로 뒤와 닫는 `$` 바로 앞이 빈칸이 아니고 닫는 `$` 뒤에 숫자가 없을 때만이다.

그림 문법:

- `![w:300 대체 글](images/a.png)` 그림 크기. 대체 글을 함께 써도 된다.
- 칸 안의 그림은 칸에 맞게 줄어든다. 같은 칸에 글을 쓰면 글이 먼저 자리를 차지한다.
- `![bg right:40%](images/a.png)` 배경을 오른쪽 40% 에. 왼쪽은 `left`.
- `![bg](a.png)` 를 두 줄 쓰면 배경이 나뉜다.
- `![bg sepia](a.png)` 필터 (`blur`, `grayscale`, `sepia` 등).

## 7. 지시어

| 지시어 | 뜻 |
|---|---|
| `<!-- _class: lead -->` | 이 장을 표지처럼 가운데로. 장 구분에도 쓴다 |
| `<!-- _class: invert -->` | 이 장을 어둡게 |
| `<!-- _backgroundColor: #17293d -->` | 이 장의 바탕색 |
| `<!-- _paginate: false -->` | 이 장의 쪽 번호 빼기 |
| `<!-- eyebrow: 시장 요약 -->` | 제목 위의 작은 머리글 |

`_` 를 앞에 붙이면 그 장만이다. `_` 가 없는 `class`·`backgroundColor` 는 뒷장으로 이어진다. `layout`·`grid`·`text`·`eyebrow` 는 늘 그 장만이다.

## 8. HTML 장

칸으로 안 되는 장만 HTML·SVG 로 쓴다. **그런 장은 사람이 한 줄 편집으로 고칠 수 없다.** 차트의 값도 고치기 어렵다. 먼저 칸과 `at` 으로 만들 수 있는지 본다.

- 장별 CSS 는 `<style scoped>` 로 쓴다. 그 장에만 적용된다. `section` 이 그 슬라이드다.
- `<style>` 은 문서 전체에 적용된다. 맨 앞 설정의 `style: |` 도 같다.
- 스크립트는 돌지 않는다. 인터넷 CSS·글꼴은 지워진다.

## 9. 다 쓴 뒤

Lectern 이 넘침과 잘못 쓴 칸을 상태줄의 '점검'에 모은다. 사용자가 그 목록을 터미널에 붙여 넣어 주면 이렇게 고친다.

| 점검 글 | 고치는 법 |
|---|---|
| 칸 a 이(가) 120px 넘칩니다 | 글을 줄이거나 장을 나눈다. 표면 그 장의 표 글자를 줄인다 |
| 칸 a 이(가) 옆으로 80px 넘칩니다 | 표의 열을 줄이거나 넓은 칸으로 옮긴다 |
| 칸 a 이(가) 제목과 겹칩니다 | `at` 의 y 를 110 이상으로 |
| 칸 a 과(와) 칸 b 이(가) 겹칩니다 | `at` 의 자리를 옮긴다 |
| 칸 a 이(가) 슬라이드 밖으로 나갑니다 | x+너비 1224, y+높이 660 안으로 |
| 칸 z 이(가) 배치에 없습니다 | 칸 이름을 배치의 칸으로 고친다 |
| 칸 c 이(가) 비어 있습니다 | 칸을 쓰거나 배치를 바꾼다 |
| 칸 a 의 닫는 ::: 가 빠졌습니다 | 닫는 줄을 넣는다 |
| 칸 밖에 글이 있습니다 | 글을 칸 안으로 옮긴다 |
| 배치 'x' 이(가) 없습니다 | 위 표의 이름을 쓴다 |

`칸 a 이(가) 120px 넘칩니다 (칸 높이 300px)` 라면 본문 네 줄이나 표 세 행을 줄이면 된다.

## 10. 좋은 슬라이드

- 제목은 주제가 아니라 결론을 쓴다 (`재고는 줄고 가격은 올랐다`).
- 장마다 말할 것 하나. 배치는 내용에 맞게 고른다.
- 숫자 넷이면 `kpi`, 비교는 `two`·`three`, 그림과 설명은 `left-stack`.
- 첫 장은 `lead`, 큰 주제가 바뀌면 `lead` 장을 넣는다.
- 설명은 발표자 노트에 쓴다.
