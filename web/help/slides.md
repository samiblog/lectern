# Lectern 슬라이드 작성 안내 (AI 용)

사용자가 슬라이드를 만들어 달라고 하면 이 안내대로 `.md` 파일 하나를 쓴다. 사람은 Lectern 의 슬라이드 창에서 보고, 칸 안의 글을 한 줄씩 고친다.

Marp 에서 출발했지만 Lectern 전용 형식이다. 다른 앱에서는 칸이 글자로 보인다. 발표 자료를 HTML 로 만들지 않는다.

## 1. 뼈대

```markdown
---
marp: true
title: 2026년 구리 시장 전망
paginate: true
footer: 원자재 리서치 · 2026-11
---

<!-- _class: lead -->
<!-- _paginate: false -->

# 2026년 구리 시장 전망

수요 둔화와 공급 차질 사이에서

---

<!-- layout: two -->

## 재고는 줄고 가격은 올랐다

::: a card
### 재고

거래소 재고는 **19.2만 t** 이다.
:::

::: b
| 분기 | 가격 |
|---|---:|
| 1Q | 8,650 |
| 2Q | 9,120 |
:::
```

- 맨 앞 설정의 `marp: true` 가 있어야 슬라이드가 된다.
- 장은 `---` 줄로 나눈다. 앞뒤에 빈 줄을 둔다.
- 슬라이드 크기는 1280×720 이다. 4:3 은 맨 앞 설정에 `size: 4:3` 을 쓴다. 그때는 960×720 이고 쓸 수 있는 폭은 848 이다. 5장의 폭은 16:9 기준이니 0.7 배로 어림한다.
- 제목(`#`·`##`)은 칸 밖에, 한 장에 하나만 쓴다.
- 지시어는 그 장의 맨 앞에 HTML 주석으로 쓴다.
- 그 밖의 HTML 주석은 발표자 노트다. 장 안 어디에 써도 되고 칸 밖의 글로 치지 않는다. 마지막 칸 뒤에 두면 읽기 좋다. `<!-- 출처: 통계청 -->` 처럼 콜론을 써도 된다. 지시어 이름(`layout`, `text`, `class` 등)으로 시작할 때만 지시어다. 코드 블록 안의 주석은 코드다.
- 표지·장 구분 같은 `lead` 장은 칸 없이 쓴다. 맨 앞 설정의 `footer`·`header` 는 `lead` 장에도 나온다. 그 장에서 빼려면 `<!-- _footer: '' -->` 를 쓴다.
- 각주는 쓰지 않는다. 출처는 칸 안에 짧게 쓰거나 노트에 쓴다.

## 2. 칸

`::: 이름 낱말…` 줄부터 `:::` 줄까지가 칸이다. 칸 안은 보통 Markdown 이다.

- 표, 목록, 박스글, 그림, 수식, Mermaid, 차트를 모두 넣을 수 있다.
- 머리 줄과 닫는 줄을 빠뜨리지 않는다. 칸을 다른 칸 안에 넣지 않는다.
- 칸 안에서 줄을 바꾸면 그대로 줄이 바뀐다. 문단을 나누려면 빈 줄을 쓴다.
- 굵은 글이 문장부호로 끝나면 닫는 `**` 뒤에 글자를 바로 붙이지 않는다. `**8.0%**로` 는 별표가 보인다. `**8.0%** 로` 나 `**8.0%로**` 로 쓴다.
- 박스글은 `> [!NOTE]` 로 쓴다. `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` 도 된다.
- 배치가 있는 장의 글은 제목 말고는 모두 칸 안에 쓴다.

꾸밈 낱말:

| 낱말 | 모양 |
|---|---|
| `card` | 테두리 있는 카드 |
| `accent` | 강조 색 상자 |
| `dark` | 어두운 상자 |
| `note` | 노란 메모 |
| `kpi` | 큰 숫자 카드. `**숫자**` 가 크게 나온다. 설명 줄에는 `**` 를 쓰지 않는다 (같이 커진다). 목록은 넣지 않는다 |
| `center` | 글을 위아래 가운데로 |
| `text-center` · `text-right` | 글을 가로 가운데·오른쪽으로 |
| `cols-2` · `cols-3` | 글을 2단·3단으로. 단은 문단과 목록 사이에서 나뉜다 |

낱말은 여럿 쓸 수 있다 (`::: b card center`, `::: a kpi accent`). 칸은 장의 높이를 나눠 갖는다. 글이 적은 칸은 `center` 를 쓰면 위에 몰리지 않는다. 표도 글 높이만큼만 그려지니 짧은 표가 든 칸은 `center` 를 쓴다.

어두운 장(`invert`, `lead`)의 칸·표·코드는 장의 색을 따른다. 흰 상자가 되지 않는다. `note` 칸만 노란 상자로 남는다.

KPI 칸은 이렇게 쓴다.

```markdown
::: a kpi
**9,120**
LME 가격 ($/t)
:::
```

숫자의 색은 스타일의 강조색이다. 바꾸려면 내 낱말에 `.낱말 strong { color: #… }` 를 쓴다. 숫자를 더 키우려면 칸 크기를 쓴다 (`::: a kpi 28`). 숫자는 칸 크기의 약 2배로 나오고 설명 줄은 칸 크기로 나온다. 기본은 칸 크기 18pt 에 숫자 34pt 다. 낱말의 차례는 상관없다 (`::: a kpi accent center 24`, `::: b card at 100 200 300 120 16`).

## 3. 배치

장마다 `<!-- layout: 이름 -->` 을 쓴다. 뒷장으로 물려주지 않는다.

| 이름 | 칸 | 모양 |
|---|---|---|
| `two` | a b | 좌우 반반 |
| `two-left` | a b | 왼쪽 2 : 오른쪽 1 |
| `two-right` | a b | 왼쪽 1 : 오른쪽 2 |
| `three` | a b c | 세 칸 |
| `quad` | a b c d | 2×2 |
| `left-stack` | a b c | 왼쪽 큰 칸 a, 오른쪽에 b 위 c 아래 |
| `right-stack` | a b c | 왼쪽에 a 위 c 아래, 오른쪽 큰 칸 b |
| `kpi` | a b c d e | 위에 작은 칸 넷, 아래에 넓은 칸 e |
| `kpi-two` | a b c d e | 위에 작은 칸 셋, 아래에 넓은 칸 d 와 작은 칸 e |
| `stack` | a b | 위아래 |

`kpi` 에서 카드 하나를 빼면 그 자리가 빈다. 카드가 셋이면 `kpi-two` 로 바꾸거나 격자로 쓴다 (`<!-- grid: t t t / a b c / e e e -->`, `<!-- rows: auto auto 1fr -->`).

틀에 없는 배치는 격자로 쓴다. 칸 이름으로 그림을 그린다고 생각하면 된다. 줄은 `/` 로 나눈다.

```markdown
<!-- grid: a a b / c d b -->
<!-- cols: 1fr 1fr 1.2fr -->
<!-- rows: 1fr 1fr -->
```

- 격자에 `t` 를 쓰면 제목 자리다 (`t t / a b`). 제목을 쓰는 장은 `t` 를 넣는다. `t` 가 없는 격자에는 제목을 쓰지 않는다.
- `cols` 는 열마다, `rows` 는 줄마다 하나씩 적는다. `t` 줄도 센다 (`t t / a b / c d` 면 `rows` 는 셋). `1fr`·`auto`·`200px` 를 쓸 수 있다.
- `cols`·`rows` 는 적지 않아도 된다. 열은 같은 폭, 줄은 `t` 줄만 글 높이이고 나머지는 같은 높이가 된다.
- 칸 하나로 슬라이드를 채우려면 `<!-- grid: t / a -->` 를 쓴다.
- `.` 은 빈 자리다 (`<!-- grid: t t t / a . b / . c . -->`). 칸을 쓰지 않아도 점검에 나오지 않는다.
- 줄과 열의 수에는 제한이 없다. 13열 간트나 35칸 달력도 된다. `<!-- cols: 120px repeat(12, 1fr) -->` 처럼 `px`, `fr`, `repeat()` 를 쓴다.
- 칸 색은 내 낱말과 CSS 로 준다. 칸의 굵은 글은 따라오고 소제목은 스타일의 색이 남는다.

```markdown
<style scoped>
.risk { background: #c0392b; color: #fff; }
.risk h3 { color: inherit; }
</style>

::: a card risk
```

- 세로 글자는 `.axis { writing-mode: vertical-rl; text-orientation: sideways; transform: rotate(180deg); }` 로 쓴다.
- `accent` 의 색은 스타일마다 다르다. 범례에 색 이름을 쓰지 않는다.

자리를 직접 정할 칸은 `at x y 너비 높이` 를 쓴다. 단위는 px 이고 슬라이드의 왼쪽 위가 0 0 이다. `layout` 없이 쓴다.

```markdown
::: hub note at 460 250 300 120
### 제품 마진

스프레드가 핵심이다
:::
```

- 쓸 수 있는 곳은 x 56~1224, y 110~660 이다. 위는 제목, 아래는 꼬리말 자리다. `eyebrow` 가 있어도 같다.
- `at` 칸끼리(작은 칸의 10% 넘게), 또는 제목과 겹치면 점검에 나온다. 4:3 에서는 x 56~904 다.
- 이 범위는 제목과 꼬리말이 있는 장의 기준이다. 쪽을 꽉 채우는 장은 그림을 `![bg]` 로 깐다.
- 그림만 든 `at` 칸은 칸 높이를 그림보다 12px 쯤 크게 잡는다.
- 격자 위에 `at` 칸을 얹을 수 있다. 격자 칸과의 겹침은 점검하지 않는다.

칸 사이의 선은 `links` 로 긋는다. 칸의 글은 그대로 한 줄 편집이 된다. 칸 이름을 쉼표로 잇는다.

```markdown
<!-- links: cost>hub, freight>hub, hub<>demand, hub--note -->
```

- `a>b` 는 화살표, `a<>b` 는 양쪽 화살표, `a--b` 는 선이다. 선은 직선이고 글자를 붙일 수 없다. 예·아니오 같은 글은 선 가운데에 작은 칸을 놓는다.
- `at` 칸에도 격자 칸에도 쓴다. 선은 칸 가운데를 잇고 칸 테두리에서 끝난다.
- 칸을 조금 떨어뜨려 놓는다. 붙어 있으면 선이 보이지 않는다.
- 한 쌍의 칸 사이에는 선이 하나다. 같은 두 칸 사이에 선이 여럿이면 그림으로 둔다.
- 선의 색과 굵기는 문서 CSS 로 바꾼다 (`section { --lec-link-color: #c2410c; --lec-link-width: 3; }`).

## 4. 글자 크기

기본은 제목 30pt, 소제목 20pt, 본문 18pt, 표 14pt, 박스글 16pt, 코드 14pt 이다. PowerPoint 의 pt 와 같다. 스타일이 바뀌어도 크기는 그대로다.

바꿀 때는 필요한 만큼만 쓴다.

| 범위 | 쓰는 법 |
|---|---|
| 문서 전체 | 맨 앞 설정에 `text: 제목 26, 표 12` |
| 그 장 | `<!-- text: 표 12 -->` |
| 그 칸 | 칸 머리 줄에 수 (`::: b card 14`) |

구성 요소는 `제목` `소제목` `본문` `표` `박스글` `코드` 다. 영어 `title` `sub` `body` `table` `box` `code` 도 된다. 칸 크기를 쓰면 그 칸의 표·박스글도 같은 크기가 되고 소제목은 1.15배가 된다.

**표는 12pt, 본문은 14pt 아래로 내리지 않는다.** 넘친다고 글자만 줄이지 말고 글을 줄이거나 장을 나눈다. 화면에 띄우지 않고 읽는 자료면 맨 앞 설정에 `reading: true` 를 쓴다. 그때 기준은 표 10pt, 본문 12pt 다. 기준 아래면 점검에 나온다. `reading` 은 점검의 기준만 바꾸고 글자 크기를 바꾸지 않는다.

`lead` 장에서 `#` 제목은 제목 크기의 1.45배로 나온다. 쓸 수 있는 곳은 16:9 에서 약 1112×592, 4:3 에서 약 792×592 다.

## 5. 분량 기준

글이 넘치면 줄어들지 않고 잘린다. 화면을 볼 수 없으므로 이 기준 안에서 쓴다. 칸의 글 양이 기준을 넘으면 장을 나눈다.

본문 한 줄은 35px, 소제목 한 줄은 50px, 표 한 행은 40px 이다. 18pt 한글은 한 줄에 칸 폭 ÷ 23 글자가 들어간다. 모두 약값이다.

| 배치 | 칸 | 크기(px) | 본문 줄 | 한 줄 글자 | 표 행 |
|---|---|---|---:|---:|---:|
| `two` | a b | 575×555 | 15 | 24 | 12 |
| `two-left` | a | 767×555 | 15 | 32 | 12 |
| `two-left` | b | 383×555 | 15 | 16 | 12 (3열까지) |
| `two-right` | a | 383×555 | 15 | 16 | 12 (3열까지) |
| `two-right` | b | 767×555 | 15 | 32 | 12 |
| `three` | a b c | 377×555 | 15 | 16 | 12 (3열까지) |
| `quad` | a b c d | 575×270 | 7 | 24 | 5 |
| `left-stack` | a | 690×555 | 15 | 29 | 12 |
| `left-stack` | b c | 460×270 | 7 | 19 | 5 |
| `right-stack` | a c | 460×270 | 7 | 19 | 5 |
| `right-stack` | b | 690×555 | 15 | 29 | 12 |
| `kpi` | a b c d | 279×144 | 숫자 + 1줄 | 11 | 쓰지 않는다 |
| `kpi` | e | 1168×397 | 11 | 50 | 9 |
| `kpi-two` | a b c | 377×144 | 숫자 + 1줄 | 15 | 쓰지 않는다 |
| `kpi-two` | d | 773×397 | 11 | 33 | 9 |
| `kpi-two` | e | 377×397 | 11 | 16 | 9 (3열까지) |
| `stack` | a b | 1168×270 | 7 | 50 | 5 |

- `card`·`accent`·`dark`·`note`·`kpi` 칸은 안쪽 여백이 있어 폭 32px, 높이 24px 가 줄어든다.
- 같은 칸에 소제목이나 글을 함께 쓰면 그만큼 표 행이 줄어든다.
- 격자·`at`·`cols-2` 칸은 칸 크기로 어림한다. 격자의 쓸 수 있는 폭은 1168, 높이는 제목을 빼고 555 다. 칸 사이는 가로 18px, 세로 14px 이다.
- 제목은 한 줄에 약 30자, 소제목은 칸 폭 ÷ 26 글자가 들어간다. 목록은 들여쓴 만큼 폭이 약 40px 줄어든다.
- 영문은 한글의 약 1.6 배가 들어간다 (18pt 는 칸 폭 ÷ 14). 한 낱말이 칸보다 길면 낱말 가운데서 끊긴다.
- 코드는 줄이 바뀌지 않는다. 14pt 한 줄은 칸 폭 ÷ 11 글자, 높이 29px 이다. 넘치면 점검에 나오니 줄을 나눈다.
- 표 행의 수에는 머리행이 든다.
- `eyebrow` 는 제목 위의 빈 자리에 놓여 칸의 높이를 줄이지 않는다.
- 글자 크기를 바꾸면 비례해서 달라진다. 표를 12pt 로 줄이면 표 행이 35px 이 된다.
- 한 장의 글은 짧게 쓴다. 문단보다 짧은 목록이 낫다.
- 차트·다이어그램·그림은 칸에 맞게 줄어든다. 글은 줄어들지 않는다.

## 6. 차트와 그림

차트는 코드 블록으로 쓴다. `vega-lite`, `echarts`, `plotly`, `dot`, `mermaid` 를 쓸 수 있다. 칸 안의 차트는 칸의 폭과 남은 높이에 맞춰 그려진다. 같은 칸에 제목이나 글을 함께 써도 된다.

- `vega-lite`: `"width": "container"` 를 쓰고 `height` 는 쓰지 않는다. 값은 `data.url` 이나 문서 안의 `data.values` 로 준다.
- `echarts`: ECharts 의 option 을 JSON 으로 쓴다. `height`·`width` 는 쓰지 않는다.
- `plotly`: `{"data": […], "layout": {…}}` JSON 으로 쓴다. 지도 종류는 쓰지 않는다.
- 설정은 JSON 값만 쓴다. 함수는 안 된다.
- `data.url` 은 `vega-lite` 만 읽는다. `echarts`·`plotly` 는 값을 설정에 쓴다.
- ECharts 의 범례는 기본이 아래다. `"legend": {"top": 0}` 으로 올리거나 `grid.bottom` 을 56 이상으로 둔다.
- 차트 설정의 px 은 슬라이드에서 약 1.7배로 그려진다. 도넛의 `innerRadius` 는 칸 높이의 1/6 쯤으로 쓴다.
- 칸 안의 `vega-lite` 는 축과 범례까지 칸에 맞춰 그려진다. 같은 칸에 글이 많으면 차트가 낮아진다.
- `vega-lite` 축의 숫자 형식은 `",d"` 로 쓴다. `","` 만 쓰면 `1.5e+4` 처럼 나온다.
- 칸의 `center` 는 차트·다이어그램에도 듣는다.
- 체크 칸은 사람이 눌러 바꾼다. 원문의 `[ ]`·`[x]` 를 고쳐도 된다.
- `vega-lite` 의 `layer` 는 축의 `scale`·`sort` 를 모든 층에 같게 쓴다. 한 층에만 쓰면 듣지 않는다. 정렬은 값의 배열로 준다 (`"sort": ["1월", "2월"]`).
- 차트의 값은 한 줄 편집으로 고치지 못한다. 사람은 Ctrl+E 로 고친다. 자주 바뀌는 값은 CSV 로 뺀다. Lectern 의 CSV 화면은 보기만 하니 표 프로그램이나 Claude 가 고친다. 고친 뒤 F5 를 누르면 차트가 새 값으로 그려진다.

```vega-lite
{
  "width": "container",
  "data": {"url": "data/월별.csv"},
  "mark": "line",
  "encoding": {
    "x": {"field": "월", "type": "ordinal", "sort": null},
    "y": {"field": "가격", "type": "quantitative", "scale": {"zero": false}}
  }
}
```

- `data` 의 경로와 그림 경로는 **이 md 파일이 있는 폴더 기준**의 상대 경로다.
- 다른 폴더의 문서를 바꿀 때는 경로를 다시 확인한다. 새 파일은 원본과 같은 폴더에 둔다.
- 인터넷 주소의 자료는 읽지 않는다.
- 금액의 `$` 는 그대로 쓴다 (`$11,220`, `$/t`). 수식은 `$x$` 처럼 `$` 바로 뒤와 닫는 `$` 바로 앞이 빈칸이 아니고 닫는 `$` 뒤에 숫자가 없을 때만이다.

그림 문법:

- `![w:300 대체 글](images/a.png)` 그림 크기. 대체 글을 함께 써도 된다. 칸보다 크면 비율을 지켜 칸에 맞게 줄어든다.
- 파일 이름에 빈칸·괄호가 있으면 `![공정](<images/공정 흐름 (최종).svg>)` 처럼 `<…>` 로 감싼다.
- 칸 안의 그림은 칸에 맞게 줄어든다. 같은 칸에 글을 쓰면 글이 먼저 자리를 차지한다.
- `![bg right:40%](images/a.png)` 배경을 오른쪽 40% 에. 왼쪽은 `left`. 칸과 격자는 남은 폭으로 줄어든다. 그림을 자르지 않으려면 `contain` 을 더한다.
- `![bg](a.png)` 를 여러 줄 쓰면 줄 수만큼 나란히 나뉜다. 겹치지는 않는다. `![bg vertical](a.png)` 은 위아래로 나눈다.
- `![bg sepia](a.png)` 필터. `blur`, `brightness:.6`, `contrast`, `grayscale`, `hue-rotate`, `invert`, `opacity`, `saturate`, `sepia:50%` 를 쓴다.
- 사진 위의 글은 점검이 대비를 재지 못한다. 사진을 어둡게 하고 `invert` 를 쓴다 (`![bg brightness:.5](a.png)`). 글이 길면 `dark` 칸에 넣는다. 어두운 장의 `dark` 칸은 반투명 검은 받침이다.

## 7. 지시어

| 지시어 | 뜻 |
|---|---|
| `<!-- _class: lead -->` | 이 장을 표지처럼 가운데로. 장 구분에도 쓴다 |
| `<!-- _class: invert -->` | 이 장을 어둡게 |
| `<!-- _backgroundColor: #17293d -->` | 이 장의 바탕색 |
| `<!-- _color: #ffd27f -->` | 이 장의 글자색. 제목, 굵은 글, 링크도 따른다 |
| `<!-- _paginate: false -->` | 이 장의 쪽 번호 빼기 |
| `<!-- _footer: '' -->` | 이 장의 꼬리말 빼기 (`_header` 도 같다) |
| `<!-- eyebrow: 시장 요약 -->` | 제목 위의 작은 머리글 |
| `<!-- hidden: true -->` | 숨긴 장. 발표와 PDF 에서 빠진다. pptx 로 내보내면 숨긴 슬라이드가 된다 |

`_` 를 앞에 붙이면 그 장만이다. `_` 가 없는 `class`·`backgroundColor` 는 뒷장으로 이어진다. `layout`·`grid`·`text`·`eyebrow`·`hidden` 은 늘 그 장만이다. `_class` 는 이어진 `class` 에 더하지 않고 바꾼다. 둘을 함께 쓰려면 `<!-- _class: lead invert -->` 처럼 다 적는다.

표의 정렬은 `---:` 오른쪽, `:---:` 가운데로 쓴다. 쓰지 않으면 수가 70% 넘는 열을 앱이 글자 칸까지 오른쪽으로 맞춘다. 합계 행처럼 한 행을 눈에 띄게 하려면 그 장에 CSS 를 쓴다. 어두운 색을 깔면 글자색도 함께 정한다.

```markdown
<style scoped>
tbody tr:last-child td { font-weight: 700; background: #fff1e6; }
</style>
```

## 8. HTML 장

글 안의 `<u>`·`<sub>`·`<sup>`·`<br>` 은 칸에서 그냥 써도 된다. 한 줄 편집도 된다. 칸으로 안 되는 장만 HTML·SVG 로 쓴다. **그런 장은 사람이 한 줄 편집으로 고칠 수 없다.** 차트의 값도 고치기 어렵다. 먼저 칸과 `at` 으로 만들 수 있는지 본다. `<style scoped>` 만 쓴 장은 칸의 글을 그대로 고칠 수 있다. 문서의 HTML 은 장 안에서 닫힌다. 닫지 않은 태그가 다음 장으로 넘어가지 않는다.

- 장별 CSS 는 `<style scoped>` 로 쓴다. 그 장에만 적용된다. `section` 이 그 슬라이드다.
- `<style>` 은 문서 전체에 적용된다. 맨 앞 설정의 `style: |` 도 같다.
- 슬라이드의 내용은 세로 가운데가 기본이다. 위에서 시작하려면 `section { justify-content: flex-start; }` 를 쓴다.
- 스크립트는 돌지 않는다. `@import`·`@font-face`·`@keyframes`·중첩 규칙·`position: fixed`·`url()`(데이터 그림 말고)은 지워진다. `url()` 이 든 줄임 속성에 변수를 함께 쓰면 그 규칙 전체가 지워진다.

## 9. 다 쓴 뒤

Lectern 이 넘침과 잘못 쓴 칸을 상태줄의 '점검'에 모은다. 사용자가 그 목록을 터미널에 붙여 넣어 주면 이렇게 고친다.

| 점검 글 | 고치는 법 |
|---|---|
| 칸 a 이(가) 120px 넘칩니다 | 글을 줄이거나 장을 나눈다. 표면 그 장의 표 글자를 줄인다 |
| 칸 a 이(가) 옆으로 80px 넘칩니다 | 표의 열을 줄이거나 넓은 칸으로 옮긴다 |
| 칸 a 이(가) 제목과 겹칩니다 | `at` 의 y 를 110 이상으로 |
| 칸 a 과(와) 칸 b 이(가) 겹칩니다 | `at` 의 자리를 옮긴다 |
| 칸 a 이(가) 슬라이드 밖으로 나갑니다 | x+너비 1224, y+높이 660 안으로 |
| 표가 10pt 로 작습니다 (기준 12pt) | 글을 줄이거나 장을 나눈다. 읽는 자료면 `reading: true` |
| 선의 칸 x 이(가) 없습니다 | `links` 의 칸 이름을 고친다 |
| 칸 z 이(가) 배치에 없습니다 | 칸 이름을 배치의 칸으로 고친다 |
| 칸 c 이(가) 비어 있습니다 | 칸을 쓰거나 배치를 바꾼다 |
| 칸 a 의 닫는 ::: 가 빠졌습니다 | 닫는 줄을 넣는다 |
| 칸 밖에 글이 있습니다 | 글을 칸 안으로 옮긴다 |
| 배치 'x' 이(가) 없습니다 | 위 표의 이름을 쓴다 |
| 칸 표시로 읽지 못했습니다 | 줄 맨 앞에 `::: 이름`, 콜론 셋과 빈칸 |
| 짝이 맞지 않는 ::: 가 있습니다 | 머리 줄이나 닫는 줄을 맞춘다 |
| 칸 a 이(가) 두 번 나옵니다 | 칸 이름을 장마다 하나씩 쓴다 |
| 칸 a 의 낱말 'x' 을(를) 모릅니다 | 꾸밈 낱말을 고친다. 내 CSS 의 낱말이면 `.x` 규칙을 쓴다 |
| 칸 a 의 'x' 을(를) 읽지 못했습니다 | 글자 크기는 수만, 자리는 `at x y 너비 높이` |
| 'x' 은(는) 지시어가 아니어서 노트로 읽었습니다 | 지시어 이름을 고친다 |
| 글자 크기 'x' 을(를) 읽지 못했습니다 | `표 14` 처럼 쓴다 |
| 격자의 줄마다 칸 수가 같아야 합니다 | 줄마다 같은 수로 쓴다 |
| 격자를 읽지 못했습니다 | 칸 이름은 글자와 숫자, 빈 자리는 점 |
| 아래가 120px 잘렸습니다 | 칸 밖의 글을 줄이거나 장을 나눈다 |
| 격자의 칸 a 이(가) 네모가 아닙니다 | 같은 이름은 네모로 이어지게 쓴다 |
| cols 값 'x' 을(를) 읽지 못했습니다 | `1fr 2fr` 처럼 쓴다 |
| 주석이 닫히지 않아 뒤의 글이 보이지 않습니다 | `-->` 를 쓴다 |
| 코드 블록이 닫히지 않아 뒤의 글이 코드가 됐습니다 | 닫는 줄을 쓴다 |
| --- 바로 위에 글이 있어 … | `---` 위에 빈 줄을 넣는다 |
| 글자가 바탕과 비슷해 보이지 않습니다 | 글자색이나 바탕을 고친다 |
| 코드가 옆으로 80px 잘렸습니다 | 줄을 나눈다 |
| 그림을 찾을 수 없습니다 | 경로를 고친다. 이 md 파일 기준이다 |
| 그림을 그리지 못했습니다 | 차트·다이어그램의 설정이나 자료 경로를 고친다. 까닭이 글에 나온다 |
| 굵게로 읽지 못한 별표가 있습니다 | 닫는 `**` 뒤에 빈칸을 둔다 |

`칸 a 이(가) 120px 넘칩니다 (칸 높이 300px)` 라면 본문 네 줄이나 표 세 행을 줄이면 된다.

## 10. 좋은 슬라이드

- 제목은 주제가 아니라 결론을 쓴다 (`재고는 줄고 가격은 올랐다`).
- 장마다 말할 것 하나. 배치는 내용에 맞게 고른다.
- 숫자 넷이면 `kpi`, 비교는 `two`·`three`, 그림과 설명은 `left-stack`.
- 첫 장은 `lead`, 큰 주제가 바뀌면 `lead` 장을 넣는다.
- 설명은 발표자 노트에 쓴다. 노트는 PDF 에 들어가지 않는다.
- 읽는 자료는 칸마다 출처를 쓰지 말고 격자의 맨 아래 줄을 출처 칸으로 둔다.

## 11. Marp 문서 옮기기

그대로 듣는 것: `headingDivider`, `paginate`, `header`, `footer`, `class`, `_class`, `backgroundColor`, `color`, `![bg …]`, `![w:300]`, `<style>`, `<style scoped>`, 수식.

| Marp | Lectern 에서 |
|---|---|
| `theme: gaia` | 듣지 않는다. 사람이 슬라이드 창의 스타일을 고른다 |
| `<!-- fit -->` | 듣지 않는다. 표지 제목은 이미 크다 |
| `<div class="columns">` | 보이기는 하지만 한 줄 편집이 어렵다. `layout: two` 와 칸으로 옮긴다 |
| `@import` 웹 글꼴 | 지워진다. 인터넷에서 받지 않는다 |
| `animation`·`@keyframes` | 지워진다 |
| `<!-- _class: invert -->` 의 칸 | 어두운 상자가 된다 |

옮길 때는 글을 빠뜨리지 말고, 옮기지 못한 효과를 사용자에게 알린다.

## 12. 예제

Lectern 의 예제 프로젝트 `slides/README.md` 에 상황별 모범 발표 10개와 처음부터 만드는 과정이 있다. 설치 폴더의 `samples/slides/` 다. 경영 요약, 대안 비교, 시장 분석, 원인 지도, 시나리오, 월간 보고, 기술 세미나, 사진 기록, 로드맵, 문서에서 발표로가 있다. 비슷한 상황이면 그 예제의 칸 쓰임을 따른다. 대시보드, 잡지 지면, 프로세스 지도, 간트, 달력, 위험표 같은 복잡한 배치 20가지는 `slides/복잡한-배치/README.md` 에 있다.

## 13. PowerPoint 와 주고받기

사용자가 pptx 를 Lectern 슬라이드로 옮기거나, pptx 를 참고해 md 를 슬라이드로 만들거나, 슬라이드를 pptx 로 내보내라고 하면 Claude Code 스킬 `pptx-to-lectern`·`lectern-to-pptx` 를 쓴다. 이 스킬들은 Lectern 프로그램 폴더의 `skills/` 에 들어 있다 (설치본은 `_internal\skills`).

스킬이 아직 설치되어 있지 않으면 먼저 사용자에게 설치할지 묻는다. 그렇다고 하면 두 폴더를 `~/.claude/skills/` 로 복사한다. 아니라고 하면 그 폴더의 `SKILL.md` 를 읽고 그 자리의 스크립트로 한다.
