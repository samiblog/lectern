# Lectern 에서 잘 보이는 문서 쓰기 — AI 용 작성 안내

이 안내는 Claude Code 같은 AI 가 읽는다. 사람은 **Lectern**(Markdown을 중심으로 AI와 함께 작업하는 Windows용 통합 리서치 작업 환경)으로 프로젝트 폴더의 문서를 읽고 그 자리에서 고친다. 아래 규칙대로 쓰면 표·목차·다이어그램·차트가 제대로 보이고, 사람이 Lectern 에서 고른 위치(`@경로 12~20행`)를 AI 에게 다시 건넬 수 있다.

**형식은 글을 보이게 하는 것이고, 글의 질이 먼저다.** 아래 규칙은 Lectern 에서 제대로 보이게 하는 법일 뿐, 좋은 글을 만들지는 않는다. 쓰기 전에 누가 읽고 읽은 뒤 무엇을 판단해야 하는지 정한다. 폴더 자료에서 멈추지 말고 지난 자료와 웹에서 배경과 반대 근거를 찾아 출처를 남긴다. 개조식 나열보다 문단으로 쓰고, 다 쓴 뒤에는 읽는 사람이 되어 처음부터 다시 읽고 고친다. 보고서를 자주 쓰는 사람에게는 Lectern 설정 창의 '글쓰기 스타일'(Claude Code 의 출력 스타일)이 이 일을 세션 전체에 걸어 둔다.

해야 할 일이 '이 프로젝트의 CLAUDE.md 에 규칙을 정리해 넣기'라면, 맨 끝의 **CLAUDE.md 에 넣을 요약**을 그 프로젝트에 맞게 줄여 넣고, 이 안내의 전체 경로를 함께 적어 표·차트·슬라이드를 쓸 때 다시 읽게 한다. 프로젝트의 CLAUDE.md 가 형식 규칙집이 되지 않게, 그 프로젝트의 읽는 사람·목적·말투를 형식 규칙보다 앞에 둔다. 예제는 Lectern 설치 폴더의 `samples` (Lectern 에서 '예제 열기') — 특히 `samples/CLAUDE.md` 와 `samples/guide/04-문서-쓰는-법.md`.

## 1. Lectern 이 보는 것

- 문서: Markdown(`.md`)과 HTML(`.html`). 그 밖의 파일은 사이드바의 '코드'(소스·설정) 또는 '자료'(CSV·PDF·엑셀·그림 등) 목록에 나오고, 코드는 줄 번호와 언어 색으로 읽기만 한다.
- 보이지 않는 것: 이름이 `.` 으로 시작하는 파일·폴더, Windows 숨김·시스템 파일, 심볼릭 링크·정션, 문서가 없는 폴더, 제외 폴더(`node_modules`·`__pycache__`·`venv`·`env`·`dist`·`build`·`target`·`site-packages`·`htmlcov`).
- 앱 소스 폴더(`src`·`public`·`static`·`templates`·`web`·`www`·`frontend`·`out`) 안의 html 은 문서로 보지 않는다 — 웹앱 화면이지 보고서가 아니라서. 사람이 읽을 HTML 보고서는 `reports/` 같은 다른 폴더에 둔다.
- Lectern 은 보기 앱이다. 문서를 만들거나 지우지 않는다. 사람이 편집 모드로 고칠 수 있는 것은 UTF-8 글 파일, 2MB 까지.
- 파일이 바뀌면 1~2초 안에 다시 그리고 바뀐 블록을 잠깐 표시한다. 같은 문서를 조금씩 고쳐도 된다.

## 2. 파일과 제목

- 문서 제목: frontmatter 의 `title` → 없으면 첫 `# 제목`. 문서마다 `#` 제목은 하나만 둔다 (목차에서 빠지고 문서 제목이 된다).
- 요약(폴더 개요에 보임): frontmatter 의 `description` → 없으면 첫 문단(160자). 첫 문단을 한두 문장의 요약으로 쓴다.
- 순서가 있는 문서는 `01-`, `02-` 처럼 번호로 시작한다. 정렬은 숫자를 수로 비교한다 (`2-` 가 `10-` 앞).
- 파일 이름에 한글을 써도 된다. 빈칸 대신 `-` 를 쓴다.
- frontmatter 는 맨 위 `---` 와 `---` 사이의 YAML 이다. 문서 위에 '메타데이터' 상자로 보인다.

```markdown
---
title: 리서치 자동화 구현 계획
description: 가격 자료 수집부터 보고서 배포까지 세 단계
status: 진행 중
---

# 리서치 자동화 구현 계획
```

## 3. Markdown

### 제목

`##` → `###` → `####` 순서로, 단계를 건너뛰지 않는다. 오른쪽 목차, 절 접기(제목 왼쪽의 화살표·Ctrl+Shift+[), 장 하이라이트(한 `##` 절씩 보기)가 이 단계를 따른다. 절이 길면 `###` 로 나눈다.

### 문단과 줄바꿈

- 문단 안에서 Enter 로 바꾼 줄은 화면에서도 줄이 바뀐다 (Word 의 Shift+Enter 처럼). 개조식으로 쓰려면 그대로 줄을 바꾸면 된다.
- 그래서 한 문장을 폭에 맞춰 여러 줄로 끊어 쓰지 않는다 — 문장 하나는 한 줄에.

### 표

- 칸에는 값만, 단위는 머리행에: `| 가격 (USD/t) |`.
- 숫자로 읽히는 열은 저절로 오른쪽 정렬된다. 숫자로 읽히는 칸: `1,234`, `-3.5%`, `+3.2%p`, `$105`, `105.2달러`, `12억`, `1.2x`, `30bp`, 빈 값 `-`.
- 긴 표는 머리행이 위에 붙어 있으므로 나누지 않아도 된다.
- 첫 열(구분·항목)은 짧게 — 길면 Lectern 이 첫 열을 넓혀 맞추지만(다른 열보다 여러 줄로 감길 때), 짧은 이름표가 가장 읽기 좋다. 설명은 오른쪽 열에.
- **캡션**: 표 바로 위에 `표 1. 제목` 한 줄(또는 통째로 굵게 쓴 한 줄 — `**〈표 2〉 항만별 물동량**`)을 두면 목차·모아 보기에서 그 표의 이름이 된다. 그림은 바로 아래에 `그림 1. 제목`, 다이어그램·차트는 바로 위에. `<표 3>`·`[그림 2]`·`〈표 Ⅱ-15〉`·`표 3-1.` 도 된다.

### 할 일·출처·문서 정보

- 할 일은 체크리스트로 (`- [ ] 할 것`, 끝나면 `- [x]`) — Lectern 의 모아 보기가 프로젝트의 안 한 일을 모아 보인다.
- 표·그림의 출처는 바로 아래 한 줄에 `자료: 기관명 (연도)` (또는 `출처:`)로 — 모아 보기의 '출처'에 모인다. 각주(`[^1]`)도 출처로 모인다.
- 계획·결정·보고 문서는 맨 앞 설정에 `status`·`owner`·`updated`(YYYY-MM-DD)·`tags: [a, b]` 같은 키를 같은 이름으로 — 모아 보기의 '문서 정보'가 키마다 값으로 묶는다.
- 사람이 Lectern 의 '담기'로 다른 문서의 조각을 넣으면 조각 앞에 `<!-- 담은 곳: 경로 a~b행 -->` 주석이 붙는다. 출처 기록이니 문서를 고칠 때 지우지 않는다 (화면에는 보이지 않는다). 조각을 옮겨 오라는 요청을 받으면 같은 주석을 남긴다.

### 강조글 (callout)

인용의 첫 줄에 종류를 적는다. 다섯 가지뿐이다.

```markdown
> [!NOTE]
> 참고할 내용.
```

`[!NOTE]` 참고 · `[!TIP]` 팁 · `[!IMPORTANT]` 중요 · `[!WARNING]` 경고 · `[!CAUTION]` 주의. 그 밖의 `>` 는 보통 인용이다.

Lectern 은 강조글에 제목 줄('참고'·'팁' 같은 종류 이름)을 붙이지 않는다 — 종류는 색으로만 보인다. 제목이 필요하면 첫 줄을 굵게 쓴다:

```markdown
> [!TIP]
> **표는 숫자만**
> 단위는 머리행에 적는다.
```

### 박스글

본문의 흐름과 떨어진 주제를 가볍게 다룰 때 쓴다 — 보고서의 '박스'·'참고'. 주석 두 줄 사이에 보통 Markdown 으로 쓴다.

```markdown
<!-- box -->
**박스 1. 구리 재고와 가격의 관계**

재고가 줄면 가격이 오른다는 통념은 2020년 이후 약해졌다.

| 연도 | 재고 (만 t) | 가격 (USD/t) |
|---|---|---|
| 2023 | 12 | 8,500 |

자료: LME
<!-- /box -->
```

- Lectern 은 테두리와 제목 띠가 있는 상자로 그린다. 다른 뷰어에서는 주석이 보이지 않아 굵은 제목과 보통 글로 읽힌다 — `:::` 같은 표시를 쓰지 않는 까닭이다.
- 여는 줄 `<!-- box -->` 과 닫는 줄 `<!-- /box -->` 은 줄을 통째로 쓴다 (같은 줄에 다른 글을 쓰지 않는다). 닫는 줄이 없으면 다음 제목 앞에서 끝난다.
- 첫 줄이 제목이다 — 한 줄로 쓴다. `**박스 1. 제목**` 처럼 번호를 붙이면 `[박스 1](#박스-1)` 로 가리킬 수 있고, 사람이 박스글을 더하거나 옮기면 Lectern 이 번호와 링크를 함께 고친다. 번호는 1부터 차례대로.
- 안에는 문단·목록·표·그림·차트·수식·강조글·각주를 쓴다. 제목(`#`)과 다른 박스글은 넣지 않는다 — 박스글은 절이 아니라 구성 요소이고, 한 절 안에 둔다.
- 안의 표·그림 번호는 본문과 이어서 센다 (표 3 다음의 박스글 안 표는 표 4).
- 강조글(`> [!NOTE]`)과 다르다: 강조글은 한두 문장을 눈에 띄게, 박스글은 따로 읽을 만한 분량을 담는다. Lectern 슬라이드에는 박스글이 없다.
- 사람이 Lectern 의 'Claude 에 박스글 요청'으로 '대화를 정리해 `@경로 12행` 바로 뒤에 박스글로'라고 하면, 그 줄 바로 뒤에 빈 줄을 두고 박스글 하나만 넣는다. 번호는 요청에 적힌 대로, 그 밖의 줄은 고치지 않는다. 대화를 옮겨 적지 말고 문서에 남길 결론·근거·남은 질문만 추린다.

### 그 밖의 블록

- 목록, 번호 목록, 체크리스트(`- [ ]`, `- [x]` — 사람이 칸을 누르면 원문의 표시가 바뀌어 저장된다).
- 각주: 본문에 `[^1]`, 아무 곳에 `[^1]: 내용`. 문서 끝에 모인다.
- 표·그림을 가리킬 때는 링크로: `[표 3](#표-3)`, `[그림 2](#그림-2)` (캡션 단락이 그 자리다). 사람이 표를 넣거나 옮기면 Lectern 이 캡션 번호와 이 링크를 함께 고친다 — 글자로만 쓴 '표 3' 은 고치지 않는다.
- 참고문헌은 `## 참고문헌` 절에 목록으로, 본문 인용은 `(저자, 연도)`. 사람이 그 목록에서 골라 인용을 넣는다.
- 문서 안 목차는 `[목차]` 한 줄 (`[표 목차]`·`[그림 목차]` 도), 쪽 나눔은 `<div style="page-break-after: always;"></div>` 한 줄 — 둘 다 인쇄·PDF 를 위한 것이다.
- 코드 블록: 언어를 적는다 (```` ```python ````). 색이 입혀지고 복사 버튼이 생긴다.
- HTML 조각: `<details><summary>…</summary>…</details>` 로 접는 내용. `<script>`·`<style>`·`<form>`·이벤트 속성(`onclick` 등)은 지워진다.

### 링크와 위치

- 다른 문서·그림·자료는 **이 문서 기준 상대경로**로: `[계획](../plans/구현-계획.md)`, `![그림](images/x.svg)`.
- 절 링크: `문서.md#제목-글자` — 제목을 소문자로, 빈칸은 `-`, 기호는 뺀다 (`## 가격 범위` → `#가격-범위`, 한글은 그대로).
- 코드 위치: 본문에 `src/report.py:14` (또는 `src/report.py#L14`, `src/report.py`)를 쓰면 프로젝트에 그 파일이 있을 때 링크가 되고, 누르면 코드 화면의 그 줄로 간다. 문장 속 인라인 코드(`` `src/report.py:14` ``)도 내용 전체가 경로면 링크가 된다. 코드 블록 안은 링크가 되지 않는다.
- 절대경로(`C:\…`, `file:///…`)는 프로젝트 안일 때만 열린다. 상대경로를 쓴다.
- 인터넷 링크는 기본 브라우저로 열린다. 인터넷 그림은 사람이 설정에서 끌 수 있으니, 꼭 보여야 할 그림은 프로젝트 안에 파일로 둔다.

### 수식

- 문장 안: `$…$` 또는 `\(…\)`. 줄 하나: `$$…$$` 또는 `\[…\]`. ```` ```math ````·```` ```latex ```` 코드 블록도 수식이 된다.
- 달러 금액은 수식이 아니다: 여는 `$` 바로 뒤나 닫는 `$` 바로 앞이 빈칸이거나, 닫는 `$` 바로 뒤가 숫자이면 글자로 둔다 (`$105에서 $110`, `$95~$110/t`).

## 4. 다이어그램과 차트

코드 블록의 언어로 정한다. 모두 움직이지 않는 그림(SVG)이 되고, 색은 사람이 고른 문서 스타일을 따른다. 그리지 못하면 그 자리에 원문과 까닭이 보인다.

| 언어 | 라이브러리 | 쓸 때 |
|---|---|---|
| `mermaid` | Mermaid 12 | 흐름도·시퀀스·상태·간트·마인드맵·타임라인·ER, 간단한 차트(`xychart-beta`·`pie`·`sankey-beta`) |
| `vega-lite` (`vega`) | Vega-Lite 6 | 데이터 차트 — 막대·선·면적·산점도·히트맵, 겹친 차트, 프로젝트의 CSV·JSON 읽기 |
| `echarts` | ECharts 6 | 종류가 많은 차트 — 도넛·캔들·게이지·레이더·생키 |
| `plotly` | Plotly 4 | 분석 차트 — 상자 그림·히스토그램·선버스트·폭포. Python 의 `fig.to_json()` 결과 그대로 |
| `dot` (`graphviz`) | Graphviz | 노드가 많은 구성도·의존 관계의 자동 배치 |

규칙:

- **설정은 JSON 값만.** 함수(`formatter: function…`, `=>`)는 돌리지 않으므로 오류가 된다. ECharts 의 `formatter` 는 `'{b}\n{d}%'` 같은 문자열 틀을 쓴다. ECharts 예제처럼 `option = { … }`, 따옴표 없는 키, 작은따옴표, 주석, 끝 쉼표는 읽는다.
- **데이터는 차트 안에.** 데이터는 `"data": {"values": [...]}` 로 차트 안에 적는 것이 기본이다 — 문서만 보내도 다른 PC 에서 차트가 그려지고, 사람은 차트의 [표] 단추로 그 값을 표로 보고 엑셀로 복사한다. 프로젝트의 CSV 를 가리키는 것(`"data": {"url": "../data/x.csv"}`, 문서 기준 상대경로)은 행이 수백 개를 넘거나 다른 프로그램이 갱신하는 작업용 자료일 때만 쓴다 — CSV 는 문서와 함께 가지 않을 수 있다.
- **인터넷에 닿지 않는다.** 인터넷 주소의 데이터, 차트 속 인터넷 그림, Plotly 의 지도 종류(scattergeo·choropleth·mapbox)는 쓰지 않는다. 차트 속 링크는 풀린다.
- **크기.** 문서 폭에 맞추려면 Vega-Lite 는 `"width": "container"` 와 `"height"`, ECharts 는 `"height"`(Lectern 만 읽는 키, 기본 360)만, Plotly 는 `layout.height`(기본 400)만 적는다. 폭을 숫자로 적으면 그 크기로 그린다.
- **색.** 정하지 않으면 스타일 색이 쓰인다 (밝은·어두운 스타일 모두 읽히게). 색을 정하면 그대로 쓰인다. Plotly 는 `layout.template` 이 있으면 그것을 따른다.
- **제목.** Vega-Lite·ECharts 는 `title`, Plotly 는 `layout.title`, Graphviz 는 그래프 이름(`digraph 이름 {`)이 목차·모아 보기의 이름표가 된다.
- **Mermaid** 의 한글 축 이름·글자는 따옴표로 감싼다 (`x-axis ["1월", "2월"]`). 참여자 이름은 `participant U as 사람` 처럼 영문 별칭을 쓴다.
- **Graphviz** 는 한글 상자 폭을 앱이 맞춘다. 글꼴(`fontname`)은 정하지 않는 편이 낫다.

## md 문서 스타일

사용자가 md 문서 스타일을 만들어 달라고 하면 Lectern 설정 폴더의 `md-styles` 에 `이름.json` 파일 하나를 쓴다 (`%APPDATA%\\Lectern\\md-styles`). 있는 파일을 덮어쓰지 않는다. Lectern 전체가 함께 쓴다.

```json
{"kind": "prose", "marks": ["제{1}장", "제{1}절", "{1}.", "{가}.", "{1})", "{가})"]}
```

- `kind` 는 서술식이면 `prose`, 개조식이면 `outline` 이다.
- `marks` 는 머리글 단계마다의 틀 글자다. 6개까지, 하나에 16자까지. 첫째가 문서 제목 다음 단계다. 번호가 없는 단계는 빈 글자다.
- 틀 글자: `{1}` 숫자, `{I}` 로마 숫자, `{가}` 한글, `{①}` 동그라미 숫자, `{path}` 1.1.1. 나머지 글자는 그대로 쓴다.

## 5. Lectern 슬라이드

맨 앞 설정에 `marp: true` 가 있는 md 는 **슬라이드**로 보인다. Marp 에서 출발한 Lectern 의 발표 형식이다. 칸(`::: a card`)과 배치(`<!-- layout: quad -->`)로 장마다 다른 배치를 만든다. 사람은 슬라이드 안의 글을 한 줄씩 고친다.

**발표 자료를 만들거나 고칠 때는 이 파일 옆의 `slides.md` 를 먼저 읽는다.** 문법·배치·글자 크기·분량 기준이 거기에 있다. 발표 자료를 HTML 로 만들지 않는다.

### 자료 (CSV·텍스트)

- 표로 모은 자료는 CSV 로 둔다 — Lectern 에서 누르면 표로 보이고(열마다 거르기·정렬·통계), 차트의 `data.url` 로도 읽는다. **첫 줄은 머리행**(열 이름), 칸에는 값만, 단위는 머리행에 (`가격(USD/t)`). UTF-8 로 저장한다 (엑셀의 CP949 도 읽지만 편집은 UTF-8 만).
- 문서에서 자료를 가리킬 때는 링크(`[월별 가격](../data/월별-가격.csv)`)나 `data/월별-가격.csv:5` 처럼 — 누르면 표의 그 행으로 간다.

## 업무 카드 — WORK.md

프로젝트 폴더 맨 위의 `WORK.md` 는 그 폴더의 **업무 카드**다. Lectern 이 여러 폴더의 WORK.md 를 모아 업무 현황(상태·마감·할 일·일정)과 알림으로 보여 준다. 사람은 Claude 없이도 이 파일을 쓰고 고친다 — Claude 가 쓸 때도 사람이 그대로 이어서 고칠 수 있게 같은 형식을 지킨다.

```markdown
---
status: 진행
priority: 상
due: 2026-12-15
---

# 시장분석 보고서

이 과제를 한 줄로.

## 현재 상태

## 할 일

- [ ] 초안 3장 작성 (2026-11-14)

## 일정

- 2026-11-12 14:00-15:00 팀장 1차 보고
- 2026-11-20 종일 원자재 세미나

## 결정

## 기록

### 2026-11-10

- 팀장 1차 보고. 범위를 국내로 좁힘

## 자료
```

- **머리 설정 세 키만 읽는다**: `status`(예정·진행·지연위험·막힘·보류·완료·중단 — 영어 `planned`·`active`·`at-risk`·`blocked`·`on-hold`·`done`·`dropped` 도 된다), `priority`(상·중·하), `due`(`YYYY-MM-DD`). 키 이름을 바꾸거나 값을 꾸미지 않는다. 다른 키를 더하는 것은 된다 (모아 보기 '문서 정보'로 묶인다).
- **할 일**: `- [ ] 내용 (YYYY-MM-DD)` — 줄 끝 괄호의 날짜가 기한이다 (`(11/14)` 도 된다). 끝내면 `[x]`.
- **일정**: `- YYYY-MM-DD HH:MM 내용`, 끝나는 시각은 `HH:MM-HH:MM`, 하루 종일은 `종일`. 날짜는 늘 절대값으로 쓴다 — '내일'·'금요일'처럼 쓰지 않는다. 시각이 있는 일정은 10분 전에 알린다.
- **기록**: 날짜마다 `### YYYY-MM-DD`, 최신 날짜가 위, 그 아래 한 줄씩. 한번 적은 기록은 고치지 않는다.
- 절 이름과 차례는 권장이다. Lectern 은 절에 기대지 않고 머리 설정과 할 일·일정의 줄 모양만 본다. 일정 줄은 '일정' 절에 모은다 (사람이 일정 더하기로 넣는 자리다).
- 과제 밖의 일정·할 일(회의·행정)은 공통 폴더의 `WORK.md` 에 쓴다. 과제 하나의 사실(상태·마감·할 일·일정)은 그 과제의 WORK.md 에만 둔다 — 정리 문서에 다시 쓰지 않는다.
- 업무 현황은 화면이다. 현황을 파일로 만들어 두지 않는다.
- 업무 현황의 '확인할 줄'은 이 형식을 벗어난 줄이다 (정해지지 않은 상태 값, 키 이름 오타, 읽지 못한 날짜·시각, `- []` 같은 체크 칸, 닫히지 않은 머리 설정). 사람이 그 줄을 건네면 형식에 맞게 고친다.

## 6. HTML 문서

- 자기 스타일(`<style>`)을 그대로 보여 준다. 스타일이 없으면 Lectern 의 문서 스타일을 입힌다.
- **스크립트는 돌지 않는다.** JS 차트(Chart.js·Plotly 의 HTML 내보내기 등)는 빈칸이 된다. 차트는 정적 SVG 로 그려 넣거나, Markdown 문서의 차트 코드 블록으로 만든다.
- 인터넷의 CSS·글꼴·스크립트는 막힌다. 스타일은 문서 안에 둔다.
- `<title>` 이 제목, `<meta name="description">` 이 요약, `h1`~`h4` 가 목차가 된다. `h2` 에 `id` 를 주면 절 링크가 된다.
- 문서·그림 링크는 상대경로로 (`../research/x.md#전망`) — Lectern 안에서 열린다.

## 8. 하지 않을 것

- HTML 보고서에 JS 차트를 넣지 않는다 (보이지 않는다).
- 차트 설정에 함수·인터넷 주소를 넣지 않는다.
- 문서를 `node_modules`·`dist`·`build`·`.` 폴더에 두지 않는다 (보이지 않는다).
- 사람이 읽을 HTML 을 `src`·`web` 같은 앱 소스 폴더에 두지 않는다.
- 한 문서에 `#` 제목을 여럿 두거나 제목 단계를 건너뛰지 않는다.
- 표의 칸에 단위·설명을 섞지 않는다 (숫자 열 정렬이 깨진다).
- 슬라이드 한 장에 긴 글을 넣지 않는다 (아래가 잘린다).
