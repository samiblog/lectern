# pptx → Lectern 슬라이드

사람이 Lectern 에서 읽고 한 줄씩 고칠 수 있는 Lectern 슬라이드를 만든다. 원본과 똑같이 만드는 것이 목적이 아니다. **내용은 빠짐없이, 구조는 살려서, 모양은 인상만.**

원본 pptx 는 그대로 남고, 변환기록이 쪽마다 원본과 이어 준다. 그래서 md 가 pptx 의 모든 것을 들고 있을 필요가 없다. 나중에 pptx 로 되돌릴 때 고치지 않은 쪽은 원본 쪽을 그대로 쓸 수 있다.

이 스킬에는 두 길이 있다. 사용자의 말로 고른다.

- **옮기기**: "이 pptx 를 Lectern 슬라이드로". 아래 순서를 따른다.
- **참고해 만들기**: "이 pptx 를 참고해서 이 md 를 슬라이드로". 맨 아래 장을 따른다.

## 스크립트 돌리기

아래의 `<실행기>` 는 이 차례로 고른다. 사용자가 Python 을 설치하지 않아도 된다.

1. Lectern 스킬 실행기 `%LOCALAPPDATA%\Programs\Lectern\lectern-skill.exe`. Python, pywin32, Pillow 가 들어 있다. Bash 에서는 `"$LOCALAPPDATA/Programs/Lectern/lectern-skill.exe"`, PowerShell 에서는 `& "$env:LOCALAPPDATA\Programs\Lectern\lectern-skill.exe"` 로 부른다.
2. 없으면 `python` (3.10 이상).
3. 둘 다 없으면 Lectern 을 어디에 설치했는지 사용자에게 묻는다. 그 폴더에 `lectern-skill.exe` 가 있다.

실행기는 스킬의 `scripts` 폴더 안 파일만 돌린다. 다른 Python 코드는 돌리지 못한다.

## 무엇을 지키고 무엇을 버리나

| 수준 | 대상 | 어떻게 |
|---|---|---|
| 꼭 지킨다 | 모든 글, 쪽의 수와 차례, 표, 그림, 차트 값, 노트, 링크 | 빠지면 실패다. `verify.py` 가 잰다 |
| 구조를 살린다 | 제목, 목록 단계, 굵게, 칸 배치, 표지·장 구분, 큰 숫자 | Lectern 칸과 격자로 |
| 인상만 살린다 | 테마 색, 로고, 표지 배경, 제목 색, 칸 색, 꼬리말, 쪽 번호 | 문서 CSS 와 지시어로 |
| 그림으로 남긴다 | 칸으로 짜면 뜻이 깨지는 도식 | 쪽 그림을 오려 넣고 글은 노트에 |
| 버린다 | 애니메이션, 전환, 정확한 글꼴·좌표, 그림자, 리본·띠 같은 장식 도형, 3D | 버린 것을 보고한다 |

숨긴 쪽은 `<!-- hidden: true -->` 로 남는다. 발표와 PDF 에서 빠지고 되돌리면 숨긴 쪽이 된다.

옮길 때 지키는 약속이다. 이것이 스킬 없이 옮길 때와 다른 점이다.

- **쪽 하나는 쪽 하나로.** 쪽 번호가 어긋나면 되돌릴 수 없다. 넘친다고 쪽을 나누지 말고 칸 크기를 줄이거나 `reading: true` 를 쓴다.
- **원문을 바꾸지 않는다.** 요약, 다듬기, 번역을 하지 않고 없던 제목을 짓지 않는다. 글의 책임은 사용자에게 있다. 오타는 고치지 말고 보고에 적는다.
- **그림 속 글을 받아 적지 않는다.** 스크린샷의 표나 코드를 타이핑하면 대조할 원문이 없어 틀려도 모른다. 그림으로 두고, 사용자가 원하면 그때 옮긴다.
- **CSS 로 도형을 그리지 않는다.** 리본이나 겹친 원을 CSS 로 흉내 내면 비슷해 보여도 사람이 고칠 수 없고 스타일을 바꾸면 깨진다. 칸의 색 정도까지만 쓴다.
- **쪽 그림을 배경으로 깔지 않는다.** 글자만 지운 쪽 그림 위에 글을 얹으면 똑같아 보이지만 그림을 옮길 수 없고 되돌릴 때도 쓸 수 없다. '느낌을 살려 달라'는 요청이어도 색, 로고, 원본 그림 파일로 살린다.
- **안 보이던 글은 노트로.** 쪽 밖의 글, 흰 바탕의 흰 글자처럼 원본 화면에 없던 글은 쪽에 드러내지 않는다.
- **검토 메모는 옮기지 않는다.** 내부 메모가 문서로 새지 않게 있었다는 사실만 알린다.

## 순서

### 1. 초안을 만든다

```bash
<실행기> <이 스킬>/scripts/convert.py 원본.pptx 출력폴더 --name 문서이름
```

사용자가 **PowerPoint 에 띄워 둔 발표**를 말하면 ("지금 열어 둔 ppt", "화면에 띄운 발표") 파일 경로 없이 이렇게 한다.

```bash
<실행기> <이 스킬>/scripts/convert.py --active 출력폴더
```

앞쪽 창의 발표를 옮긴다. 저장하지 않은 수정도 들어가고, 띄워 둔 발표는 저장하지도 닫지도 않는다. 출력의 `log` 에 다른 발표가 열려 있다고 나오면 어느 것을 옮겼는지 알린다. 다른 것이면 `--pick 이름의일부` 로 다시 돈다. 출력폴더를 모르면 사용자에게 묻는다. `source` 가 비어 있으면 저장한 적 없는 발표다.

출력폴더를 정하지 않았으면 원본과 같은 폴더다. 몇 초면 끝난다. 스크립트가 알아서 고른다:

- 읽기는 ZIP 안 XML 로 먼저 한다 (빠르고 PowerPoint 가 없어도 된다).
- ZIP 으로 못 여는 파일(.ppt, DRM)은 PowerPoint 로 pptx 사본을 받아 읽고, 사본이 막히면 PowerPoint 에서 직접 읽는다. `pywin32` 가 필요하다. 파일이 DRM 으로 안 열리면 PowerPoint 에 띄워 놓고 `--active` 로 옮기는 길도 있다.
- PowerPoint 가 있으면 쪽 그림을 뽑고 EMF 를 PNG 로 받는다. 도식을 그림으로 자르려면 `Pillow` 도 필요하다.

둘 다 실행기에 들어 있다. `python` 으로 돌릴 때 없으면 `pip install pywin32 pillow` 를 제안한다. 설치가 안 되는 환경이면 없이 돌리고, 도식이 칸으로만 옮겨진다고 알린다. PowerPoint 는 읽기 전용, 창 없이, 매크로를 끄고 쓴다. 이미 떠 있던 PowerPoint 는 닫지 않는다.

출력의 `log` 가 비어 있지 않으면 먼저 읽는다. 쪽 그림을 못 뽑았다면 다시 돌린다. 그래도 안 되면 PowerPoint 가 보이지 않는 확인 창에서 멈춰 있을 수 있다. 사용자에게 PowerPoint 창을 봐 달라고 하고, 프로세스를 직접 끄지 않는다. 사용자의 작업일 수 있다. 암호가 걸린 파일은 사용자에게 암호를 풀어 달라고 한다.

```text
출력폴더/
  문서이름.md                 Lectern 슬라이드
  문서이름-그림/              쓰는 그림
  문서이름-변환기록.json      쪽마다 어떻게 옮겼는지. 되돌릴 때 쓴다
  .pptx-work/문서이름/        source.pptx 이때의 원본, deck.json, outline.md, draft.md, ref/001.png 쪽 그림, media/ 원본 그림
```

**사용자가 빨리 달라고 했거나 쪽이 아주 많으면 여기서 끝낸다.** `convert.py` 가 검증까지 돌리니 그 출력만 보고 4단계의 보고를 쓴다. 작성 안내를 읽거나 원본과 손으로 대조하지 않는다. 그러면 1분이면 된다. 초안도 글은 다 있고 칸으로 옮겨져 있다. 다듬을 곳은 보고에 적어 두고 사용자가 부르면 한다.

### 2. 쪽을 다듬는다

초안은 글을 정확히 옮겼지만 배치 판단은 기계적이다. 사람이 고칠 수 있는 글이 많아지고 원본 인상이 살아나는 곳만 손댄다. 모든 쪽을 다시 쓰지 않는다.

`<실행기> <이 스킬>/scripts/sheet.py .pptx-work/문서이름/ref .pptx-work/문서이름/sheets` 로 원본을 몇 장에 모아 훑고, 출력의 `review` 차례로 본다:

1. **표지·장 구분.** 제목이 길어 넘치지 않는지, 배경과 로고가 맞는지 본다.
2. **그림으로 둔 쪽.** `outline.md` 에서 그 쪽의 글과 자리를 본다.
   - 네모 상자가 규칙적인 도식, 카드, 단순한 흐름, 큰 숫자는 칸으로 되살린다. 패턴은 `references/patterns.md` 에 있다. 쪽에 쓰인 글은 노트 '그림 속 글'에서 옮겨 오면 된다.
   - 글과 도식이 함께 있는 쪽은 글만 칸으로 빼고 도식은 `scripts/crop.py` 로 오려 둔다. 효과가 가장 크다.
   - 곡선, 글이 겹침 영역에 있는 원, 사진 위의 글, 지도처럼 자리 자체가 뜻인 도식은 그림으로 둔다.
   - 판단이 서지 않으면 그림으로 둔다.
3. **도형을 뺀 쪽.** 초안은 글 없는 도형과 선을 뺐다. 뜻이 있는 화살표면 `links` 로 되살리고 장식이면 그대로 둔다.

새로 그림이 필요하면 `.pptx-work/문서이름/media/` 에서 `문서이름-그림/` 으로 복사해 쓴다.

문법은 Lectern 의 작성 안내를 따른다. 설치본은 `%LOCALAPPDATA%\Programs\Lectern\_internal\web\help\slides.md`, 저장소에서는 `web/help/slides.md` 다. 칸·격자·`links`·글자 크기를 쓰기 전에 읽는다.

### 3. 검증하고 봉한다

```bash
<실행기> <이 스킬>/scripts/verify.py 문서이름.md .pptx-work/문서이름 --seal
```

`errors` 와 `slides_missing_text` 가 비어야 한다. 빠진 낱말이 있으면 다듬다가 잃은 것이니 되돌린다. `warnings` 의 '넘칠 듯합니다'는 약값이니 그 칸을 살펴 글자 크기를 줄인다. `text_editable_pct` 는 그림 쪽의 글이 빠진 값이다. 다듬기 전보다 올랐는지 본다.

`--seal` 이 쪽마다 지문과 옮긴 방식을 변환기록에 적고 안 쓰게 된 쪽 그림을 지운다. 기록을 손으로 고치지 않는다.

### 4. 보고한다

짧게 알린다.

- 쪽 수, 글 보존율, 고칠 수 있는 글의 비율
- 그림으로 남긴 쪽 번호와 까닭 (한 줄)
- 버린 것 (애니메이션이 있던 쪽 수, 동영상, 검토 메모 수). 답을 나중에 보여 주던 쪽은 답이 처음부터 보인다고 적는다
- 원문에서 본 오타나 앞뒤가 안 맞는 곳이 있으면 고치지 않았다는 말과 함께
- 다음 할 일: Lectern 에서 문서를 열어 상태줄의 **점검**을 보고, 목록을 터미널에 붙여 넣으면 고친다

넘침과 대비는 화면을 그려야 정확히 알 수 있어 Lectern 의 점검이 잡는다. 점검 글마다 고치는 법은 작성 안내 9장에 있다.

## 참고해 만들기

사용자가 pptx(파일이나 화면에 띄운 것)를 참고해서 md 문서를 슬라이드로 만들어 달라고 할 때다. 내용은 md 에서, 모양은 pptx 에서 온다. pptx 의 글은 쓰지 않는다.

### 1. 양식을 읽는다

```bash
<실행기> <이 스킬>/scripts/reference.py 양식.pptx 출력폴더 --name 양식이름
<실행기> <이 스킬>/scripts/reference.py --active 출력폴더 --name 양식이름      # 화면에 띄운 pptx
```

`<양식이름>-양식.md` 에 맨 앞 설정, 칸 색, 표지 만드는 법, 쪽 종류별 칸 자리가 나온다. 쪽 그림을 `sheet.py` 로 모아 보고 양식의 분위기를 잡는다. 맨 앞 설정의 `style` 은 `.pptx-work/<양식이름>-양식/style.txt` 의 전체 글을 쓴다. 쪽마다 있는 로고는 그 안에 있고, 표지에만 있는 로고는 양식 안내의 표지 장식을 보고 넣는다.

로고와 'Co-funded by…' 같은 표시는 그 양식 주인의 말이다. md 의 내용이 아니니 사용자의 회사 양식이 아니면 넣기 전에 보고에 적는다.

### 2. md 를 읽고 슬라이드를 쓴다

Lectern 의 작성 안내를 읽고 md 내용으로 Lectern 슬라이드를 쓴다. 옮기기와 달리 이 일은 내용을 슬라이드로 **다시 짜는 것**이다. 줄이고 쪽을 나눠도 된다. 양식의 쪽 종류를 내용에 맞춰 고르고, 표지는 양식의 표지 지시어를 따른다.

대신 이것은 지킨다.

- 숫자, 고유명사, 결론은 md 그대로 쓴다. 사용자가 보고서로 쓸 자료라서 숫자 하나가 틀리면 문서 전체를 믿을 수 없게 된다.
- md 에 없는 사실을 더하지 않는다.
- 분량을 정하지 않았으면 md 의 큰 장마다 한두 쪽을 쓴다.
- 문서 이름은 사용자가 정하지 않았으면 md 이름에 `-슬라이드` 를 붙인다. md 는 고치지 않는다.
- 쪽 제목은 결론 문장으로 써도 된다. 그때 md 의 장 이름은 `<!-- eyebrow: 장 이름 -->` 로 남긴다. 어느 장의 내용인지 찾을 수 있고 검사도 통과한다.

### 3. 맞춰 본다

```bash
<실행기> <이 스킬>/scripts/from_md.py 원본.md 슬라이드.md
```

`errors` 와 `numbers_added` 는 비어 있어야 한다. `numbers_added` 는 md 에 없는 숫자가 슬라이드에 생겼다는 뜻이다 (쪽 번호나 표의 순위처럼 스스로 붙인 것은 빼도 된다). `numbers_missing` 과 `headings_missing` 은 줄이면서 뺀 것이다. 중요한 것이 빠졌는지 보고, 뺀 것을 보고에 적는다. 그리고 Lectern 의 점검을 부탁한다.

### 4. pptx 로도 내달라고 하면

lectern-to-pptx 스킬로 `--template .pptx-work/<양식이름>-양식/source.pptx` 를 준다. 같은 양식의 pptx 가 나온다.

## pptx 스타일과 템플릿 묶음 만들기

"이 pptx 로 회사 보고 스타일과 템플릿을 만들어 줘", "이 pptx 를 pptx 스타일로 등록해 줘" 라고 하면 이 길이다. 이름을 안 주면 묻는다.

```bash
<실행기> <이 스킬>/scripts/register_style.py 양식.pptx 출력폴더 --name "회사 보고"
<실행기> <이 스킬>/scripts/register_style.py --active 출력폴더 --name "회사 보고"      # 화면에 띄운 pptx
```

Lectern 전체의 보관소에 `회사 보고.pptx` 와 미리보기 그림(표지, 본문)을 둔다. 같은 이름이 있으면 멈춘다. 바꿔도 되는지 물은 뒤 `--force` 를 준다. PowerPoint 가 없으면 미리보기 그림은 없다.

그다음 출력의 `group` 자리에 템플릿 묶음을 쓴다. 이름이 같아서 스타일과 짝이 된다.

1. 출력의 `guide`(양식 안내)와 쪽 그림을 보고 양식에서 자주 쓰는 장의 틀을 고른다. 5~12개면 된다.
2. 작성 안내의 '템플릿' 장대로 쓴다. 장마다 `<!-- template: 이름 -->`, 칸마다 무엇을 쓸 자리인지 안내 글을 넣는다. 양식의 실제 내용을 옮기지 않는다.
3. 어떤 틀을 만들었는지 사용자에게 알린다. 갤러리의 왼쪽 묶음 목록에 바로 나온다.

양식의 장과 그림은 pptx 로 전환한 결과에 들어가지 않는다. 레이아웃에 있는 로고와 꼬리말은 들어간다.
