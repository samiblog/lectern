# 이 프로젝트의 문서 규칙 (Claude Code 용)

이 프로젝트의 문서는 사람이 **Lectern**(Markdown을 중심으로 AI와 함께 작업하는 Windows용 통합 리서치 작업 환경)으로 읽고 그 자리에서 고친다. 문서를 쓰거나 고칠 때 아래를 따른다. 자세한 규칙은 Lectern 의 작성 안내(`web/help/writing.md` — Lectern 설정 창의 'Claude Code 에 Lectern 알려 주기'가 경로를 알려 준다)에 있다.

## 글

- 이 예제에서 리서치 문서와 주간 보고서를 읽는 사람은 구리를 사들이는 회사의 구매 담당자이고, 다음 분기에 언제 얼마나 살지 정하는 데 쓴다 (예제의 가정 — 요청이 다른 독자를 말하면 그 독자를 따른다). 쓰기 전에 그 사람이 무엇을 판단해야 하는지부터 정한다.
- 개조식 나열보다 문단으로, 결론을 앞에. 숫자는 무엇에 비해 얼마인지와 함께 쓰고, 가져온 사실에는 출처(문서 경로·주소)를 단다.
- 다 쓴 뒤에는 읽는 사람이 되어 처음부터 다시 읽고, 나열만 있는 문단과 되풀이되는 어미를 고친다. 아래 형식은 그다음이다.

## 파일

- 문서는 Markdown(`.md`)으로 쓴다. 보고서처럼 모양이 중요하면 HTML 도 되지만 **스크립트는 돌지 않는다** — 차트는 HTML 의 JS 대신 Markdown 의 차트 코드 블록으로 만든다.
- 문서 첫 줄은 `# 제목` 하나. 트리('제목' 버튼)·폴더 개요·창 제목에 이 제목이 쓰인다 (frontmatter 의 `title` 이 있으면 그것).
- 순서가 있는 문서는 `01-`, `02-` 처럼 번호로 시작한다 (`2-` 가 `10-` 보다 앞에 온다).
- 첫 문단은 문서를 한두 문장으로 요약한다 — 폴더 개요의 요약이 된다. 계획·결정 문서는 frontmatter 의 `description` 으로 따로 적어도 된다.
- `.` 으로 시작하는 폴더, `node_modules`·`dist`·`build` 안의 문서는 보이지 않는다. `src/`·`web/` 같은 앱 소스 폴더의 html 은 문서로 보지 않는다.

## 쓰는 법

- 제목 단계(`##` → `###`)를 건너뛰지 않는다. 오른쪽 목차·절 접기·장 하이라이트가 이것으로 나뉜다.
- 표의 칸에는 숫자만, 단위는 머리행에 (`가격 (USD/t)`). 숫자 열은 저절로 오른쪽 정렬된다.
- 강조할 말은 강조글: `> [!NOTE]`·`> [!TIP]`·`> [!IMPORTANT]`·`> [!WARNING]`·`> [!CAUTION]`.
- 본문과 따로 읽을 주제는 박스글: `<!-- box -->` 줄과 `<!-- /box -->` 줄 사이에 쓰고 첫 줄은 `**박스 1. 제목**`. 안에 제목(`#`)은 넣지 않는다.
- 사람이 '대화를 정리해 `@경로 12행` 바로 뒤에 박스글로'라고 하면: 그 줄 바로 뒤에 박스글 하나만 넣는다. 대화를 옮겨 적지 않고 결론·근거·남은 질문만 추리고, 그 밖의 줄은 고치지 않는다.
- 코드 위치는 `src/report.py:14` 처럼 적는다 — 누르면 그 줄로 간다 (코드 블록 안에서는 링크가 되지 않는다).
- 그림·다른 문서는 이 문서 기준 상대경로로 링크한다. 절 링크는 `문서.md#제목-글자`.
- 표 캡션은 표 위에 `표 1. 제목`, 그림 캡션은 그림 아래에 `그림 1. 제목`. 문장에서 가리킬 때는 `[표 1](#표-1)` 처럼 링크로 쓴다 — 사람이 표를 넣거나 옮기면 Lectern 이 번호와 링크를 함께 고친다.
- 다이어그램은 ```` ```mermaid ````, 차트는 ```` ```vega-lite ````·```` ```echarts ````·```` ```plotly ````·```` ```dot ```` 코드 블록.
  - 설정은 JSON 값만 쓴다 — 함수(`formatter: function…`)는 안 된다.
  - 데이터는 문서 안에 적거나, 프로젝트 안의 CSV·JSON 을 문서 기준 상대경로로 가리킨다 (Vega-Lite 의 `data.url`). 인터넷 주소의 데이터·그림은 읽지 않는다.
  - 문서 폭에 맞추려면 Vega-Lite 는 `"width": "container"`, ECharts 는 `"height"` 만, Plotly 는 `layout.height` 만 적는다.
- 발표 자료는 Lectern 슬라이드로 쓴다: 맨 앞 설정에 `marp: true`, 슬라이드는 `---` 로 나눈다. 칸(`::: a card`)과 배치(`<!-- layout: quad -->`)를 쓰고, 넘치면 글은 잘린다 (그림·다이어그램·차트는 줄여 맞춘다). 쓰기 전에 작성 안내 옆의 `web/help/slides.md` 를 읽는다. 발표자 노트는 `<!-- … -->`, 쪽 번호는 `paginate: true`.
- Lectern 슬라이드를 새로 쓸 때는 `slides/README.md` 에서 상황이 맞는 예제를 고르고, `slides/상황별/과정/` 의 과정 문서대로 만든다. 칸이 많은 배치는 `slides/복잡한-배치/` 를 본다.
- 수식은 `$…$`·`$$…$$`. `$105` 같은 달러 금액은 그대로 둔다 (닫는 `$` 앞이 빈칸이면 수식이 아니다).
- 사람이 Lectern 의 '담기'로 넣은 조각 앞의 `<!-- 담은 곳: 경로 a~b행 -->` 주석은 출처 기록이다 — 지우지 않는다.

## 이 프로젝트

- `src/collect.py` 가 `data/월별-가격.csv` 에 월평균 가격을 덧붙이고, `src/report.py` 가 요약 문장을 만든다.
- 리서치 문서는 `research/`, 계획은 `plans/`, 보고서는 `reports/` 에 둔다.
- 숫자를 바꾸면 리서치 문서의 표와 보고서의 숫자를 함께 맞춘다.
- 이 과제의 상태·마감·할 일·일정은 맨 위의 `WORK.md` 에 있다 (업무 카드). 머리 설정 `status`·`priority`·`due` 만, 할 일 `- [ ] 내용 (YYYY-MM-DD)`, 일정 `- YYYY-MM-DD HH:MM 내용` (날짜는 절대값). 일을 마치면 기록 절의 오늘 날짜 아래에 한 줄.
