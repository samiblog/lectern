## 모든 예제의 공통 순서

1. **먼저 정한다.** 듣는 사람과 그들이 결정할 것, 장 수를 정한다.
2. **Claude 에게 요청한다.** 터미널에 요청문을 넣는다. 작성 안내(`web/help/slides.md`)대로 쓰라고 한다.
3. **제목만 먼저 세운다.** 제목만 읽어도 이야기가 이어지게 한다.
4. **칸을 채운다.** 내용 양에 맞는 배치를 고른다.
5. **점검을 고친다.** 상태줄의 **점검** 목록을 터미널에 붙여 넣으면 Claude 가 고친다.
6. **사람이 다듬는다.** F2 로 그 자리에서 고친다.
7. **발표하고 전한다.** Shift+F5 로 발표하고, 우클릭의 **인쇄 / PDF로 저장…** 으로 나눠 준다.

## 좋은 슬라이드의 약속

- 제목은 주제가 아니라 결론을 쓴다.
- 장마다 말할 것 하나. 긴 설명은 발표자 노트에 쓴다.
- 칸으로 쓴다. HTML 장은 사람이 고칠 수 없다.
- 값이 자주 바뀌면 CSV 로 뺀다.
- 숫자는 장을 넘어서도 맞아야 한다. 합계와 비율을 계산해 본다.
- 점검이 0건이어도 눈으로 본다. 사진 위의 글과 빈 곳은 점검이 모른다.

칸과 배치의 기본은 [슬라이드 칸](../guide/10-슬라이드-칸.md), 발표는 [발표](../guide/08-발표.md) 에 있습니다.

## 더 복잡한 배치

대시보드, 잡지 지면, 프로세스 지도, 간트 차트, 분석 틀처럼 칸이 많은 예제 20가지는 [복잡한 배치](복잡한-배치/README.md) 에 있습니다.
