## 읽기 함수에 다섯 줄을 더했다

::: a center
```python
def get_book(book_id):
    key = f"book:{book_id}"
    book = cache.get(key)
    if book is not None:
        return book
    book = db.find_book(book_id)
    cache.set(key, book, ttl=300)
    return book
```
:::

::: b center 20
### 더한 것

- 책 번호로 키를 만든다
- 캐시를 먼저 본다
- 읽은 값을 300초 둔다

### 그대로인 것

- DB 조회 함수
- 쓰기 경로

## 적중률 90%면 평균 응답은 14ms다

::: a card center text-center 56
$$T = T_c + (1 - h)\,T_d$$
:::

::: b kpi
**2 ms**
$T_c$ 캐시 응답
:::

::: c kpi
**120 ms**
$T_d$ DB 응답
:::

::: d kpi
**0.9**
$h$ 적중률
:::

::: e kpi accent
**14 ms**
2 + 0.1 × 120
:::

<!-- 캐시는 늘 한 번 보고, 미스일 때만 DB 값을 더 낸다. 적중률이 1%p 떨어지면 평균이 1.2ms 늘어난다. -->

## 캐시는 새로운 실패 두 가지를 들여왔다

::: a center 24
### 부하

> [!WARNING]
> 캐시가 통째로 비면 **2,000회/초**가 한꺼번에 DB로 간다.

- 수명을 ±10% 흩뜨린다
- 같은 키 조회를 하나로 묶는다
:::

::: b center 24
### 정확성

> [!NOTE]
> 고친 책이 **최대 300초** 옛 값으로 보인다.

- 가격·재고는 캐시에서 뺐다
- 책을 고칠 때 키를 지운다
:::

<!-- 왼쪽은 부하의 위험이고 오른쪽은 정확성의 위험이다. 둘 다 아직 막지 못한 부분이 있다. -->
