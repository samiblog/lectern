# 06 월간 보고 — 처음부터 만들기

> 완성본: [월간 보고](../06-월간-보고.md)

**언제 쓰나** 회의에 띄우지 않고 책상에서 PDF 로 읽는 자료에 쓴다.

**이 예제에서 배우는 것**
- `reading: true` 를 언제 쓰는지 안다.
- 4:3 의 폭 848 에 맞게 배치를 고른다.
- 장마다 같은 자리에 출처 줄을 둔다.

## 1. 먼저 정한다

읽는 사람은 물류 회사의 전략·영업 담당자다. 회의가 아니라 자기 자리에서 혼자 읽는다. 발표자가 말로 채워 주지 않으니 글이 장 안에 다 있어야 한다.

그들이 정할 것은 둘이다. 이달 시장을 어떻게 볼지, 다음 달에 무엇을 지켜볼지다.

장 수는 보고의 틀로 정한다. 매달 같은 틀이어야 읽는 사람이 찾기 쉽다.

| 내용 | 장 |
|---|---:|
| 표지 | 1 |
| 이달의 요약 | 1 |
| 부문별 매출 | 1 |
| 택배, 육상 화물, 포워딩, 창고 | 4 |
| 다음 달 전망 | 1 |

모두 8장이다.

크기와 글자는 이렇게 정했다.

- `size: 4:3` 을 쓴다. 인쇄한 쪽에 가까운 모양이다.
- `reading: true` 를 쓴다. 출처 줄을 12pt 로 쓰기 위해서다.
- 본문 14pt, 표 12pt 로 내린다. 화면에 띄우는 문서라면 하지 않을 일이다.

## 2. Claude 에게 요청한다

터미널에 그대로 붙여 넣는다.

```text
web/help/slides.md 작성 안내대로 읽는 자료를 써 줘. 발표용이 아니라 PDF 로 읽는 문서다.

- 파일: slides/06-월간-보고.md, 자료는 slides/data/06-*.csv
- 주제: 국내 물류 시장 월간 보고 2026년 10월호. 숫자는 만든 값이다
- 맨 앞 설정: size: 4:3, reading: true, text: 제목 24, 소제목 16, 본문 14, 표 12, 박스글 13
- 8장: 표지, 요약, 부문별 매출, 택배, 육상 화물, 포워딩, 창고, 11월 전망
- 시장 매출은 네 부문의 합이고 장마다 맞아야 한다. 계산해서 확인해
- 표지 뒤의 모든 장은 격자로 쓰고 맨 아래 줄을 출처 칸 s 로 둔다. 칸 크기는 12
- 4:3 의 쓸 수 있는 폭은 848 이다. 열이 많은 표는 폭 전체를 쓴다
- 제목은 결론으로 쓴다. HTML 장은 쓰지 마
- 꼬리말: 예제 — 숫자는 만든 값입니다
```

## 3. 제목만 먼저 세운다

| 장 | 결론 제목 | 격자 |
|---:|---|---|
| 1 | 10월 물류 시장은 택배가 떠받쳤다 | `lead` |
| 2 | 10월 시장은 4조 2,000억 원, 전년보다 3.2% 늘었다 | `t t t / a b c / d d d / e e e / s s s` |
| 3 | 네 부문 중 육상 화물만 줄었다 | `t / a / b / s` |
| 4 | 택배는 물량이 9.1% 늘고 단가는 1.3% 내렸다 | `t t / a a / b c / s s` |
| 5 | 육상 화물은 운임이 2.3% 내려 매출이 줄었다 | `t t / a a / b c / s s` |
| 6 | 포워딩 증가분의 70%는 항공이 만들었다 | `t t / a b / c b / s s` |
| 7 | 창고는 늘었지만 지방 공실률은 12% 이상이다 | `t t / a a / b c / s s` |
| 8 | 11월 시장은 4조 3,000억 원으로 본다 | `t t / a a / b c / s s` |

제목 글자를 24pt 로 내렸다. 그래도 폭이 848 이라 제목은 한 줄에 스물몇 자까지다. 2장의 제목이 가장 길고 한 줄에 들어갔다.

## 4. 칸을 채운다

### 맨 앞 설정

```markdown
---
marp: true
title: 국내 물류 시장 월간 보고 2026년 10월호
paginate: true
size: 4:3
reading: true
text: 제목 24, 소제목 16, 본문 14, 표 12, 박스글 13
footer: 예제 — 숫자는 만든 값입니다
---
```

글자 크기를 문서 전체에 한 번만 쓴다. 장마다 쓰면 장이 달라 보인다.

### 3장: 폭이 좁으면 위아래로

```markdown
<!-- grid: t / a / b / s -->
<!-- rows: auto auto 1fr auto -->
<!-- eyebrow: 부문별 매출 -->

## 네 부문 중 육상 화물만 줄었다

::: a
| 부문 | 10월(억 원) | 전년 동월(억 원) | 증감(억 원) | 증감(%) | 비중(%) |
|---|---:|---:|---:|---:|---:|
| 택배 | 12,600 | 11,700 | +900 | +7.7 | 30.0 |
| 육상 화물 | 14,700 | 15,000 | -300 | -2.0 | 35.0 |
| 포워딩 | 8,400 | 8,000 | +400 | +5.0 | 20.0 |
| 창고 | 6,300 | 6,000 | +300 | +5.0 | 15.0 |
| **합계** | **42,000** | **40,700** | **+1,300** | **+3.2** | **100.0** |
:::
```

- 16:9 라면 표와 차트를 좌우로 놓았을 것이다. 4:3 의 폭 848 을 둘로 나누면 칸은 415 다. 6열 표에는 좁다.
- 그래서 표는 폭 전체를 쓰고 차트를 아래에 둔다. 4:3 은 세로가 넉넉하다.
- `rows` 는 제목 줄까지 넷을 적는다. `1fr` 인 줄이 남는 높이를 갖는다. 차트가 든 b 줄이다.

### 출처 줄

```markdown
::: s 12
출처: 가상 물류통계원 「부문별 매출」 2026-10. 비중은 10월 매출 기준이다.
:::
```

- 격자의 맨 아래 줄을 `s` 로 두고 `rows` 의 끝을 `auto` 로 쓴다. 글 높이만큼만 차지하고 늘 쪽 맨 아래에 온다.
- 표지 뒤의 일곱 장이 모두 같다. 읽는 사람의 눈이 출처를 같은 자리에서 찾는다.
- 끝의 `12` 는 칸 크기다. 이 12pt 때문에 `reading: true` 가 필요하다.

### 6장: 왼쪽 둘, 오른쪽 하나

```markdown
<!-- grid: t t / a b / c b / s s -->
<!-- rows: auto auto 1fr auto -->
<!-- eyebrow: 포워딩 -->

## 포워딩 증가분의 70%는 항공이 만들었다

::: a
| 구분 | 2025-10 | 2026-10 | 증감(%) |
|---|---:|---:|---:|
| 해상 | 6,000 | 6,120 | +2.0 |
| 항공 | 2,000 | 2,280 | +14.0 |
| **합계** | **8,000** | **8,400** | **+5.0** |
:::
```

- 표가 4열로 작으니 415 칸에 들어간다.
- 격자에 `b` 를 두 번 적으면 차트가 두 줄을 차지한다. 왼쪽은 표와 글, 오른쪽은 긴 차트다.

## 5. 점검을 고친다

처음 쓴 문서의 점검 결과는 이렇다.

```text
8장, 점검 0건, 한 줄 편집 78/78, 차트·그림 오류 0건
```

점검은 0건이었다. 눈으로 보고 고친 것은 이렇다.

| 장 | 본 것 | 고친 것 |
|---:|---|---|
| 2 | 낮은 차트에 축 제목 `시장 매출 (억 원)` 이 빠듯했다 | `매출 (억 원)` 으로 줄였다 |
| 3 | 막대가 육상 화물, 창고, 택배, 포워딩 차례로 나왔다 | `sort` 를 표와 같은 차례의 배열로 바꿨다 |
| 6 | 처음엔 `t t / a b / c c / s s` 였다. 표가 칸 가운데 떠서 위아래가 비었다 | `t t / a b / c b / s s` 로 바꿔 글을 표 아래로 옮겼다 |
| 6 | 글 칸이 커지며 비어 보였다 | 소제목과 두 줄을 더했다 |
| 8 | 볼 지표와 위험 칸이 절반쯤 비었다 | 항목을 늘리고 `center` 를 썼다 |

`reading: true` 가 하는 일을 보려고 이 줄을 뺀 사본으로 돌려 봤다. 점검이 7건 나왔다.

```text
2장 본문이 12pt 로 작습니다 (기준 14pt)
3장 본문이 12pt 로 작습니다 (기준 14pt)
…
8장 본문이 12pt 로 작습니다 (기준 14pt)
```

출처 칸이 든 일곱 장이 모두 걸린다. 화면에 띄울 문서라면 맞는 경고다. 읽는 자료에서만 이 한 줄로 기준을 내린다.

같은 사본에서 `**8.0%**로` 도 시험했다. 별표가 글자로 그대로 나왔고 점검에는 나오지 않았다. `%` 뒤의 닫는 `**` 에 글자를 바로 붙이지 않는다.

마지막 결과는 8장, 점검 0건, 한 줄 편집 84/84 이다.

숫자가 맞는지는 점검이 보지 않는다. 그래서 따로 계산했다. 틀린 값은 없었다.

| 어디 | 계산 | 결과 |
|---|---|---|
| 3장 | 12,600 + 14,700 + 8,400 + 6,300 | 42,000 |
| 3장 | 900 - 300 + 400 + 300 | +1,300 |
| 3장 | 42,000 ÷ 40,700 | +3.2% |
| 4장 | 12,600억 원 ÷ 480백만 상자 | 2,625원 |
| 4장 | 물량 +9.1%, 단가 -1.3% | 매출 +7.7% |
| 5장 | 물량 +0.3%, 운임 -2.3% | 매출 -2.0% |
| 6장 | 280 ÷ 400 | 70% |
| 7장 | 200 ÷ 2,000 | 공실률 10.0% |
| 8장 | 600 + 100 + 300 + 0 | +1,000, 합 43,000 |

## 6. 사람이 다듬는다

다음 달 판을 만든다고 생각하고 해 본다.

1. **출처를 고친다.** 3장의 출처 줄에서 F2 를 누른다. `2026-10` 을 `2026-11` 로 고치고 Enter 를 누른다.
2. **표의 값을 고친다.** 3장 표의 택배 행에서 F2 를 누르고 값을 고친 뒤 Enter 를 누른다. 합계 행도 같이 고친다. 2장의 요약과 8장의 표도 같은 숫자를 쓴다.
3. **글자 기준을 본다.** 출처 줄에서 Ctrl+Shift+< 를 눌러 글자를 내린다. 12pt 아래로 내려가면 상태줄의 '점검'에 나온다. Ctrl+Z 로 되돌린다.
4. **부문을 한 장 더한다.** 5장에서 Ctrl+D 로 장을 복제한다. Ctrl+Shift+PageDown 으로 자리를 옮기고 글을 F2 로 고친다. 복제하면 격자와 출처 칸이 그대로 따라온다.
5. **격자를 바꾼다.** Ctrl+M 으로 빈 장을 더하고 우클릭의 '배치 넣기…'로 배치를 고른다. 출처 줄이 필요하면 Ctrl+E 로 `grid` 줄에 `s s` 를 더한다. 상태줄의 '구조 보기'를 켜면 숨은 줄이 보인다.

## 7. 발표하고 전한다

이 문서는 PDF 로 전한다. 문서의 우클릭 메뉴에서 '인쇄 / PDF로 저장…'을 고른다. 이 예제에서 볼 점은 셋이다.

- 모든 쪽의 아래쪽 같은 자리에 출처가 있는지 본다.
- 노트는 PDF 에 들어가지 않는다. 읽는 사람이 꼭 알아야 할 말은 칸에 쓴다. 단가 계산법을 출처 칸에 쓴 까닭이다.
- 작은 표의 글자가 읽히는지 PDF 를 열어 100% 로 본다.

Shift+F5 로 발표할 수는 있다. 하지만 출처 줄 12pt 는 회의실 화면에서 작다. 띄워야 한다면 `reading: true` 를 빼고 장을 나눈다.

## 되새길 것

- 띄우면 발표 문서, 돌려 읽으면 읽는 자료다. `reading: true` 는 뒤의 경우에만 쓴다.
- 4:3 은 좌우보다 위아래로 쌓는다.
- 출처는 칸마다 쓰지 않고 맨 아래 한 줄에 둔다.
