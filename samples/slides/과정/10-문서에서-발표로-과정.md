# 10 문서에서 발표로 — 처음부터 만들기

> 완성본: [문서에서 발표로](../10-문서에서-발표로.md)

**언제 쓰나** 이미 쓴 리서치 문서를 회의에서 말해야 할 때 쓴다.

**이 예제에서 배우는 것**

- 문단을 옮기지 않고 전할 말을 고른다
- 경로를 새 파일 기준으로 다시 쓴다
- 사이드바 우클릭의 'Lectern 슬라이드로 바꾸기 요청'을 쓴다

## 1. 먼저 정한다

원문은 [구리 시장 동향](../../research/구리-시장-동향.md)이다. 원문은 고치지 않는다.

**듣는 사람** 원문을 읽지 않은 동료들.

**그들이 결정할 것** 3분기 가격을 원문의 범위로 보고 일할지, 어떤 신호가 나오면 다시 볼지.

**장 수** 문서의 절 수로 세지 않는다. 전할 말의 수로 센다. 원문의 첫 문단에 벌써 세 가지가 있다. 올랐다, 왜 올랐다, 앞으로 어떻다. 여기에 범위를 움직일 신호와 다음 할 일을 더하면 다섯이다. 표지까지 6장이다.

원문의 각 부분을 어디에 쓸지 먼저 가른다.

| 원문 | 발표에서 |
|---|---|
| 첫 문단 | 표지의 부제, 2·3·4장의 제목 |
| 요약 표의 네 지표 | 표로 옮기지 않았다. 가격은 2장, 재고·수입은 3장, 가동률은 4장으로 나눴다 |
| 월별 차트 | 2장. 같은 CSV 를 읽는다 |
| 가격 범위 그림 | 뺐다. 숫자가 없는 예시 그림이다. 범위는 4장 차트의 띠로 그렸다 |
| 전망 세 줄 | 범위는 4장, 두 신호는 5장 |
| IMPORTANT 박스글 | 6장의 제목 |
| 출처와 각주 | 6장의 링크 하나로 줄였다 |

## 2. Claude 에게 요청한다

터미널을 열어 둔다. 사이드바에서 `research/구리-시장-동향.md` 를 우클릭해 **'Lectern 슬라이드로 바꾸기 요청'**을 고른다. 요청 글이 터미널에 들어온다. Enter 는 눌리지 않는다. 그대로 보내지 말고 아래처럼 파일과 장 수, 고를 말을 덧붙인 뒤 Enter 를 누른다.

메뉴를 쓰지 않으려면 이 글 전체를 터미널에 붙여 넣는다.

```text
작성 안내 web/help/slides.md 대로 research/구리-시장-동향.md 를 Lectern 슬라이드로 바꿔 줘.
새 파일은 slides/10-문서에서-발표로.md, 6장이다. 원문은 고치지 않는다.
듣는 사람은 원문을 읽지 않은 동료들이다. 3분기 범위와 볼 신호를 정한다.
순서는 표지, 2분기 가격, 오른 이유, 3분기 범위, 두 신호, 다음 할 일과 근거 문서다.
- 문단을 옮기지 말고 장마다 말할 것 하나만 고른다.
- 숫자는 원문의 것만 쓴다. 새로 계산한 숫자는 넣지 않는다.
- 원문이 '본다'고 쓴 것은 단정하지 않는다.
- 차트는 ../data/월별-가격.csv 를 읽는다. 경로는 새 파일 기준으로 쓴다.
- 마지막 장에 원문을 ../research/구리-시장-동향.md 로 링크한다.
- 제목은 결론으로 쓰고, 내용 장마다 발표자 노트를 한두 문장 쓴다.
- 숫자는 만든 값이라고 꼬리말에 적는다.
```

`단정하지 않는다` 줄은 5장에서 겪은 일을 보고 더한 줄이다.

## 3. 제목만 먼저 세운다

제목 여섯을 이어 읽으면 원문의 첫 문단과 전망이 된다. 그렇지 않으면 말을 잘못 고른 것이다.

| 장 | 결론 제목 | 배치 |
|---:|---|---|
| 1 | 2분기 구리 시장 동향 | `lead` |
| 2 | 2분기 평균 가격은 3.9% 올랐다 | `left-stack` |
| 3 | 재고가 줄고 중국 수입이 늘어 가격이 올랐다 | 격자 `t t / a b / c d` |
| 4 | 공급 차질이 풀려 오름폭은 줄어들 것으로 본다 | `right-stack` |
| 5 | 두 신호가 범위를 움직인다 | `quad` |
| 6 | 다음 보고서부터 재고를 주 단위로 모은다 | `stack` |

## 4. 칸을 채운다

### 2장: 원문의 차트를 새 파일에서 읽는다

````markdown
::: a
```vega-lite
{
  "title": "월평균 가격 (USD/t)",
  "width": "container",
  "config": {"view": {"stroke": null}},
  "data": {"url": "../data/월별-가격.csv"},
  "mark": {"type": "line", "point": true},
  "encoding": {
    "x": {"field": "월", "type": "temporal", "title": null, "axis": {"format": "%y.%m"}},
    "y": {"field": "가격", "type": "quantitative", "title": null, "scale": {"zero": false}, "axis": {"format": ",d"}}
  }
}
```
:::
````

원문의 차트를 옮기면서 `height` 를 뺐다. 칸 안의 차트는 칸의 높이에 맞춰 그려진다.

경로는 이 md 파일이 있는 폴더가 기준이다. 옮길 때마다 하나씩 본다.

| 무엇 | 원문(`research/`)에서 | 새 파일(`slides/`)에서 |
|---|---|---|
| 가격 자료 | `../data/월별-가격.csv` | `../data/월별-가격.csv` |
| 후속 과제 | `../plans/10-후속-과제.md` | `../plans/10-후속-과제.md` |
| 원문 자신 | 없음 | `../research/구리-시장-동향.md` |
| 가격 범위 그림 | `images/price-band.svg` | 쓴다면 `../research/images/price-band.svg` |

`research/` 와 `slides/` 는 같은 높이라 앞의 둘은 그대로다. 문서 옆의 파일을 가리키던 그림만 달라진다.

### 5장: 문장을 옮기지 않고 나눈다

원문의 한 줄은 이렇다. '재고가 230천 t 아래로 내려가면 상단을 다시 본다.' 이것을 신호와 움직임으로 나눠 두 칸에 썼다.

```markdown
::: a kpi center
**230천 t**
거래소 재고의 기준
:::

::: b card center 20
### 상단을 다시 본다

재고가 이 아래로 내려갈 때다.
2분기 재고는 241천 t 이다.
:::
```

왼쪽이 신호, 오른쪽이 움직임이다. 아래 줄도 같은 차례로 썼다. `quad` 를 고른 까닭이다. `241천 t` 은 원문 요약 표의 값이다. 기준과의 차이는 원문에 없어서 계산해 넣지 않았다.

### 6장: 원문으로 돌아갈 길을 남긴다

```markdown
::: b card center text-center 22
### 근거 문서

[구리 시장 동향](../research/구리-시장-동향.md) · 2026-07-03 · 상태는 검토 중이다.
숫자는 Lectern 예제용으로 만든 값이다.
:::
```

원문의 머리에 '상태: 검토 중'이 있다. 발표로 바꾸면 이런 말이 사라지기 쉽다. 그래서 칸에 그대로 남겼다. 노트가 아니라 칸에 쓴 것은 PDF 에도 남기기 위해서다.

## 5. 점검을 고친다

처음 쓴 문서의 점검은 **0건**이었다. 6장, 한 줄 편집은 34줄 중 34줄이었다. 차트 문제도 없다고 나왔다.

그런데 눈으로 보니 고칠 곳이 있었다. 제일 큰 것은 4장이다. 점검은 차트의 눈금까지 보지 않는다.

| 장 | 눈에 띈 것 | 고친 것 |
|---:|---|---|
| 3 | 막대 위 숫자가 차트 제목과 틀 선에 닿았다 | 차트 제목을 빼고 단위를 KPI 설명으로 옮겼다. `scale.domain` 을 300 과 170 까지 잡았다 |
| 4 | 세로축이 0 부터 시작해 선이 납작했다. 범위 띠가 위쪽의 얇은 줄이 됐다 | 띠와 선은 세로축을 함께 쓴다. `domain` 을 선 층에만 적어서 듣지 않았다. 축을 층 밖 `encoding` 으로 올렸다 |
| 4 | 띠가 무엇인지 차트만 봐서는 몰랐다 | 띠 안에 `3분기 전망 범위` 글을 넣었다. 눈금은 `10,600`·`11,400` 둘만 남겼다 |
| 5 | 아래 오른쪽 칸의 글이 한 줄이라 비어 보였다 | 원문대로 `중국의 전력망 투자 일정이` 를 살리고 글자를 20 으로 키웠다 |
| 6 | 글이 왼쪽에만 있어 오른쪽 절반이 비었다 | `text-center` 와 크기 22 를 썼다 |

원문과 어긋난 말도 찾았다.

- 처음 제목은 `오름폭은 줄어든다` 였다. 원문은 '줄어들 것으로 본다'다. 예상을 단정으로 바꾸면 안 된다. 표지와 4장을 원문대로 고쳤다.
- 5장의 `하단 쪽으로 움직인다` 도 원문대로 `움직일 수 있다` 로 고쳤다.
- 6장의 처음 제목은 `재고를 주 단위로 모아 신호를 일찍 본다` 였다. '일찍 본다'는 원문에 없다. 원문의 말로 바꿨다.

마지막으로 칸의 숫자를 모두 뽑아 원문과 맞췄다. 원문에 없는 숫자는 0개였다.

마지막 결과는 점검 0건, 한 줄 편집 35줄 중 35줄이다.

## 6. 사람이 다듬는다

1. **숫자를 고친다.** 재고가 새로 나왔다고 해 본다. 5장의 `2분기 재고는 241천 t 이다.` 줄에서 F2 를 누르고, 값을 고친 뒤 Enter 를 누른다. 다 봤으면 Ctrl+Z 로 되돌린다.
2. **차트의 값을 고친다.** 3장의 막대는 값이 문서 안에 있어 한 줄 편집으로 고치지 못한다. Ctrl+E 로 편집 모드를 열어 `data.values` 를 고친다. 2장·4장의 차트는 CSV 를 읽으니 CSV 가 바뀌면 저절로 바뀐다.
3. **강조한다.** 4장의 `$10,600~$11,400/t` 줄에서 Ctrl+Shift+> 를 눌러 글자를 키운다. 지나치면 Ctrl+Shift+< 를 누른다.
4. **요약 장을 더한다.** 듣는 사람이 바쁘면 표지에서 Ctrl+M 으로 장을 더한다. 우클릭의 '배치 넣기…'로 `three` 를 고르고 세 칸에 올랐다, 왜, 3분기를 한 줄씩 쓴다. 숫자는 원문의 것만 쓴다.

고친 뒤에는 상태줄의 '점검'이 0건인지 본다.

## 7. 발표하고 전한다

Shift+F5 로 발표한다. 문서를 우클릭해 '인쇄 / PDF로 저장…'을 고르면 PDF 가 된다.

- 4장은 6월 값이 띠의 위쪽에 있는 것을 짚는다. 오름폭이 줄어든다는 말이 여기서 보인다.
- 노트는 PDF 에 들어가지 않는다. 그래서 근거 문서는 6장의 칸에 썼다.
- PDF 를 받는 사람에게는 원문 파일이 없을 수 있다. 문서 이름과 날짜, 상태를 글자로 남긴 까닭이다.

## 되새길 것

- 장 수는 문서의 절이 아니라 전할 말의 수로 센다.
- 숫자는 원문에서만 가져오고, 말의 세기도 원문을 넘지 않는다.
- 경로는 새 파일이 있는 폴더 기준으로 다시 쓴다.
